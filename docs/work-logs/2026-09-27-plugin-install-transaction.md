# 2026-09-27 插件安装与更新事务修复

## 结果

- 外部插件安装、更新和内置插件自动刷新共用 `install_transaction.rs` 的同卷暂存与目录切换流程。来源复制后核对目录清单、文件内容和 manifest；切换旧目录前先写入操作记录。
- 操作记录保存旧 registry/settings 字节和精确配置路径，记录各提交阶段。失败时用保留的旧版备份恢复目录和元数据；重复恢复仍保留备份，直到操作记录清除。恢复失败返回 `RecoveryPending`，发现和后续变更停止。跨文件提交不承诺原子性。
- 插件管理根使用文件锁串行化不同进程的操作及恢复；锁不可用返回 `Busy`。所有目录删除/移动、操作记录路径和元数据路径先检查绝对位置、直属安装目标、插件身份及重解析点；`.ops` 不参与插件发现。
- 外部安装默认禁用，更新保持原启用状态；CLI 原有独立 `/plugins enable` 命令继续用于显式启用。内置插件自动刷新不写入新启用设置，保留用户显式状态和 manifest 默认状态。
- 卸载及已移除内置插件的清理仍是删除操作，已增加安装目录与插件 ID 一致的检查；未把 Web 端尚未接通的安装接口（501）描述为可用。

## 验证

- `cargo test -p coolzhu-plugin-system --offline`：37 项通过。覆盖暂存/registry/settings 失败、旧版保留、更新启用态、崩溃后及重复回滚、备份缺失时停止发现、竞争锁、伪造操作路径和内置插件刷新失败。
- `cargo test -p coolzhu-command-router --offline`：20 项通过。
- `cargo build -p coolzhu-plugin-system --offline` 与 `cargo build -p coolzhu-command-line --offline`：通过。
- 相关 Rust 文件已格式化，相关跟踪文件 `git diff --check` 通过。

## 范围与限制

事务保证在进程中断或普通 I/O 错误后可按操作记录回滚，未提供断电时跨目录和两个 JSON 文件的全局原子性。用户主动卸载和内置插件来源移除后的清理是另外的删除语义，不在安装/更新替换事务中；目录删除已受路径校验保护。
