# 执行树真实用量汇总

对应 WBS 2.2、2.5、4.2、4.5 的执行可追溯性增量。

执行详情沿同工作区、同房间的 `parent_execution_id` 收集本执行和后代。递归 SQL 使用 UNION 去重，即使父链存在循环也不会无限展开。不同工作区、不同房间及未接到本树的孤立记录不参与汇总，不按名称或时间猜配父执行。

使用既有真实 run 和 request_usage 事实，按真实 attempt_id 去重。同一 run 同时被父执行和会话工具子执行引用时，不重复计算网络请求。同一 attempt 的事实冲突时拒绝汇总；索引与用量查询使用同一 SQLite 读取事务快照。任一已记录请求缺少输入或输出用量，对应汇总保留 null；无请求也保留未知，禁止估算成零。

执行详情展示后代数、去重请求数、输入/输出用量及执行 ID；列表不逐行扫描全树。原运行轨迹、停止能力和模型执行入口不改变。

验证日志位于 tmp/analysis-execution-subtree-*。首次新增测试因只初始化会话 schema、未初始化独立用量表失败，已补实际 chat_insights 初始化并重跑，专项 1 通过、0 失败（0.04 秒）。前端语法与工程切换/迟到响应回归通过，增加了后代汇总及未知文案断言。最终 `cargo build -p coolzhu-web-console --offline -j1` 实际 exit 0（1 分 43 秒，包含等待锁）；全量 `cargo test -p coolzhu-web-console --offline -j1` 实际 exit 0，1457 通过、0 失败、6 忽略（38.04 秒）。既有 151 项构建警告仍保留，不声称消除。

尚未闭环：正式安装界面中的多层真实子 Agent、跨执行来源链及真实模型用量验收。循环父链这里只证明遍历安全，不代表循环关系有效；缺失父索引不猜测修复。整个 32WBS 仍未完成正式验收与交付。
