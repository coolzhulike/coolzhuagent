# Harness 对齐 v2 方案与接替机制

按用户要求，将 GPT-6 Pro 已完成的网页审核落实为 [实施方案书](../plans/harness-alignment/PLAN.md)，首轮采用轻量提示词组装、任务连续性、工具暴露、实际请求绑定、分类恢复、有限审批复用/Web 并发、明确验证状态与任务内证据复用。T08 拆为两个延期候选，未启动业务改造。

交付 13 个必做工作包、60 条 [验收合同](../plans/harness-alignment/ACCEPTANCE.md)，每项明确入口、依赖、执行步骤、通过/失败条件、证据与回退。将“未执行、无法执行、空失败列表、0 项测试不等于通过”落实到状态规范；保留宿主权限撤销、调用身份、根预算与取消。

[接替入口](../plans/harness-alignment/START_HERE.md) 提供最小阅读集、检查点、突然中断恢复及可复制给新会话的指令。[状态台账](../plans/harness-alignment/state.json) 初始为 13 项待执行、60 条待验收、2 项延期，没有虚报功能通过。检查工具只检查项目台账与证据，不进入产品推理路径，不自动启动新模型。

固定了 27 个相关源码/配置文件哈希及审核材料哈希。与 Pro 引用清单中可比文件相比，当前 `main.rs` 已变化；现有权限/审批改动需在 HA-00 回查后决定复用或补测。原始三方报告、Pro 原文、决策表和会话凭据保留不变，v2 的实施范围以新方案为准。

本轮验证范围是方案结构、60 条映射、依赖、链接、检查器拒绝错误关闭的能力及历史材料未变。业务源码未修改，未运行 Rust 构建、功能验收或真实模型性能对照。实际规划检查结果保存在 [规划验证记录](../plans/harness-alignment/evidence/planning-validation.json)；这些检查不关闭业务验收条目。
