# 共享 CLI 停止响应统一身份校验

实际审查发现：断流分支已经会按已知原轮次请求停止，再查询终态，并非漏发 Ctrl+C 停止；但停止响应 turn_id 校验只在正常 SSE 取消分支进行，断流分支未校验。现将原 turn_id 校验收敛进 interrupt 共用函数，错误或缺失身份返回“停止结果待确认”，不推断已成功停止。

正常流仍显示停止请求事件；断流分支通过共用函数取得相同检查。协议/输出异常分支的停止属于尽力动作，保持原错误归因，不将停止失败覆盖原异常。本修改不新增重复业务提交或自动重试，也不把响应正确身份等同真实进程回收。

真实本机 HTTP 回归分别返回原 turn、外来 turn、缺失 turn；验证请求仍仅包含原 session/room/turn，后两者被拒。既有 SSE 接纳和取消回归同时通过。离线 CLI 构建实际退出 0；完整 crate 测试实际退出 0，85 通过、0 失败、0 忽略。日志 tmp/analysis-cli-interrupt-identity-build.txt、tmp/analysis-cli-interrupt-identity-tests.txt。

这些是本地客户端协议验证，不是产品后台/真实模型正式验收；已安装 0.2.128 不含本候选。停止响应多字段契约、实际终态及全部入口取消矩阵仍需按服务接口继续审查。
