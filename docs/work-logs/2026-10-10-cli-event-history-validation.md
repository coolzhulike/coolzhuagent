# CLI 恢复时验证持久事件

此前会话恢复仅读取消息，新落盘的成功/失败轨迹没有恢复读取路径。本次在独立 resume-session、交互 /resume 及 /session switch 中读取并验证对应事件历史。旧会话无目录时兼容空历史；已有目录的读取错误或损坏轨迹不忽略，也不冒称成功恢复。

读取上限为单轨迹 8 MiB、历史原始 JSON 总量 64 MiB、10000 文件。只接纳普通文件，核对首事件 TurnStarted、连续序号、轨迹内 thread/turn 一致、仅末事件为 completed/failed/interrupted，以及不同历史记录的 thread/turn 不重复。JSON 半份、缺终态、重复起点或身份均返回错误。总量是输入 JSON 上限，不宣称反序列化后内存等于原始字节。

测试实际回读已完成轨迹及模型失败轨迹，逐事件与原值比较；删除终态及损坏 JSON 均被拒绝；旧会话无历史目录仍通过。补齐 switch 入口后再离线编译及完整 CLI 回归，均退出 0，90 通过、0 失败、0 忽略。最终工具会话 99075 退出 0；日志 tmp/analysis-cli-history-restore-build-2.txt、tmp/analysis-cli-history-restore-tests-2.txt。首轮日志保留。

此路径用于验证恢复历史，不自动重放模型或工具，不重试未知执行。尚未提供损坏记录修复、历史分页展示、原子会话/事件提交或崩溃后的未知状态处置。正式运行恢复矩阵、外部模型及全部入口仍需验收，当前安装版 0.2.130 不含本改动，32WBS 未完成。
