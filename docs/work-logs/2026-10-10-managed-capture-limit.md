# 同步结果管道的超限失败保护

在启动后错误分类及全部线程回收基础上，managed_process 的每根结果管道改为分块读取，最多保留 8 MiB 原始字节，另有固定 8 KiB 读取缓冲。恰好达到上限仍可正常完成，继续读到任何额外字节即返回 InvalidData，标记采集失败；执行器轮询到该信号后关闭受管子树并收齐线程。读取 I/O 错误也通知同一停止路径。两个管道分别受限，不将部分字节作为 ManagedOutput 成功返回。

错误保留已启动分类，因此 Hook 不会沿启动失败警告路径放行。bash、注册工具、Goal 命令及 Web 插件原调用者传播 io::Error；此次未把超限映射为正常成功、退出码零或可解析的截断协议。该保护改变超过上限命令的行为：命令失败并被停止，而不是无限增长内存。

测试覆盖恰好上限的完整字节保持、超过一字节的显式错误，以及真实 PowerShell stdout/stderr 分别超限后及时停止且不执行四秒后的写入。构建日志 tmp/analysis-managed-capture-limit-build.txt 实际 exit 0；完整运行时串行回归日志 tmp/analysis-managed-capture-limit-tests.txt，终态需核对。

完整运行时串行回归已核对实际 exit 0：369 通过、0 失败；库 MCP 与两项 DSH 集成测试共 3 项忽略，不计通过。主控制台生产构建另外执行，以核对下游注册工具和 Web 调用者的编译接线。

这只是超限失败保护，不等于完整输出存储/引用、spill/GC 或全局配额完成。超限之前的输出没有作为完整内容交付或另存，不得宣称完整留存。stdin 请求容量、异步/后台日志、启动器长期监督、OS 回收失败、真实外部模型及正式候选安装仍缺独立证明。
