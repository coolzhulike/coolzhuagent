01 · QUICK START

安装后第一次启动

先完成本地工作区和模型会话配置，再把工具权限交给聊天室。权限属于聊天室，不会因切换模型而绕过。

1

启动软件

从桌面或开始菜单打开 “COOLZHU CODE Agent”。启动器会拉起本地服务与 Tauri 控制台。

2

选择项目

在“项目”中确认工作区路径，等待文件和符号索引完成；后续相对路径都以活动工作区为根。

3

配置会话

在“设置”中配置 Provider，再创建或选择已有模型会话；可填写上下文容量与最大输出。

4

选择聊天室

在“聊天室”明确选择发送对象。历史、记忆、会话模型与工具结果均按聊天室组织。

5

设置权限

在聊天室设置普通、工具或 full-access 权限。高风险写入和输入事件仍可要求一次性审批。

6

检查终态

工具成功、失败、拒绝、超时或取消后，都应在原模型会话看到唯一终态与原因。

隐私边界 发布安装包不得包含 web-sessions、SQLite 及 sidecar、.env、coolzhu.toml、微信凭据、二维码、密钥、日志备份或当前模型会话配置。当前 0.2.0 候选制品的暂存目录与行政解包结果均已通过扫描；重新生成制品后仍应核对对应扫描报告。

03 · CONTEXT

  1. 建立会话：选择 Provider、模型、推理强度、上下文容量和最大输出。微信侧只能选择已经配置好的会话。

04 · TOOLS

工具调用的可靠闭环

模型可以提出工具调用，但能否执行由当前聊天室权限、工具风险级别和审批状态共同决定。

模型识别意图→参数与路径归一化→聊天室权限预检→执行或审批→唯一终态回灌

成功 completed：结果、证据和实际作用域进入原模型回合。

失败 failed/blocked：返回具体原因；相同失败由看护阻止递归调度。

审批 rejected/timed_out：批准、拒绝、超时或取消均有终态，未批准时不得产生副作用。

轮数上限：达到最大反馈轮后停止执行新工具，并让模型向用户说明。

07 · WECHAT CONNECTION

微信私聊连接

窗口名称为“微信连接”，机器人显示名为 “coolzhu robot”。当前官方 iLink Provider 仅支持私聊，不把群聊能力列为发布承诺。

1

扫码登录

二维码直接显示在“微信连接”窗口。扫码成功后状态应切换为 Online 并隐藏二维码；不要跳转外部二维码窗口。

2

认领操作管理员

在窗口内点击“认领管理员”。这里指 coolzhu robot 的操作管理员，不是微信群管理员；默认与已登录微信账号绑定。

3

绑定路由

先选择 coolzhu 聊天室，再从该聊天室已有模型会话中选择发送对象。模型名相同也必须按会话编号、ID 或唯一会话名选择。

4

继承权限

微信联系人能力与目标聊天室授权取交集；微信通道不能扩大 full-access、工具、文件或审批权限。

聊天成员

可以私聊并接收模型回复、查询自身和连接状态；不能调用工具、读写文件或控制任务。

操作员

在聊天室授权范围内增加工具调用和文件读写；不能管理任务、解决审批或更改管理员绑定。

操作管理员

由登录账号在窗口内认领，可管理路由绑定、任务与审批。管理员身份不能越过聊天室本身的权限边界。

10 · TROUBLESHOOTING

常见问题

控制台页面空白、旧样式或按钮没有响应

先在诊断中确认 web-console health。前端资源通过 include_str! 编译进可执行文件，修改 HTML/CSS/JS 后必须重新构建并重启；旧进程占用端口时先安全退出旧进程。浏览器控制台仍有错误时记录首个错误及请求状态码。

会话上下文限制保存后没有生效

确认编辑的是当前活动会话，并检查保存后的“有效值/默认值/是否覆盖”。清空两项再保存会恢复 Provider 默认。微信端会话目录变化后必须重新发 /sessions，再用编号或稳定 ID 选择。

工具写到了错误目录或中文输出乱码

先在“项目”确认活动工作区，再在终端执行 (Get-Location).Path。相对路径必须以活动工作区为根。中文 Windows 子进程输出应按 UTF-8 优先、失败后回退 GB18030；若仍乱码，保存原始命令和原始字节来源。

工具一直等待审批或模型反复调用同一失败工具

在任务/聊天室审批卡选择批准、拒绝或取消。每个终态都应回到原模型会话。重复失败看护会阻止相同请求继续调度；先修复权限、参数或外部依赖，再由用户主动发起新请求，不要通过模型递归自重试。

Browser Bridge 已连接但自测提示 restricted_page

浏览器内部页、扩展页和部分安全页禁止快照。使用普通网页或随任务打开的本地测试页；任务只能关闭自己创建的标签。受限页兜底后的五项专项自测已通过，最新证据见测试表 CU-04。

Computer Use 显示不可用或动作没有发生

确认工具目录中的 computer-use 分类、Browser Bridge/桌面适配器健康、当前聊天室 full-access 和审批状态。失败原因应同时显示在工具结果和模型反馈中；无权限时输入事件必须为 0。

实时语音没有转写、没有声音或重复朗读

检查所选麦克风/扬声器、STT/TTS readiness 和 Provider 配置。默认环境使用 half_duplex_guarded；full streaming 四门不齐时不要强制启动。重复朗读时检查增量去重；“Remote context usage”及之后内容不应进入 TTS。

微信二维码刷新失败、扫码后仍显示二维码

确认 sidecar 与 provider health、登录端口及旧进程状态。二维码应内联显示；扫码成功后页面应在轮询周期内切换为 Online 并隐藏二维码。若显示“无法连接”，先用 /status detail 或窗口诊断查看具体环节，再执行一次 /reconnect。

微信消息无回复或提示“未找到绑定”

依次发送 /rooms、/room <编号>、/sessions、/use <编号>。不要用模型名代替会话标识；/new 不创建会话。仍无回复时检查联系人权限、聊天室授权、inbox/outbox/dead-letter 状态和最近结构化错误。

微信 /file get 没有返回附件

路径必须位于授权根内，联系人需要文件读取权限，Provider 必须在线。先用 /file info <路径> 检查存在性与大小，再执行 /file get；失败后查看 /errors，不要连续发送相同请求触发重复失败看护。

如何确认安装包没有带入个人配置

以对应 MSI 的暂存目录和行政解包结果为准，扫描会话 JSON、SQLite 及 sidecar、.env、coolzhu.toml、key/token、微信凭据、二维码、日志、备份和个人绝对路径。当前候选制品两处均扫描 776 个文件、0 项发现；重新打包后必须核对新制品自己的扫描报告，不能沿用旧报告。
