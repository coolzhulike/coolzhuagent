## 2. 架构与定位地图

主界面由 Web Console 提供，桌面 Tauri 外壳加载其本地 HTTP 页面。Web Console 同时编排会话、权限、模型调用循环、工具执行、SSE 和 SQLite；它不是单纯的前端静态服务。能力模块仍分别位于 core-runtime、llm-adapter、tooling、vision 和 computer-use。

本轮抽出统一参数页、聊天体验脚本和统计后端模块，没有开展全仓架构重写。

## 3. 功能变更与验收契约

### P1：工具暴露、权限与偏航恢复（最高优先级）

| 功能 ID | 旧问题 | 新行为与判定依据 |
| --- | --- | --- |
| P1-01 | 调试完全访问会覆盖工具关闭并强制扩大暴露 | 权限和工具开关分别求值。关闭工具后请求无工具 schema，执行端也拒绝未开放调用；完全访问不会重新启用工具 |
| P1-02 | 工具策略主要靠全局设置 | 会话可覆盖工具开关、暴露模式、名单、Computer Use；请求构建和实际执行两端检查 |
| P1-03 | 小上下文只剩电脑操作工具，文件任务偏航 | ≤16,384 上下文仍可保留常用文件/搜索/命令/语义工具；纯 HTML/SVG/文件任务不会因此被迫走 UI |
| P1-04 | Computer Use 绕过模式/名单，旧语义路径可旁路 | Computer Use 也受全局、会话、房间、模式、名单及意图限制；旧本地意图进入统一校验 |
| P1-05 | UI 失败后任务丢失或工具结果充当答案 | UI 终态继续限制后续 UI 操作；最多一次无工具恢复原任务，保留历史和已执行结果 |
| P1-06 | 正文伪 `<tool_call>` 被静默当作完成 | 已识别伪调用不执行；触发一次恢复。再次伪调用/空回答/非法调用等明确显示未完成，不无限重试 |
| P1-07 | 权限显示和生效状态不同 | 房间权限接口分别给保存值和 effective 值；调试完全访问明确标注，不改写原房间授权 |

关键优先级：

- `enable_llm_tools` 会话非空值覆盖全局；会话 true 可以覆盖全局 false。房间关闭工具仍是上限。
- Computer Use 必须先满足全局 `[computer_use].enabled=true`，再满足会话/房间等限制；会话 true 不能覆盖全局 CU=false。
- `tool_allowlist=null` 表示不增加名单限制；`[]` 表示没有工具；非空列表与模式产生的集合取精确名称交集。
- `all`、`whitelist`、`dispatch-only` 是三个 API 合法模式。dispatch-only 至多提供 `tools_semantic_dispatch`，不追加 CU。
- `dev_open_permissions` **debug 缺省 true、Release 缺省 false**，显式配置优先。Release 升级不会强行清除用户原来显式设置的 true。
- dev_open 不改模式字符串，但权限变高后 whitelist 可用集合可能增大。看到工具数增加不能据此断言模式被改成 all。
- 名单约束模型调用入口，不等于禁止入口内所有操作：开放 semantic dispatch 后，可识别文件写入仍按文件权限链执行；不能把“只开放 semantic”误判为“完全无写能力”。

对应 API：`GET/POST /api/sessions/{id}/model-settings`；`GET /api/chat/rooms/{id}/permissions`；`POST /api/chat/send`、`/api/chat/send/stream`、`/api/chat/send/relay`。

重点边界：纯文本不会获得执行授权；明确要求原样协议示例可作为文本显示。当前伪调用检测并非通用 XML/Markdown 解析器，对解释文字前缀、围栏大小写等应记录实际行为，不能预设任意标签形态都可检测。详见 [P1 专项测试契约](testing/release-0.2.12/tool-policy-test-contract.md)。

### P2：统一模型参数配置

| 功能 ID | 新行为 | 验收要点 |
| --- | --- | --- |
| P2-01 | 使用一个模型参数页面，不再要求维护 Provider 配置表 | 左侧设置 → 模型参数；可编辑指定会话；模型 ID 自由输入，新模型不必先添加目录条目 |
| P2-02 | 连接、容量、采样、思考、工具策略统一保存 | 读取、保存、重载后值一致；参数进入实际模型 HTTP 请求，而不是只改变页面 |
| P2-03 | 显式原生协议和精确 Endpoint | OpenAI Chat Completions、Anthropic Messages；完整 Endpoint 不被再次追加协议路径 |
| P2-04 | 显式思考模式适应未知模型 | auto 沿用能力目录；effort/thinking/adaptive/budget 按对应原生字段发送；协议和互斥组合保存前校验 |
| P2-05 | 安全编辑密钥与长路径 | 密钥不回显；UI 留空保留，明确清除才删除。长本地模型路径不再受旧 64 长度限制 |
| P2-06 | 编辑草稿与运行环境区分 | 编辑另一个会话不等于激活它；普通会话刷新不抹草稿；跨工程使旧编辑上下文失效；保存等待真正完成 |

接口请求为 `{ "session": { ...可选... }, "parameters": { ... } }`。**POST model-settings 整组替换 parameters**，不是字段 merge：自动化测试应先 GET，保留无关字段后修改目标参数。旧 `/model-limit` 只改容量，不得清除新参数。UI 留空密钥会省略该字段；直接 API 显式传空串具有清除含义，测试不能混用。

长字段边界按当前实现核对：模型 ID 最多保留1024个 Unicode 字符，密钥最多4096个；直接 API 超长输入仍按既有归一化逻辑截断，不能将“超长必返回400”作为已实现契约。

保留旧 provider 身份用于读取既有配置、环境变量密钥和默认策略；“移除 Provider 配置表”是用户配置流程变化，未删除底层协议适配器。当前不宣称支持 OpenAI Responses 或所有服务商的任意私有参数。详细字段、范围、枚举及请求映射见 [模型/消息专项契约](testing/release-0.2.12/model-chat-test-contract.md)。

### P4：消息展示、搜索定位、耗时与 Token

| 功能 ID | 新行为 | 测试判据 |
| --- | --- | --- |
| P4-01 | 思考只在生成期间显示，正文开始即收起 | SSE 先思考后正文；完成/失败/取消/切房间无残留思考卡。隐藏是 UI 规则，不是删除协议上下文 |
| P4-02 | 工具过程使用独立状态栏 | tool-call/result/summary 及旧别名不生成普通聊天气泡，也不进入可见消息索引/搜索/朗读 |
| P4-03 | 房间完整历史搜索和定位 | 不只查当前加载的 DOM；支持关键词、分页、消息序号、目标前后上下文及返回最新 |
| P4-04 | 每轮实时计时、结束后保存耗时 | 刷新/重启仍有记录；旧历史缺失耗时不根据页面停留时间补造；普通/流式/接力均覆盖 |
| P4-05 | 右侧用量按房间汇总并分 Agent 展示 | 模型真实 usage 为依据；同轮工具反馈可能产生多次模型请求；累计流式 snapshot 不重复累加 |
| P4-06 | usage/耗时独立 SQLite 事实记录 | 旧 session 快照写回不擦除新事实；完成或取消只落一次已得到的用量；旧无 usage 历史不补估算 |

统计口径必须保持一致：

- 消息 `#序号` 是可见消息顺序位次，不是永久 ID；删除后会重排。定位以稳定消息 ID 结合 around 查询完成。
- 搜索范围是**当前房间完整记录**，不是全应用所有房间搜索。
- `requests` 是有可解析非零 usage 的模型请求数，不是聊天轮数，也不保证等于所有 HTTP 尝试次数。没有返回 usage 的请求不能伪计消耗。
- 输入/输出合成 total；缓存读/写单独展示，不再次加到 total。不要把上下文估算当消耗，也不要假设所有协议都返回思考细分。
- 无需为了 UI 隐藏思考/工具而删除底层结构化消息，后续工具反馈仍依赖原始协议内容。

相关路由包含 `GET /api/chat/rooms/{id}/search`、`/insights` 与消息 around 查询；参数、响应及删除级联边界以 [专项契约](testing/release-0.2.12/model-chat-test-contract.md) 为准。

## 7. 兼容、维护与回退注意

- 新参数继续存入 `session_model_limits`，保持旧配置可读。明确区分 null/未设置与0；不要用默认表单值抹掉继承关系。
- 新usage/耗时事实独立于旧快照，旧数据缺少字段时不估算回填。数据库字段与删除清理规则见专项附件。
- 静态资源支持磁盘覆盖，默认安装目录比内嵌优先；开发机还可能回退编译源码路径。本次安装目录无旧index/src，验收另用显式静态root排除了源码回退。将来升级若有人工放置旧资源，必须对比hash，不应仅刷新缓存。
- 背景、图标、头像和竹叶脚本仍是外置assets；HTML/JS/CSS内嵌不代表整个界面完全单文件。
- 修改前端必须重编并重新发布；不要只复制某张CSS造成DOM/脚本/样式跨版本混用。
- 本次没有改 Goal 失败回退等其它未闭环需求，不应从界面改版推断这些业务已完成。
- 需要回退时先停止本应用、备份当时数据，再评估安装旧包与数据库兼容。旧MSI仍在dist；不自动降级，不把安装前备份无条件覆盖用户后来产生的记录。
