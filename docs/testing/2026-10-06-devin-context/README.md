# Devin 同一远端会话续接：改动与真实测试交接

日期：2026-10-06。范围为本项目聊天室的 Devin ACP 会话，适用于 SWE-2 与 Opus 5.5 High。**本目录记录源码候选，当时正式安装版 0.2.74 未包含本轮改动；不能把这些候选截图当作新安装包验收。** Browser Use / Paint 基础验收沿用 0.2.74 / 0.2.73 已归档报告，不在本轮重复宣称全面通过。

后续已构建并安装 0.2.75；正式身份及六轮页面续接/重启验收见 [0.2.75 交接报告](../release-0.2.75/change-report-and-test-handoff.md)，与本目录候选证据分别记录。

## 问题及行为

旧聊天适配把 run_id 纳入上下文身份，每轮新建远端会话并重复传入宿主历史。现在按冻结工程、聊天室、Agent 配置、调用通道绑定远端 ID；同一上下文使用 `session/load` 继续，正常关闭或后台重启后也能恢复。精确模型变化或明确重置上下文时归档旧绑定并新建。恢复失败明确报错，不能静默创建替代会话或重发旧任务。

首次发送使用宿主选定历史；之后仅发送当前用户输入及新增、更正的宿主历史。宿主消息 ID 与内容摘要用于去重；实际生成回复时确定的 Agent ID 用于归属，同一运行中其他发送对象的回复仍须导入。增量消息带原始作者，不能把其他模型的回复冒充成自己的远端回复。模型参数页增加简短续接提示，不显示远端 ID、游标或其它调试数据。

系统说明与选定记忆改变时发送替代版本。更正、撤回只作废远端旧内容；远端已经接收的原文不能物理擦除，彻底清空须明确重置。直接查询消息库确认撤回，不能将历史预算裁剪当作删除；只在协议 end_turn 且进程已排空后确认同步。已撤回以及预算外更正的旧版本有持久作废标记，避免每轮重复通知，未注入的新正文仍保留后续真实注入资格。

## 职责及改动位置

路径前缀：`modules/gui-web/packages/web-console/src/`。

| 文件 | 职责 | 针对性检查 |
|---|---|---|
| `devin_acp/context.rs` | 新增宿主增量投影、已发送摘要与撤回同步记录、实际回复归属 | 其他模型消息导入一次；自身回复不重复导入；未发送不推进；未知轮次不重放旧用户指令 |
| `devin_acp/chat.rs` | 稳定上下文身份；连接后登记增量，沿用既有运行、取消和工具桥 | 重启后相同远端 ID；不把每轮 run_id 当新会话；冻结工程根不被界面切换覆盖 |
| `devin_acp/journal.rs` | 保留原协议状态机；稳定绑定每轮仍检查旧锁收尾；显式 reset 允许变更隔离缓存目录 | 不能用“同一上下文”绕过旧执行收尾；取消且排空只解锁，不改判旧轮成功 |
| `devin_acp/session.rs` | load 失败明确报恢复失败并提示核账号/重置 | 不 fallback new，不重复发送；CLI 固定版本变化需要适配重新验收，不能只靠重置解决 |
| `chat_run_admission.rs`、`devin_acp/bridge.rs` | 接纳时记录真实发送目标；工具桥分离主会话与目标身份 | 非主会话 Opus 正常读取；未接纳、缺失、跨运行或重复目标记录拒绝；保留冻结父运行校验 |
| `main.rs` | 非流式与流式持久化实际回复后登记归属 | 宿主失败提示下轮仍作为新增宿主消息回送；任一目标失败时保守跳过整轮归属登记，可能多导入成功回复，但不会漏失败结论 |
| `model_settings.js` | Devin 配置区说明续接与新会话边界 | 普通用户能知道“继续发送”与“重置”的区别；无调试信息 |

没有新增第二个运行状态机、权限系统、通用插件执行平台，也没有开放原生 Devin 文件或命令工具。DSH / SKILL 完整桥接、Goal、Relay、附件仍属于待完成任务。

## 真实模型结果

所有 SWE 回合 requested/effective 为 `swe-2-medium`，Opus 为 `claude-opus-5-5-high`。`resolved_model=null`，只证明 ACP 有效配置，不能冒称取得了服务端独立解析模型 ID。未使用模型回包夹具，没有改用 Qwen。每项原始请求、回复、运行身份与协议结果见 [证据](evidence/regression-summary.json)。

| 项目 | 实测结果 |
|---|---|
| SWE 连续对话、后台重启 | 同一 `fifth-motorist`，记住并找回合成口令；后台重启后一致，第三轮历史增量 0 |
| 外部 Opus 回复 | SWE 能读到同聊天室 Opus 新增标记；后续增量 0，仍为原远端 ID |
| 流式 API 与页面正常发送 | 实际回复和归属事件持久化，历史增量 0；页面截图显示 SWE 回复，7.8 秒 |
| 撤回两条合成测试消息 | 第一轮撤回标记 2，下一轮 0；消息库实际行数 0，同一远端继续正常 |
| SWE 显式重置 | 新远端 `veiled-anise`，历史数 0，模型回答“不知道”旧口令；旧聊天室记录保留 |
| Opus 连续对话、后台重启 | 同一 `fair-amaryllis`，连续及重启后均找回口令，历史增量 0；7.5 秒重启复测 |
| Opus 页面发送与实际仓库读取 | 页面找回原口令，13.7 秒；随后真实 `read_file` 完成，19.7 秒；主会话仍为 SWE、发送目标为 Opus，均续接原 `fair-amaryllis`，历史增量 0 |

上述正常回合均 protocol terminal/end_turn/drained。截图：[SWE 页面发送](evidence/context-ui-reply.jpg)、[Opus 连续与重启](evidence/opus-context-restart-chat.jpg)。页面截图不展示调试 ID，绑定事实从真实运行库只读核验，二者共同构成证据。

新增页面证据：[Opus 找回口令](evidence/opus-ui-final.jpg)、[Opus 真实读取文件](evidence/opus-ui-read.jpg)。读取只覆盖验收工程中的 `repository/README.md` 前 3 行，不能外推为最新版全仓审查通过。

最终 Web 检查：1390 通过、0 失败、6 跳过；最后补丁另外复测 10 项 Journal 检查和 1 项发送目标身份负向检查，全部通过。最后实际 `cargo build -p coolzhu-web-console --offline` 成功，前端脚本语法检查通过；既有编译警告仍保留，不把跳过检查记为通过。

原失败保留：流式脚本首次用了与刚结束回合相同的文本，收到重复提交 409，尚未派发模型；改用新的验收文本后成功。脚本第一次只解析 `message`、漏了 `message_done`，误报回复为空；原始 SSE 已含正确完整回复与 completed，修正解析器后重新分析原字节，没有为修正报告重发该回合。首次测试编译因内存不足失败，采用仅本 package 测试 debug=0 后通过原 10 项 Journal 检查，不将失败编译记作通过。

真实页面发送另曾失败：聊天室主配置仍是 SWE，实际发送目标为 Opus，旧工具桥错误要求二者相等，导致 ACP `not_sent`。保留[失败截图](evidence/opus-ui-before-target-fix.jpg)及事实，不追认该轮成功。修复使用接纳时记录的真实目标，不改写冻结父运行、不关闭工具、不放宽工程关系；修复后上述页面续接和读取均通过。

## Opus 审查决定

[实施复核](evidence/opus-context-implementation-reply.md)与[补丁复核](evidence/opus-context-final-reply.md)均通过本项目真实 Opus 聊天室完成，只审阅提供片段，不是全仓审查。直接查库、撤回同步、作者标记、宿主失败提示回送及预算外更正仅作废旧版本的建议已落实。原 candidate_ids 本来取全聊天室历史，Opus 在后续复核撤回了“预算裁剪必然误删”的判断。不能把模型审查意见未经核实直接作为源码事实。

`execution_failed` 实际用 OR 汇总任一失败，不是全部失败才为真；流式 `terminal_status` 一开始即为 Completed，错误/取消会更新，不存在等到登记之后才设 Completed 的问题。当前保守跳过失败整轮归属可能重复导入成功发送对象回复，属于成本边界，不会吞宿主失败提示。

## 未覆盖及后续测试要求

[真实 Opus 身份方案讨论](evidence/opus-target-admission-reply.md)同意分离主会话与发送目标。既有 HostModelSnapshot 只接受 HTTP Provider，无法直接复用 Devin；本次复用运行事件记录目标，没有增设通用状态机。非主目标的 CU 深层调用仍需另测，普通只读工具通过不能替代 CU 验收。

1. 新正式安装包上核版本、Web 摘要、launcher 自检，再测 SWE 与 Opus 正常页面两轮和重启续接；不能拿本目录候选身份代替安装身份。
2. 记录实际远端 ID、delta 历史数、模型有效配置、end_turn、进程排空、宿主回复归属和界面截图；“记住口令”单独不能证明同一远端，宿主全量重传也可能回答正确。
3. 精确模型切换、账号或会话过期 load 失败、强杀 prepared/submitted 崩溃恢复、旧 CU 取消后续接尚未实测。不新增伪造成功或重放旧工具；恢复必须尊重原输入安全库与既有收尾事实。
4. 预算外更正的新正文晚于撤回说明被选中时需真实导入；更正、记忆撤回与全量历史压缩没有本轮完整用户流程验收。当前消息界面没有一般编辑接口，不用绕过业务 API 的数据库写入伪称用户功能通过。
5. Goal、Relay、附件、自动 Handoff 后续跳转尚未接入/完整验收，不由普通聊天结果外推。CLI 升级须重新验证受控配置与协议行为。

证据不包含运行数据库、API 密钥或未经筛选的服务日志；[manifest](evidence/manifest.json)记录原字节 SHA256。原基线 PR #80 已合并，续接增量为草稿 #81；不宣称续接 PR 已合并或整合计划全部闭环。
