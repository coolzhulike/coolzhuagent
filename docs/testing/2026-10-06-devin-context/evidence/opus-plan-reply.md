**结论：方向可行，但需要先做 6 项修正。** 本轮没有调用工具，以下只依据你贴出的片段，不是完整审查。

## 一、同一远端会话：必须修正

1. **锁释放规则要两处共用。** 现在\"已取消、已排空、工具已结账就放行\"这条规则只写在 `rotate_idle_context` 里。绑定改稳定后，digest 不再变化，这段逻辑不会执行，`claim` 会一直被旧的 unknown 锁挡住。应把这组判断抽成一个函数，`rotate` 和 `claim` 都调用它。
2. **CLI 版本检查会失效。** `cli!=binding.cli_identity` 只在 digest 变化的分支里检查，稳定 digest 下会被跳过。应在 load 之前单独比较，不一致就报错，并提示用户手动重置。
3. **模型切换没有处理。** 跨模型 load 没有实测。建议把 model 放进 digest：切换模型就新建绑定，并明确告诉用户。远端 set_model 实测通过之前，不要在原会话上换模型。
4. **load 时回放的历史不能当成新内容。** load 期间收到的 session/update 回放，不能写入宿主消息，也不能计为本轮输出或工具调用。load 响应之后的事件才算本轮。
5. **工作区路径要用冻结值。** `instructions` 用的是 `active_workspace_path()`，应改为冻结父上下文里的工作区，否则中途切换工程会让提示和实际作用域不一致。
6. **load 失败（会话过期、账号变化）直接报错，并提示重置。** 只有从来没有绑定过（remote 为 None）时才允许 new。

## 二、游标

- 以绑定（工程、聊天室、agent、lane、reset、model）加 remote_session_id 为键，逐条记录：消息 ID、内容哈希、来源 attempt、状态（已导入或不确定）。
- 只有本远端会话以 end_turn 收尾、进程排空的回复，才算\"远端已有\"，不再发送。其它 agent、handoff 和宿主生成的消息（包括\"本轮未完成\"这类占位）都按外部消息导入。
- **取消并排空、但没有终态的旧轮**：
  - 那一轮的 user 消息标为\"不确定\"，不推进游标，也不当作指令重发。
  - 下一轮只附一条宿主说明：\"turn X 已取消，结果未知，不得续做\"。可以附原文作引用，但必须标明不执行。
  - CU 已由 `reconcile_drained_acp_cu` 结账，不会重复执行。
- **历史被修改**：哈希变化时，在增量里发一条更正说明，标明旧内容作废。
- **历史被删除、记忆被撤回**：发作废说明。同时要如实告诉用户：远端无法真正擦除已发内容，需要彻底清除就重置上下文。不自动新建会话。
- 每轮的系统说明和记忆都标为\"本轮替代此前版本\"。

## 三、插件与 SKILL

**过度防护**
- 会话级显式工具 ID 列表，和插件的全局启用状态形成了两套事实来源。如果 HTTP 会话已经有会话级工具选择，就复用它，不要再造一套 ACP 专用列表。
- 开插件不应该要求先开 CU。

**必要修正**
- 现在 `review=false` 就进入纯文本模式，没有 MCP。需要把布尔参数换成一个工具档位（文本、只读、插件、CU 等），由它决定 `prepare_directory_with_tools`、提示文本和 load 时的 mcpServers。每轮都按当前档位重写配置。
- 桥不要硬编码 dsh__/plugin__ 前缀的判断，应调用现有的准入函数（冻结父上下文加冻结的 DSH 绑定）。call 时只按本轮冻结的定义集合校验，不回查实时 registry。
- 防递归的排除表集中放在一处：云 Devin、子 agent、handoff 类工具都排除；CU 未开启时也排除 CU。
- 插件工具的 `required_permission_for_tool` 是否取自插件清单，我没有核实。默认值偏低就会越权，必须核对。
- 插件调用和 CU 一样走 `policy.gate`，再走 `run_model_tool_dispatch_for_session_with_identity`，不进入同步 worker，也不重复登记。
- 只读审查模式下不开放插件。
- SKILL：现有 loader 的根目录改为\"全局根 + 冻结工程里已启用的 skill\"，复用现有执行入口。skill 正文只当作工具结果，不授予命令权限；需要执行命令的 skill 会失败，要如实返回失败。

## 四、真实验收

1. 连续三轮使用同一个 remote_session_id，并且跨一次进程重启；第二轮起提示字节数明显下降，模型能复述第一轮中没有重发的细节。
2. 两轮之间插入一条外部 agent 消息，它恰好被导入一次。
3. 取消、排空后的下一轮：使用同一个远端会话，旧指令不再执行，CU 没有重复。
4. 修改、删除消息和撤回记忆时，更正说明生效。重置后建立新绑定，旧绑定被归档。伪造或过期的会话 load 失败时报错，不会偷偷新建。
5. SWE-2 调用官方计算器插件，收到真实结果，台账里有 request ID。已停用的插件不可见；审查模式下不可见；调用中途停止能正常结账。
6. 工程 skill 和全局 skill 都能调用，未启用的 skill 不出现在列表里。

单元测试只能证明规则，以上各项都要实测通过才算交付。
