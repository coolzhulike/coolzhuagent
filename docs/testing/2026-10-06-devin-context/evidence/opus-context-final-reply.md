**必须修**
1. **预算外的更正会每轮重复通知。**
   - `corrected` 遍历的是全部 known，但 `stamps` 只记 source 和 selected。没被选中投影的更正消息，known 里一直是旧摘要，所以每一轮都会再报一次\"旧内容作废\"。
   - 修法：给\"已更正、但本轮没有注入\"的 ID 写一条和墓碑同类的作废记录（可复用 `deleted:true`，或者新加 `voided`）。completed 后从 known 里移除；以后这条消息被选中时，按新增消息注入。这样既不会把没注入的新正文当成已导入，也只通知一次。

**需核实，成立就必修**
2. **`execution_failed` 是整个运行的汇总，还是每个回复各自的结果。**
   - 如果是\"全部失败才为真\"，在多目标运行里，Devin 的失败提示仍可能被记成它自己的输出，远端就看不到宿主的失败结论。
   - 如果是\"任一失败就为真\"，Devin 自己成功的回复不会被记录，下一轮会作为外部消息重复导入。这只是重复，不会出错。
   - 最好按每个 candidate 自己的失败标记来过滤。
3. **流式路径在这个位置，`terminal_status` 是不是已经被设成 Completed。** 如果 Completed 是在这之后才赋值，流式路径就永远不会记录。要确认：流式 delta0 的实测是在本补丁之后做的，并且轨迹里能看到 `chat.context_outputs`。

**可以延期**
- \"此前未完成回合\"还是会报历史上最后 8 个，建议只报最后一次 completed 之后的。
- 同一个 run 里有多次 attempt 时，outputs 会在被墓碑删除之后又重新插回 known，可能导致删除通知重复。只是边缘情况。
- 查询时带上了全部 known 的 ID，会随会话变长而增长。目前可以接受，以后再考虑压缩游标。
