## 升级与运行后数据

正式升级前与安装后首次启动前，使用同一带私有密钥的清单和 SQLite 在线备份比较：均为 66 个持久文件、41 个附件（49,153,852 字节）、6 个 SQLite 库；文件摘要、白名单表语义摘要及配置摘要一致。原始用户数据、附件和摘要密钥只保留在忽略目录 `tmp/candidate-0.2.22/`，不入公开证据。

全部上述原生操作后，以同样方法取得最终快照。排除**备份目标自己生成**的 SQLite `-wal/-shm` 临时边车后，持久文件仍为 66 个，41 个附件逐项哈希未变，配置摘要未变，`web-sessions.json` 内容未变。6 库的逻辑差异仅包括：`memory_access` 仍为 85 行，其中 2 行只变化 `last_accessed_at` 与 `access_count`；输入安全事件 89→90，归属 epoch 表仍为 2 行，其中 1 行的接管/释放时间、持有进程等运行字段变化。其余 workspace SQLite 表语义摘要相同，未见消息、附件引用或会话配置行改写。输入安全仍保留 2 条历史归属缺口、2 条待本人复核、2 条待收敛遗留，当前输入隔离；本轮没有人工放行、清库或重置安全策略。

私有 `post-runtime-final` 旧测量曾把 4 个备份目标的 WAL/SHM 边车算成新增文件，得出错误的 70 文件数；该测量保留在 `tmp/` 供审计，不作为数据结论。仅修正 `tmp/` 快照脚本的 SQLite 连接生命周期后，在新目录 `post-runtime-clean` 重取，并在比较中显式排除备份目标的瞬时边车。最终计数与字段级对比收据为 `tmp/candidate-0.2.22/runtime-diff-summary.json` 和 `post-runtime-clean/inventory.json`；没有删除或更改源用户库。
