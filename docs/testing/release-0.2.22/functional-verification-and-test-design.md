# 0.2.22 原稿界面、模型路由修复与针对性验收

日期：2026-09-27。**完整 release、正常升级、关键安装文件 10/10、原稿界面与活动网页窄窗恢复、运行后数据核对均已完成。** 本轮原生通过范围及十张实操截图见 [022 原生报告](installed-native-acceptance.md)。本文供其他模型据实际模块设计测试。前版原生 LSP/视频与运行后数据见 [021 报告](../release-0.2.21/installed-native-acceptance.md)；当前整体范围见 [后续改动报告](../navigation-update-followup/change-report.md)。不得把前版结果追认为本版通过。

## 用户可见变化与模块边界

1. 顶部恢复居中 COOLZHU 金玉字标。Agent 和工程位于左侧，聊天室位于右侧；窄窗口压缩标签而不隐藏 Logo。独立素材配合真实下拉控件，背景恢复参考原稿的竹林。改动集中于 `index.html`、`scroll_theme.css` 与 `assets/ui-redesign/scroll-frame/`，没有为本次样式重写业务状态。动画 B、已有导航与原生浏览器生命周期保持原路径。
2. 模型配置中明确保存的类型优先于模型名称。例如类型 text、ID 含 image 时，仍走文本会话；是否直接发送图片由明确的图片输入能力决定。禁用图片直传时先由配置的视觉模型转述，再给目标文本模型。旧配置只有确实缺字段才兼容推断，不猜测并覆盖已保存的 text。
3. 图片生成前置失败、请求失败向会话 run 传播失败结果；取消已经发生时不能被晚到结果覆盖。后台视频仍区分父请求已接纳与生成子任务成功/失败，不能将父 completed 当作视频已生成。
4. S0 增加正式受控录制驱动并接入 CI：真实 Web 接纳、工具派发、轨迹和用量由产品执行，本地假模型提供可重复响应。六类主场景与三个夹具拒绝场景用于日后回归，不能冒充真实云模型或原生桌面验收。

路由和失败传播的具体文件、兼容策略及 11 个场景见 [模型窄修报告](../navigation-update-followup/model-media-routing-narrow-fix-2026-09-27.md)。S0 命令、隔离和拒绝边界见 [正式驱动报告](../navigation-update-followup/s0-controlled-replay/ci-integration-2026-09-27.md)。功能证据与测试工具自己的白名单区分记录。

## 远端 CI 首轮失败

[Draft PR #68](https://github.com/coolzhulike/coolzhuagent/pull/68) 首个 head `f1d80e3` 的两条 Windows 检查均编译成功，随后 S0 步骤在打印中文进度时抛出 `UnicodeEncodeError`（charmap）。日志定位到测试驱动输出编码，不能记为产品会话失败，也不能因为本机通过而隐藏远端失败。`d38a2a5` 仅修复驱动 stdout/stderr UTF-8，并在本机 `PYTHONIOENCODING=cp1252` 下复跑六类与三拒绝，全部通过；该提交两条真实 Windows CI 的编译与 S0 步骤也已通过。其余阶段及最终 head 状态以 PR 检查为准，详细失败和修复证据见 [CI 编码报告](../navigation-update-followup/s0-controlled-replay/ci-windows-encoding-followup-2026-09-27.md)。该后续测试脚本修复不属于 022 原打包快照，产品源码和已安装文件不变，不以新提交追认旧构建输入。

## 原生首轮窗口来源核查

正常安装文件已核对通过，但首轮桌面截图显示临时 `visual-scroll-final` 工程；随后 Accessibility 核实该窗口 URL 为 `http://127.0.0.1:55222/`，是开发预览地址。因此该图不计入 022 安装版功能通过，仅可作为来源待核的本机过程记录。注册版本和磁盘文件哈希无法单独证明某个显示窗口所连接的 Web 来源。

已核实预览环境虽隔离 HOME/APPDATA/运行目录，却遗漏 TMP/TEMP/TMPDIR。Web 启动会向 `env::temp_dir()/coolzhu-gui-web-url.txt` 写地址，共享文件在预览启动时被写为 55222；桌面壳可以读取该提示。两个预览服务随后均停止，端口无监听。预览操作者尝试删除该精确提示文件遭自动审批拒绝，未绕过、未换工具重试删除；改为按产品正常流程退出相关旧壳并启动正式安装版，由 Web 自身启动写入当前地址。先核窗口 URL=8765 及对应安装 Web 的 SHA-256，再继续截图。实际进一步核实：操作者首轮直接启动了桌面 shell，该入口读取残留提示文件；不能将其记为正式 launcher 启动失败。正常关闭误绑壳后，使用系统注册的 `COOLZHU CODE Agent` 正式入口重启，新安装 Web 监听 8765、文件路径在 Program Files 且哈希为本版 F9C08D…A384A，窗口 URL 为 `http://127.0.0.1:8765/`，提示文件由正常启动自然更新，原用户工程和受控验收房恢复。未执行被拒的删除动作，也未改安全策略。自这个来源确认时点起才记录 022 原生功能证据。此后所有隔离预览必须同时隔离系统临时目录并避免与原生验收并行；正式 S0 驱动已有这些隔离变量。
