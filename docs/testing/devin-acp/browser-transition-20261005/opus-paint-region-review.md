**结论：契约可以采纳，没有新增坐标体系，也没有扩大权限。有 2 项必须修，其余可选。** 本轮没有调用任何工具，下面基于你给的事实；源码没读，"已有/未有"的判断都要你核对。

**必修**
1. **执行时校验落点。** 你的 rect 用 UIA 完整范围，画布滚动或放大时可能超出可见区。这时按 rect 相对坐标换算出的屏幕点，会落到工具栏或滚动条上。如果现有执行器没有这项检查，就在执行时逐点核对：换算后的每个点都要落在该元素的可见范围（rect 与客户区的交集）内，否则只拒绝这个动作。候选为空、只观察时都不拒绝。
2. **标清坐标单位。** 候选里写明 rect 和 visible_rect 都是屏幕坐标，和截图 screen_rect 同一坐标系。还要写明拖拽相对的是 rect，不是 visible_rect。canvas_rect 的说明同时改成"客户区，含工具栏"。不改字段名，也不改原来的语义。

- 第一版不进 FrameRef 的相等比较，避免旧帧失配。
