# 定时任务结果聊天室绑定：源码候选

当前正式101的 poll 定时任务固定发送到系统聊天室。Devin 按工程、聊天室及 Agent 绑定远端，因此直接测试会创建另一云端会话。本轮把轮询结果房间作为计划配置，复用原 SWE-2-medium / island-kayak 的实际验收留到新正式包；没有复制远端绑定或修改运行库。

## 实现与使用

- 定时任务页选择发送对象、轮询型、结果聊天室、计划及内容后创建。结果房间固定保存，后续切换当前聊天室不会改变已有任务目标。列表显示结果聊天室；已删除的目标明确标为不可用。
- 创建 API 新增可选 `chat_room_id`。省略或 null 保持旧系统房间；显式空白返回400，不存在或不属于当前工程返回404。新页面要求轮询型明确选择房间。Goal型不接受该字段，仍走原目标执行和系统房间镜像。
- 新 `scheduled_delivery.rs` 只负责 poll 的房间复核、原聊天入口调用及真实终态判定；领取/计划投影仍由原调度器负责，权限生命周期仍由 `scheduled_execution` 负责。模型执行不在存储锁内。
- 任务配置 None 跳过序列化，保持旧任务完整 JSON 字节与领取指纹。执行按已固定的工程 pin、发送对象及房间创建原300秒单次权限上下文；请求携带 `expected_workspace_id`，不修改房间权限表。
- 显式目标删除后，不创建替代系统房间或改投其它房间。失败状态只写原目标房间；目标已删除时仅保留原领取/计划失败记录。聊天实际持久化入口也在同一存储锁内复核房间存在，晚到输入或回复不能自动重建已删除的房间。
- 后台定时投递保持 `native_browser_panel=false`，不能借页面选择永久接管前台浏览器。
- 非流式 HTTP200 可能带真实 failed、interrupted 或 commit_pending。现在只有 `execution_failed=false` 且运行回执 completed 才按成功推进；其它状态明确失败或未确认，不自动再提交。回执采用真实终态描述，不把“真实模型已启用”之类通用 notes 当失败原因。

## 验证与失效用例

最终 offline build成功（34.48秒），JavaScript语法检查通过。最终完整控制台1420通过、0失败、6既有忽略，另lib8与原生宿主1通过，主回归执行32.92秒；见[最终原日志](tests-final.log)及[摘要](verification.json)。这些是源码回归，正式安装版实机仍待。

首轮完整回归为1419通过、1失败、6既有忽略。旧 `task_schedule_run_due_uses_system_room_without_changing_active_room` 使用无有效模型配置的 Custom/qwen，却把 API HTTP200 作为 executed；补诊断复现后，真实运行失败，返回的末条 notes 只是“真实模型已启用”。旧测试也手动替换全局存储与配置，断言失败后不能正常恢复。没有把失败预期改成成功，也没有补模型夹具：删除此失效测试，以本地宿主准备检查保留系统房间幂等创建及不切换当前房间的原意。

仅新增三个确定性宿主回归：旧领取字节不变；绑定精确作用域/删除零准备与无替代房间/旧路径幂等；HTTP200缺少完成终态不能推进计划。它们不执行模型、不代替正式软件验收。首轮失败及补诊断日志单独保留，不能抹除后声称首轮全部通过。
