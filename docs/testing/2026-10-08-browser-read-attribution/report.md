# Browser读取回调错误归因修补（源码候选）

代码审查发现，`read_session`先处理WebView2失败HRESULT，再核对资源/URL。若失败回调到达时面板已关闭或文档已切换，原代码会将已经确定的资源变化覆盖为通用观察失败或命中测试失败。

修补仅将回调处已有资源/URL核对放到HRESULT判断之前；资源仍相同时保留原失败分类，成功读取继续使用原UTF-16长度与JSON校验。没有新增HTTP接口、重试、等待、状态库、权限例外或前端调试控件；输入投递与释放事实完全不改。队列失败、超时与取消分类未扩改，没有将所有失败泛化成资源变化。

实际独立桌面workspace离线构建退出0；完整既有桌面回归76通过、0失败、0忽略，驱动最终退出0已读取。未为几行判断搬移添加镜像测试。证据保留原始构建/测试输出及源文件SHA。此轮模型请求0、新云端会话0；正式110仍运行旧源码。

这是静态发现和源码修补通过，不是失败HRESULT与资源切换同时发生的实机闭环，也不能关闭严格down/up窗口的新Target替换、跨来源commit、在途观察资源撤销验收。后续统一出包复验，不能继承110的安装或截图结果。
