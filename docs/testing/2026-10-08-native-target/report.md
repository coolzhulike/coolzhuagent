# 097 新原生目标替换：严格时序未命中

本轮使用 0.2.97 正式安装版、原 SWE-2-medium 和唯一 `island-kayak`，只提交一次真实 `computer_use_perform`。正常关闭旧网页标签，再点击已保留的新网页标签，导航诊断确认原生 generation 从 1 变成 3；新页面未收到旧动作的 pointer、click、input 或 key 事件。

**严格按下期间替换仍未验收通过。** 网页记录的真实按下至释放为 2401.6 ms，而正常关闭操作开始于释放后 6413.5 ms。新原生目标也在释放之后创建。不能把本轮结果混算为按下期间替换，更不能把模型转述的“期间替换”当作时间证据。

旧动作投递一次且 released；关闭后旧轮观察以 `native_browser_panel_unavailable` 停止，CU blocked，父运行 failed，无重试或补发。远端正常 end_turn、进程 drained，原绑定解锁，没有新建云会话或修改输入安全状态。新页面显示“没有输入事件”。

证据：[真实时序与台账](result.json)、[仅文件导航诊断](navigation-diagnostics.json)、[替换前实拍](before.jpg)、[新目标实拍](new-target-loaded.jpg)。`server.py` 为普通受控网页事件记录器，不生成模型答案、不驱动宿主动作。

本轮没有产品代码改动。桌面壳在空闲且路径、启动时间、安装摘要全部匹配后重启，仅开启文件导航诊断；生产后台与安全库保持。该实验明确暴露两次正常 GUI 操作加模型/工具回合开销无法稳定命中约 2.4 秒窗口，后续需要调整采证方式，不能以扩大到输入超时之外的忙等待来制造通过。
