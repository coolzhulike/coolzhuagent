# 0.2.14 Agent 回归测试契约

本文件供其他模型或测试人员设计用例。它描述可断言的行为与失败边界；实际执行结果见同目录的版本改动报告，不能把下表中的预期当作已通过记录。

## 测试环境与判定层级

使用独立运行目录和端口，复制测试模型配置时仅在本机复用凭据，清空测试副本历史。不得把含凭据的配置、数据库、原始请求或真实用户截图提交仓库。测试前回读模型 ID、协议、图片能力与工具设置；截图只采集已授权的测试窗口。

正式 Computer Use 测试需工程启用、会话启用、聊天室持久化 full-access 三者同时满足。调试全访问开关不能代替房间授权。仅开放测试所需工具；画图测试只允许 `computer_use_perform`，不得用绘图脚本、图片导入或主测试程序代画。

分别判定四层结果：外层聊天是否结束、工具调用终态、Computer Use 控制器终态、窗口中的实际效果。外层回复“已完成”不能证明工具成功；工具执行了输入也不能证明图像目标达成。模型只完成部分绘图时，应如实记录部分效果。

## 核心功能点与用例边界

| 编号 | 前提与刺激 | 必须断言的结果 | 反例与边界 |
|---|---|---|---|
| AG-STREAM-01 | 模拟流式 thinking、工具参数分片、最终答案；参数含大型 HTML 与专用标记 | 参数完整还原为工具 JSON；思考正文不含工具参数标记；同轮原生调用与结果保持配对 | 分片跨 UTF-8 字符；空分片；两个同名工具；取消发生在参数未完成时 |
| AG-STATUS-01 | 首次流式请求加至少一次非流式反馈请求，产生多个工具调用 | 每个真实调用只有一个稳定状态项，按请求→执行→终态更新；摘要和结果不重复计数；终态不被晚到事件改回执行中 | 同名不同 ID；重复事件；晚到旧房间事件；失败、取消、流断开 |
| AG-FALLBACK-01 | 工具调用后模型未返回最终文字；分别构造全失败、混合、未执行、全成功 | Agent 兜底正文准确描述调用状态，不能把调用数量当作任务完成证据；保留失败原因并说明尚不能确认目标完成 | 流式/非流式/接力或侧车入口；失败摘要中包含“完成”字样；模型完全空响应 |
| AG-HISTORY-01 | 第一轮产生思考、工具参数、工具结果、最终答复；第二轮再次提问 | 第二轮跨轮上下文不把内部思考和审计消息当普通 assistant 正文；必要工具事实/产物引用去重保留；旧存储审计不删除 | 历史老格式；上下文重置；同轮 ToolUse/ToolResult；重复大文件读取 |
| AG-MEMORY-01 | 已有自动 decision/旧自动压缩、工具记忆和手工记忆；随后新建自动记忆并召回 | 思考不能经自动记忆重新进入下一轮；新自动压缩先投影且使用 v2 来源；旧工具记忆转为有界事实；手工记忆和正常聊天/经验不删除、不误过滤 | 旧无类型自动压缩只停用召回、不删除存储；origin_message_id、manual 来源、跨房间召回边界 |
| AG-PLAN-01 | 给规划器桌面或浏览器观察，包含 target、constraints、capabilities | 请求包含当前 surface 的完整动作对象契约；动作输出可严格解析；不混入普通聊天“只回复最终文本”的指令 | `action:"click"`、未知字段、错 surface、伪造引用必须明确失败 |
| AG-PLAN-02 | 观察含大量 UIA/DOM 节点和多字节文字 | 观察裁剪后仍是完整 JSON，节点不会被切成半个对象；图片通过图像块传输 | 超限节点、不可见目标、过期 generation、恶意页面文字 |
| AG-CANVAS-01 | 最新画布引用；`drag` 携带 2–256 个相对点和可选时长 | 点映射到当前受控目标矩形；输入顺序为移动→按下→沿路径移动→释放；真实输入有前后证据 | 1/257 点、NaN、越界、超时长、错误窗口、DPI 或窗口位置改变 |
| AG-CLICK-01 | UIA 点击落到正式 SendInput 通道 | 传给原生 API 的按下/抬起 flags 分别为 2/4，不能只验证 API 返回 1；检查移动/输入返回值，失败如实报告，down 后失败仍释放 | PowerShell 嵌套值类型必须完整写回；移动失败不得点击；按下失败仍释放；释放失败优先上报 |
| AG-DPI-01 | 宿主进程 DPI-unaware，桌面缩放为 150%；观察同一个 Paint 窗口 | UIA 窗口 rect 与原生输入 helper 都使用物理像素；同步观察退出后恢复调用线程原 DPI 上下文；不再因逻辑/物理坐标混用误报窗口移动 | 100%/150%/多显示器；最大化窗口不可见外框；观察提前失败；窗口真的移动仍拒绝旧输入 |
| AG-CANCEL-01 | 长路径进行中或下一动作尚未执行时取消 | 尽快停止后续输入；已按下的鼠标释放；取消记录不伪装成功 | Escape、房间中止、原生调用失败；取消后不得再追加动作 |
| AG-VISION-01 | 当前会话支持图片，规划和验收均需要识别画布 | 最新截图原图进入模型协议图像块；不能仅依赖 UIA 文字判断绘画内容 | 无截图、损坏数据、重复旧截图、窗口遮挡 |
| AG-VISION-02 | 当前会话为纯文本，系统配置默认视觉模型 | 原图先交给默认视觉模型；当前文本规划器收到有来源的描述；独立记录两次模型调用用量 | 默认视觉缺失/不支持图片、空描述、识别失败均明确阻断 |
| AG-VERIFY-01 | 执行动作后图像与先前不同，模型逐项检查目标 | 完成须有实际截图依据和每条目标的非空证据；元数据或 UIA 文字改变不能单独判完成 | 只有窗口获得焦点、只移动鼠标、空白画布；缺项目/重复索引的验收 JSON |
| AG-USAGE-01 | 外层对话内嵌规划、视觉描述、视觉验收请求 | 有房间且响应提供非零 usage 时，每次真实响应仅记一次；CU 调用关联房间、provider trace、工具调用及用途；解析失败但已有 usage 仍记账 | provider trace 不是公开 chat-turn ID；普通聊天用量暂无调用关联；缺少或全零 usage 不入表，不虚构 token |
| AG-AUDIT-01 | 正常动作、解析失败、输入失败分别运行 | 记录真实步骤类型、目标、时间、前后证据和错误；CU 规划诊断限长脱敏，不保存完整思考或图片 data URL | 原聊天 reasoning 审计仍保留；超长/畸形 JSON、token/password 字段、进程中断发生在输入后 |

## 桌面路径参数

规划器动作对象形如：

```json
{
  "done": false,
  "action": {
    "kind": "drag",
    "target": "<当前观察提供的画布引用>",
    "arguments": {
      "points": [[0.2, 0.2], [0.5, 0.2], [0.5, 0.5]],
      "duration_ms": 800
    }
  }
}
```

目标引用必须来自当前观察。桌面相对路径与浏览器 DOM 拖拽是两个 surface 的不同参数契约，不应互相套用。时长上限 5 秒，点坐标为闭区间 0–1；最大坐标必须映射到目标最后一个有效像素，不能落到相邻窗口。

`window-canvas` 备用目标范围是整个可见窗口客户区，可能包括工具栏，不保证等于图像中的实际绘图区。模型请求必须明确这一点，实际绘图区由截图定位。输入成功但后截图失败时必须保留 `input_sent` 事实；缺少后图不算进展，也不能判目标成功。参数无效而尚未进入执行时，最多允许两次可纠正提交；第三次仍无效则关闭纠错，实际执行限额单独计算。

## 真实模型回归流程

1. 两轮文件任务：第一轮让模型写一个独立 SVG 动画 HTML 并读取确认；第二轮读取、修改标记和背景再读取确认。保存工具 ID/状态、实际文件、最终答复与两轮用量。检查工具参数没有作为思考内容出现，工具状态数量与真实调用数一致。
2. 新建空白 Paint 窗口，记录窗口标题和前图。通过正式工具请求手绘粗略海绵宝宝，不要求绘画质量。至少记录真实路径动作及后图；如果只发生工具选择或窗口聚焦，就没有完成画布动作验收。
3. 检查嵌套规划/验收请求的 usage、严格解析结果、控制器终态、真实步骤与证据。若接口契约有效且已执行输入，但模型画得不好，归为模型表现；若没有提供动作契约、截图或输入接口，归为 Agent 缺陷。
4. 纯文本视觉中转使用显式关闭图片能力的测试会话副本，确认默认视觉模型接收原图、文本会话未收到图像块，之后恢复测试配置。
5. 新安装包启动后再次回读配置、验证网页资源和核心用例。安装前后核对用户数据摘要；保留原 Base URL 与 API Key，不以测试配置覆盖正式设置。

补充断言：工具终态摘要不能包含 `content/oldString/newString/originalFile` 原始代码；不同模型反馈轮即使复用 provider ID，也不能覆盖另一真实调用；超过 30 次调用时可以只展示最近 30 条，但总数必须准确。旧自动工具记忆只有可识别格式才投影，格式不明或截断后无法识别时停止召回，原记录保留。

取消信号覆盖单目标流式与接力链路；普通非流式 HTTP 原协议没有 host turn 中止 ID。取消不能撤销已经完成的外部效果。当前视觉验收比较相邻观察，初始状态已满足目标时允许零动作完成；“本轮新增”这类时间性目标尚无独立任务初始图基线，应使用空白画布和测试前后证据单独核验。

## 同一 PR 中先前版本功能的回归范围

这次代码提交同时包含尚未进入主分支的统一会话参数、图片能力路由、Qwen 思考参数兼容和聊天工作台改动。设计用例时还需覆盖：

- 参数保存与回读、空 API Key 不清除旧值；Qwen3.8 effort 与预算互斥；基础对话及图片原生输入/默认视觉中转。
- 顶部 Agent、工程、聊天室下拉切换；运行中的环境切换保护；左侧快捷入口与右侧扩展面板。
- 思考仅在运行时显示，答案完成后收起；工具活动位于状态区；消息搜索、定位与逐轮耗时、模型用量按当前房间展示。
- 保留玉石色控件与竹林背景，确认浅色/深色文字对比度；整体美化新方案仍按用户审阅范围处理。

无需把这些先前版本功能误标为本次 Paint 修复新增，也不应因为绘画质量较低而放宽 Agent 的成功判定。
