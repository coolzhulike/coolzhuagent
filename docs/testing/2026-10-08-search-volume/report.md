# 0.2.97 万条与十万条消息搜索验收

正式安装的 `coolzhu-web-console.exe`（SHA-256 `13cce9a95ff590a139a2fe9890045b94f0399ad88375f758535f27e49d1c0593`）在独立工作区和 64605 端口运行。没有复制凭据、用户聊天或 Devin 绑定，也没有模型生成；资料是明确标注的合成容量数据，不是模型夹具或真实对话结果。

两个聊天室分别包含 10,000 和 100,000 条可见消息，各另有一条应被排除的工具轨迹。同毫秒相邻 ID、稀有英文词、中文短词和混合大小写用于验证计数、稳定排序及索引位置。验证调用正式 HTTP 路由与正式前端，不复制业务搜索实现。

| 检查 | 1万条 | 10万条 |
| --- | --- | --- |
| 稀有词匹配 / 第一条位置 | 10 / #10000 | 100 / #100000 |
| 8次热查询中位 / 最大 | 12.011 / 21.774 ms | 46.879 / 56.697 ms |
| 中文两字符搜索，完整扫描回退 | 36.120 ms，1条 | 147.268 ms，1条 |
| 英文忽略大小写搜索 | 7.254 ms，1条 | 40.425 ms，1条 |
| 中间定位，41条上下文 | #5000，5.194 ms | #50000，17.604 ms |
| offset=5、limit=3 | #5000/#4000/#3000 | #95000/#94000/#93000 |

正式页面实际搜索分别显示“10 条匹配记录”和“100 条匹配记录”。点击十万条库的 `mixedcaseprobe` 唯一结果后，聊天区实际展示 #49999、#50000、#50001，且中间消息正文正确。截图：[万条搜索](10k-search.png)、[十万条搜索](100k-search.png)、[定位结果](100k-located-chat.png)。本轮页面操作位于 Codex 内置浏览器，连接独立容量后台；它证明正式前端搜索交互，不替代 Windows 原生文件选择器、桌面壳或高 DPI 验收。

单独移除**独立容量库**可重建的 FTS 派生表后，通过正式搜索接口冷重建全部 110,000 条可见记录，耗时 **2315.376 ms**。消息行数前后均为 110,002；dirty 队列归零，FTS 索引行数 110,000。重建期间 30 次并发历史读取均返回，最长 **95.284 ms**。见[冷重建数据](cold-rebuild-result.json)。这不代表模型并发写入或硬盘极限容量已经验收。

首轮测量脚本误将响应 `total` 当作全库数，断言失败，但实际接口返回正确，未更改产品。修正为 `message_count` 表示全库、`total` 表示匹配数后保留热查询数据；初次冷计时未保留，不冒充有效数据。上面的冷性能来自随后独立重建实验。

本项关闭 10k/100k 基本搜索容量、分页/排序/定位、索引冷重建与并发读取缺口。重连迟到、跨房间用量、模型写入竞争、持久调度等仍开放。本轮不改产品代码，不新增单元测试；交接脚本、计时和安装进程身份另附。
