# Computer Use 桌面与浏览器测评矩阵

## 测试原则

- 功能通过必须有真实前端输入和动作后可见状态；API 存在、计划生成或 dry-run 不算功能通过。
- 每次动作先声明 `surface=desktop|browser`，使用该表面支持的控制器。
- 每个坐标动作前重新观察；焦点、窗口、布局或元素代际变化后旧坐标立即失效。
- 桌面测试只使用可控测试台和未保存的记事本文档，不保存、不关闭、不操作系统确认框。
- 浏览器测试只使用 `tests/fixtures/computer-use-browser.html`，不向第三方网站提交数据。
- 状态只使用 `PASS`、`FAIL`、`BLOCKED`、`NOT-RUN`。

## 非 PASS 项记录模板

每个 `FAIL`、`BLOCKED` 或 `NOT-RUN` 项必须补充：

- 精确错误或停止原因。
- 最小复现步骤。
- 失败层：客户端连接、窗口枚举、表面路由、目标定位、输入注入、页面/应用反馈、权限或产品编排。
- 已验证事实与仍属推断的部分。
- 推荐的最小下一步修复。
