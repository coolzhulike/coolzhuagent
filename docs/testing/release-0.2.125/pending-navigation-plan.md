# 在途观察与普通新窗口导航的实操方案

本项验证正式安装版在旧输入已经投递并释放、下一观察真正登记之后，网页普通新窗口请求改变浏览器资源版本时，旧观察能否明确停止且不重放输入。它不再依赖测试者在两次UI观察之间抢点关闭按钮。此前两次关闭驱动未命中在途窗口，原失败仍保留。

## 架构对应

`native_browser_host`每个观察请求在现有运行轨迹登记request_id；冻结绑定区分可合法导航的同一面板与只属于原资源完整版本的单次观察。`browser_panel::handle_new_window`复用原生面板处理普通新窗口目标，自然跳转使用独立popup序号。先前方案推测“总是递增导航版本”经实测和源码复核否定，详见下方结果。正在等待的旧请求、已到达但资源归属变化的旧回复、只读CDP结束后的文档归属分别有独立检查。原5秒外层观察期限、2秒CDP读取期限及输入释放确认均不修改。

## 验证方法

使用普通双来源网页，不模拟模型响应或工具回执。真实SWE-2只执行一次click。页面自身在可信click后发起HTTP请求，测试网页服务只读本轮SQLite事实，等待该click的sent/released及下一browser.observation_requested；响应返回后页面用普通window.open请求另一个来源的结果页。浏览器宿主按正常生产流程处理该请求，不调用私有IPC、不注入产品暂停、不放宽期限。

服务器日志关联本轮run、请求标识、输入完成、观察登记、普通新窗口请求、结果页GET和可信页面输入事件。终态必须保存原sent/released事实；结果页不能接收旧动作，模型不得重试/补发或另建云端会话。原唯一SWE-2-medium/island-kayak、revision57和已有聊天室完全访问授权保持。

## 判定与风险

- 必须命中同一请求的停止事件，普通新窗口请求时间位于观察登记与停止之间，停止早于原5秒期限；严格区分waiting_resource_changed、reply_resource_changed和host_reply。只确认本轮实际命中的分支。
- 零输入重放、原输入释放保留、效果未知不追认为成功，单ACP终态排空并解锁；保存正常原生初态及终态截图。
- 浏览器若因普通用户激活已到期而阻止新窗口，或导航晚于观察终态，记录未命中，不能把普通点击通过计为严格项通过，也不绕过浏览器限制。
- 本项不能证明HRESULT同时失败的窄竞争、实际新原生Target或跨来源commit恰好发生在down/up之间，也不能外推整个32工作包矩阵完成。
