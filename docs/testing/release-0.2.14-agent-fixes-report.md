# 0.2.14 Agent 修复、改动范围与验证报告

日期：2026-09-19。目标平台：Windows x64。配套用例设计输入：[Agent 回归测试契约](agent-runtime-regression-0.2.14.md)。

## 问题归属

先前 Paint 实测没有发生输入动作，内部规划返回 `action: "click"` 后无法解析。根因包含 Agent 未提供完整动作对象契约、复用普通聊天提示导致职责冲突，以及桌面通道没有画布路径拖拽、未向规划器提供原始截图。仅根据 UIA 文本验收也无法证明已经画图。这些属于 Agent 的执行与反馈缺陷，不能归因于模型绘画能力。

本次修复上述接口和反馈链路，同时处理同批实测暴露的工具参数混入思考、跨轮上下文包含原始审计、工具状态重复计数、嵌套调用用量遗漏及虚拟步骤记录。验收不以海绵宝宝绘画质量为门槛；模型有可用接口后仍画得粗糙，会单独记录为模型表现。

## 关键行为契约

工具参数分片只拼接成调用参数，不再追加到思考文本。当前轮的原生 Thinking/ToolUse/ToolResult 协议仍按要求配对；跨用户轮时，内部思考和原始工具审计先过滤再进入预算计算，仅保留必要的执行事实、文件引用及最终答复。旧历史存储保留，不做破坏性清理。

定向测试还发现自动记忆会把思考转为 decision，再召回下一轮。新自动提取与压缩也使用同一投影；新压缩记录标记为 `context:auto-compact:v2`。旧的自动 reasoning decision、没有原始类型可追溯的旧自动压缩记录仍保留存储，但不再自动注入；可识别的旧工具记忆改为有界事实后再召回，格式不明或截断后无法识别的记录停止召回。手工记忆以及正常聊天/经验来源保持原有行为。

工具状态由独立事件表达，首次流式请求和后续反馈请求共用调用标识。requested、running 与终态更新同一条状态；持久化摘要和结果不额外增加调用次数。预览未执行、取消、失败或终态缺失不能显示为成功。

内部规划请求不复用普通聊天的“无工具只回复文本”提示。请求明确传入目标、约束、可用能力和对应 surface 的严格动作结构，观察按完整节点裁剪。动作仍要通过引用、generation、窗口身份及参数边界校验，不靠放松解析器接受任意内容来修复模型输出。

桌面原图单独进入多模态协议；文本规划模型先收到默认视觉模型的有来源转述。视觉验收检查最新图像、实际变化及逐项目标证据，不能把 UIA 中出现目标文字当作绘画完成。有房间且已返回非零用量的内部规划、视觉描述、视觉验收调用均独立记账，关联房间、provider trace 与工具调用。这里的 trace 不等同于公开 chat-turn ID，普通聊天旧用量暂无调用关联；缺少或全零用量不猜测补齐。

拖拽路径限定为当前观察目标的 2–256 个 0–1 相对点，单次最多 5 秒。正式执行绑定窗口与 DPI，检查边界，取消或输入失败时执行释放流程。动作记录对应真实输入前后；截图文件路径、观察代际变化不算任务进展。

首次修复后真实 Paint 回归还发现 150% 缩放下的坐标口径缺陷：DPI-unaware 宿主读取窗口宽 1707，而原生 helper 与 UIA 元素读取物理宽 2560；HWND、PID 均相同。严格校验因此在观察阶段阻断，0 动作。修复统一同步观察的 DPI 上下文并在退出时恢复，不放松真实窗口移动或身份变化的检查。

后续回归中，模型漏填必填参数后尝试补正，被原有的一次调用限额阻断。现在参数校验失败且未开始执行的请求有独立、有限的纠错额度；实际观察/规划/输入仍受原执行限额约束。`window-canvas` 备用目标的坐标范围也明确为整个可见窗口客户区（可能包含工具栏），实际绘图区必须根据截图定位，不能把窗口客户区误称为白色画布。

最后的原生点击模拟测试定位到旧通道的实际 no-op：PowerShell 修改嵌套值类型字段后没有写回，传给 SendInput 的按下/抬起 flags 都为 0，即使 API 返回 1 也不代表发生点击。现已完整写回 MOUSEINPUT，校验 SetCursorPos/SendInput 返回值，并在失败时保留释放流程。成功拖拽后如果仅后续截图失败，则保留已输入事实，不能因为缺图把实际输入说成零动作；缺图仍不得通过视觉验收。

## 同一 PR 中的累计功能

- 统一会话参数页：连接协议、Base URL、Endpoint、密钥、模型 ID/用途、上下文与输出预算、思考模式/层级/预算、采样和工具策略。前端不再要求维护 Provider 配置表，后台保留旧会话兼容字段。保存参数为整组替换，自动化调用先读取再合并。
- 图片能力支持继承、原图直传、纯文本转述三态。原图按实际协议发送；纯文本目标由已配置的默认视觉会话先处理附件。此开关目前覆盖图片，不等同于新增音频/视频上传全链路。
- Qwen3.8 原生思考字段和工具选择兼容；本机已有 Qwen 会话使用 `qwen3.8-flash`，保留百炼 Base URL 与原密钥。用户配置不写入代码仓库。
- 工具请求与执行两端统一检查会话、工程和房间能力；小上下文仍可提供文件工具；伪工具文本不作为真实执行；Computer Use 失败后保留原任务的受限恢复路径。
- 左侧快捷入口与右侧扩展面板，顶部环境下拉；临时思考、独立工具活动区、消息搜索/定位、逐轮耗时、模型用量；玉石色控件与竹林背景。
- debug 缺省开发完全访问；release 缺省关闭，用户显式配置优先。Computer Use 仍要求相应房间授权，调试开关不篡改持久化房间权限。

## 验证结果与发布

### 真实模型阶段性结果

- 文件长任务两轮均结束并生成实际产物：第一轮 51.200 秒，写入后读取，共 2 次工具调用；第二轮 22.188 秒，读取、两处编辑、再读取，共 4 次工具调用。产物为 5568 字节独立 HTML，包含 6 个 SVG 动画元素；无浏览器脚本异常，两帧截图不同，背景与标题修改均保留。7 次模型请求累计输入 48629、输出 4021 token。详见 [公开摘要](release-0.2.14/qwen-file-regression.json)。
- Paint R1：坐标口径失配在观察阶段阻断，0 动作；定位并修复 DPI 问题。详见 [修复前审计](release-0.2.14/paint-dpi-before-fix.json)。
- Paint R2：模型漏填 `success_criteria`；纠正请求被旧限额拒绝，0 动作。参数纠错边界已修复并覆盖定向测试。
- Paint R3：70.001 秒，记录 2 次 UIA 点击尝试，3 次规划与 3 次视觉验收；窗口原图正常到达模型。后续模拟测试证实此时旧点击通道 flags 为 0，不能把这两次记录当作已发生物理点击，也不能直接归因于模型重复点击策略。无笔画时控制器返回 `no_progress`，没有误判任务成功。8 次模型响应累计输入 154222、输出 1998 token。详见 [R3 审计](release-0.2.14/paint-r3.json)。
- Paint R4：107.432 秒，实际 2 次正式 `drag`（7 点/800ms、5 点/2000ms），原生输入已执行并释放，前后窗口截图正常；模型选择从工具栏附近起笔，未形成目标图形，最终 `no_progress`。8 次模型响应累计输入 124276、输出 5247 token。外层模型答复错误地称有第 3 次拖拽，数据库实际仅有 2 步；测试判定以步骤和截图为准。详见 [R4 审计](release-0.2.14/paint-r4.json)。
- Paint R5：坐标说明澄清后，专项路径测试耗时 109.325 秒，实际 2 次拖拽（17 点/800ms、9 点/1500ms）；之后规划请求触及 20 秒上限。原图人工核验仍为空白绘图区，变化主要是工具选中状态，外层模型“新增线条”结论没有证据。此专项提示沿用“画笔已选中”假设，而上一测试已改变工具选择，因此不作为独立绘画成功验收。7 次已记录响应累计输入 92471、输出 4108 token；超时请求未返回 usage，不推断其成本。详见 [R5 审计](release-0.2.14/paint-r5.json)。
- Paint R6：恢复一般绘画请求、不假设当前画笔状态，耗时 85.999 秒。3 次动作尝试中，1 次真实点击选中了矩形工具（原图可见），另外 1 次点击和 1 次拖拽因观察过期而被拒绝；最终未绘制。6 次响应累计输入 86505、输出 2734 token。此次还触发模型无最终文字时的 Agent 兜底文案，“完成本轮任务”与工具失败相冲突，已纳入修复。详见 [R6 审计](release-0.2.14/paint-r6.json)。

这些事实证明执行接口和视觉反馈已贯通，但不能把绘画任务记为成功。模型动作选择、空间定位与外层总结准确性仍有不足；本轮不为绘画质量增加专用脚本或放宽成功标准。20 秒单次规划上限、120 秒任务预算及过期观察检查仍然生效；未证明海绵宝宝端到端目标通过，不能把这一结果藏在“核心测试全通过”的统计里。
