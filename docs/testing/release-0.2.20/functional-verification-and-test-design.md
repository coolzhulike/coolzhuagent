## 本包相对 0.2.19 的主要修复

0.2.19 的语言服务启动只读取临时会话授权，遗漏聊天室已有的完全访问授权，因此用户在聊天室完成授权后仍收到 `403 danger-outside`。修复后，前端启动语言服务提交当前 Agent、聊天室、预期工程；后端校验三者归属，先使用已有聊天室授权，再按原策略尝试会话临时授权。rustup 与 rust-analyzer 均经过既有执行权限检查，不以客户端布尔值代替授权，不修改全局权限。

语言服务实例记录启动归属；复用运行实例之前再次检查权限和上下文。房间/工程/Agent 切换与权限撤销使旧实例失效，旧诊断、导航及关闭请求不能影响后来启动的新实例。前端捕获请求上下文，晚响应不得把旧房间结果写到新界面。实现分布于 `lsp_host.rs`、`app.js` 与主服务生命周期接线，沿用独立 language-service crate。

## 实操用例设计矩阵

| 场景 | 前置与动作 | 必须观察的结果 | 现有证据与未覆盖边界 |
| --- | --- | --- | --- |
| 默认权限拒绝 | 隔离工程/房间，未授权时启动语言服务 | 明确拒绝；不能静默启动或提升全局权限 | 隔离 HTTP 已拒绝，原生需同包截图 |
| 房间授权正常启动 | 使用正常 UI 已授权测试房，打开 Rust 文件并启动 | 显示运行；诊断可见；定义/引用跳转到正确文件/行；停止后显示已停 | HTTP 启动/复用/诊断/导航已成功；原生验收进行中 |
| 客户端伪造与错误身份 | 假 confirmed、缺 room/工程、错 room/工程 | 拒绝且不产生新进程；不因旧句柄绕过校验 | HTTP 已覆盖；不要求以 UI 制造不可能字段 |
| 撤销授权 | 启动后撤销当前房间授权，再导航/重启 | 旧实例失效；无授权重启被拒绝 | HTTP 已覆盖，原生可见状态待验 |
| 会话临时授权兼容 | 无房间授权但有原机制临时授权，启动后再撤销 | 原兼容路径可启动；撤销后不能继续使用 | 隔离 HTTP 已覆盖，不代表全局权限放宽 |
| A/B 切换隔离 | A 启动；切 B 并合法启动；交付 A 的旧请求 | A 不污染 B；旧 close 不能停止 B；B 仍可正常使用 | HTTP 已覆盖，原生当前房间显示待验 |
| 启动中的上下文竞争 | 语言服务启动尚未完成时 A→B→A | 返回的句柄仍属有效当前代次，否则丢弃 | 代码有代次防护，未做该 ABA 动态现场，不能算已通过 |
| 升级后原数据 | 正式入口启动，观察原工程/旧会话，退出后做语义核对 | 数据仍可用；正常使用造成的预期新增与意外变化分开解释 | 安装前后静止核对通过；首启运行后对账另记 |

实操必须保留包身份、窗口截图、动作顺序和结果；仅直接接口返回 200 或源码静态断言不满足原生交互通过标准。故意错误字段的 HTTP 负例用于后端边界证明，与点击验收互补。测试只操作命名的临时工程与测试房间；原用户数据不进入公开夹具或 PR。
