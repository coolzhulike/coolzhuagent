# 0.2.23 顶部权限与卷框视觉验收（2026-09-28）

## 范围与来源

针对安装版反馈的三个问题：底部常驻诊断遮住金框、顶部中央玉石被压扁且品牌金饰被裁、聊天室权限选择不可见。源码将原 `global-system-bar` 节点移入“运行轨迹 / 安全详情”，主工作台去掉底栏轨道；原 `chat-permission-select` / 保存按钮只保留一套，移到“当前聊天室”旁的顶部弹层；卷框两侧柱沿用原图，中间玉石以同图等比取样，金线独立延展，品牌图完整适配容器宽度。权限后端规则、人工放行和 CU 运行入口未删除。权限 PATCH 的工程绑定及迟到响应守卫由同轮独立验证记录覆盖。

下列截图均来自**重新编译的真实 Web 二进制**，未设置 `COOLZHU_WEB_STATIC_ROOT`，没有代替安装版原生窗口验收。所有 Web 实例复制二进制到 `tmp/` 独立目录运行，使用随机本机端口并禁用桌面壳；`USERPROFILE`、`HOME`、`APPDATA`、`LOCALAPPDATA`、`CLAW_CONFIG_HOME`、`COOLZHU_RUNTIME_DIR`、`COOLZHU_LOG_DIR`、`TMP`、`TEMP`、`TMPDIR` 及 XDG 目录均指向该独立目录。无真实云模型请求。

## 隔离权限交互

在 `D387` 的临时 `main-room` 中，弹层唯一选择器初始为 `workspace-write`。选择完全访问并取消首个风险确认后，选择器回退到目录权限，权限 GET 仍为 `workspace-write`。再次选择完全访问并完成两次确认后，GET 变为 `full-access`；页面重载后选择器仍选完全访问。再选目录权限并保存后，GET 回到 `workspace-write`；再次重载后选择器仍选目录权限。测试配置的 `dev_open_permissions=true` 保持有效完全访问，因此最终选择器与顶部有效权限摘要不同是正确的覆盖呈现，并非权限保存失败。按 Escape 可关闭弹层。

此处仅验证隔离临时工程内的前端交互与真实权限 API；跨工程迟到 PATCH/409 零写和其它安全回放见同轮后端权限验证记录。未对真实用户工程或云模型执行权限操作。

## 启动失败记录与清理

首个测试启动脚本将 `coolzhu.toml` 写在实例根目录，却把 `COOLZHU_RUNTIME_DIR` 指向子目录，程序因此按默认 8765 启动；访问预期随机端口得到 `ERR_CONNECTION_REFUSED`。这属于测试配置错误，不是产品缺陷。仅停止该次脚本记录的 Web PID，未访问或替换用户的原生桌面服务。脚本修正后，配置与运行工作区同目录，日志确认随机端口才接入浏览器。

本轮记录的所有自有 Web PID `32068`、`9508`、`25916`、`8680` 最终均为 `STOPPED`；Playwright 会话 `ui023`、`ui023v2`、`ui023final` 均已关闭。最后一个 D763 实例只读取页面快照后即退出；未再启动源码预览。
