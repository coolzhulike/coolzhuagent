## Paint初轮实际失败点

首轮真实Qwen实际完成一次drag，path_completed=true、confirmed_point_count=5、released；后续规划等待36634ms超时，CU blocked。文件中临时改300秒但未重载内存配置，该轮真实CU期限仍120000ms，不能写成已运行300秒；原配置字节已经恢复。此失败说明本次测试准备需要重载，不能据此认定扩大预算无效。独立第二轮通过正式workspace/reload载入300秒，结束必须恢复原文件并再次重载。

另一实际问题是模型首轮选择window-canvas，该目标契约明确只代表包含工具栏的client区域。真实原始前后截图没有形成新身体，光标落在颜色区，后验criteria_met=0/6；接口并未缺少drag能力，也未再触发普通绘画审批。第二轮明确要求从新鲜UIA找到实际绘画画布reference，相对该rect绘制，仍由真实Qwen自主规划，不提供旧坐标或代画。Sky窗口截图有旧内容与原生帧不一致，保留两套原图，不用其旧帧认新成果；最终正常最大化刷新窗口后独立实拍，与原生帧联合核对，不操作或修改画布内容。

第二轮实际CU预算300000ms、根期限900000ms，三笔全部在真实画布目标uia-c049f188516a304d投递，每笔五点完整、未partial、released。模型逐笔规划/验图耗时长，第三笔之后剩余22639ms的验图请求超时，停止且不接纳迟到响应。整轮含父模型汇报334.598秒，不把它写成CU持续334秒。新增图形是三个矩形，眼睛位置与身体不匹配且与旧线重叠，没有新增笑嘴与两条腿，完整海绵宝宝失败。这里不是缺失执行接口：真实鼠标路径已执行；最终图形规划质量与共享预算是失败点。未换模型、未降低思考等级、未擦除或代画。后续若延长任务，需同时审查CU目前300秒上限、根预算及取消边界，不能静默解除时限。
