## 1. 源码里新证实的问题

1. **`canvas_rect` 名不副实**（`desktop_bridge.rs:104-107`）。它就是窗口客户区（client_rect）与截图范围的交集，包含工具栏，并不是白画布。
   - 提示词（`planner.rs:37-38`）要求模型先在截图里找画布，再换算成相对 canvas_rect 的坐标。截图原点是 screen_rect，两者在 y 方向差约 45 像素，宽高比例也不同，模型要做两次换算。
   - 模型给的 [0.62,0.16] 换算后 y≈106+0.16×1096≈281，对应截图 y≈220（共 1152 高），和报告说的“落在工具栏附近”一致。
   - 结论：这是 **Agent 接地设计缺陷**，人为抬高了定位难度，不能全部归为模型能力。
2. **验收用的“前图”是上一步，不是本轮起点**（`controller.rs:855-858`、`planner.rs:839-841`）。多步任务里，“本轮新增”只和上一步对比，不和本轮初始画面对比。
3. **“本轮新增”只靠关键词识别**（`planner.rs:1566-1574`）。必须同时出现“本轮”和“新增/新绘制/新建/新创建”才生效，“画一条新横线”这类说法识别不到，会回到初始单帧验收的老路。
4. **窗口枚举几乎不过滤**（`windows_impl.rs:352-365`）。只看 IsWindowVisible，没有排除 DWM cloaked 窗口、有 owner 的窗口、ToolWindow 和零尺寸窗口；`unique_window` 报歧义时也不列出候选（`window_target.rs:74-80`）。这很可能是 mspaint.exe 报 `target_ambiguous` 的原因，但**还需要运行时证实**。
5. **stale 恢复每轮只能用一次**（`controller.rs:482、758、774`）。执行计划要求改由重规划预算控制，代码仍是单个布尔值。目前没有实操证据显示它造成过失败。
6. **Browser 取消边界设计正确**。预检阶段可以取消（`adapter.rs:83-84`）；执行阶段传入 None，不响应取消，最多等 8 秒回执（`adapter.rs:107-109`，`native_browser_input.rs:107`）。所以按下后点停止不会丢掉释放回执。外壳一侧是否能被关闭/替换打断，**未读**。

## A. Browser 取消/关闭竞争的真实验收（最优先）

- **方法**：在本地页面的 mousedown/keydown 处理函数里放一段约 1.5 秒的同步忙循环。这是真实页面自身的行为，不改生产代码、不伪造回执；页面服务记录 down/up 时间戳。在这个窗口内由人工通过真实界面分三轮分别做：停止、关闭右栏、替换页面。
  - 这种慢页面是否超出你说的“不能用夹具伪造命中”，需要你确认。
- **通过标准**：
  - 宿主停止时间 t1 必须满足 down < t1 < up；
  - 回执是 Released 或 ReleaseUnknown，不能是“未发送”；
  - CU 进入 cancelled，没有后续步骤；
  - 下一轮可以正常执行，隔离状态没有被改写。
  - 如果外壳在同一个 UI 闭包里顺序处理 down/up，关闭动作不可能插进去，那么“t1 晚于 up 且回执为 Released”的串行证明也算通过，但要单独标为“结构上不可插入”。
- **停止条件**：每个场景 3 次都没命中窗口，就记为未覆盖并停止，不注入生产延迟。

## B. Paint 白画布与坐标

1. **改名**：`canvas_rect` 改叫 `client_rect`，旧字段保留一版作兼容；`drag_contract` 的文案（`desktop_bridge.rs:118-127`）同步改。风险很低。
2. **新增可选的 `draw_region`**：格式为 `{rect, source:"uia"|"pixel", confidence}`，识别不到就返回 null，普通观察流程不变。
   - UIA 来源可以复用已有的 `canvas_element`（`desktop_bridge.rs:896-907`）。先只读导出一次 Paint 的 UIA 元素，确认它是否真能暴露画布。
   - pixel 来源是在客户区里找最大的近白矩形，只能作为候选，不承诺语义。
3. **换坐标系**：拖拽点改为相对截图本身归一化，由宿主按 screen_rect 换算到屏幕，省掉一次换算。
   - 只有 source=uia 时，点落在 `draw_region` 外才做输入前拒绝（明确未发送），让模型重新规划。
4. **落点反馈**：类似表单的 keys 反馈，把上一笔实际落在截图上的像素位置回传给下一步规划，方便模型自我纠正。
- **三类区分**：
  - 已证实的 Agent 缺陷：上面第 1 节的第 1、2 点；
  - 可改善的设计：B 里的第 2-4 条；
  - 模型能力：LEGS-04/05 映射正确但落点在身体内，仍属模型问题。
- **通过标准**：真实 SWE-2、已有旧笔迹的画布、新独立任务，1 次 drag 落在白画布内，前后图对比可见新线，目标判定通过。
- **停止条件**：两次独立任务在映射正确的情况下都失败，就归为模型能力，不再改输入映射。

## C. 防止把旧成果当新增

- **窄的结构化字段**：给 `computer_use_perform` 加一个可选的 `requires_new_effect: bool`，由外层模型声明，和现有关键词判断取或（OR）。字段是通用的，不绑定 Paint。
- **真为 true 时**：
  - 零动作不能判完成；
  - 验收改用“本轮起点画面 + 最新画面”对比，需要在 controller 里保留初始观察；
  - 代价是多一张图片带来的费用和时延。
- **外层宣称“有新笔迹”**：不去解析外层回复的文字，由前端在回复旁边按台账直接显示宿主的 goal 结论，工具结果把每项 criteria 的证据完整回传给模型。
