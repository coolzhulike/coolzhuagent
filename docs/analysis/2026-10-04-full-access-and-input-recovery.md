# 完全访问与输入故障恢复的分层调整

## 用户新要求与实际来源

用户询问人工复核是否由Windows强制要求，并要求“完全访问”包含既有授权。代码核查确认：普通CU批准映射在 `computer_use_executor.rs::RoomFullAccessApprovalPolicy`，敏感语义门禁在computer-use-core控制器；事故隔离、原生恢复确认与开放评估在 `native_recovery`、`native_recovery_store`、`input_safety_opening`。这些属于产品策略，不是WindowsUAC要求。Windows管理员提权独立存在。

当前完全访问已批准普通可逆/有状态操作；敏感语义和历史输入结果未知仍走不同的人工路径。此次Paint的“本轮”授权声明误判已窄修；此修复不代表自动恢复方案已实现。0.2.65本轮候选继续保留既有原生人工恢复契约。

## 目标行为

- 完全访问下正常绘画、点击、输入、滚动不重复询问普通工具权限。不得把“已授权本轮”这类声明当作正在操作授权按钮。
- 鼠标释放/投递不明是执行故障，首先自动停止本轮、阻止重复输入和执行可核验的恢复；仅无法恢复时显示人工处理入口。正常权限审批和异常恢复不得共用含混的“待人工复核”提示。
- 授权和释放证据分开：完全访问是用户许可，不是OS按键状态证明；保留历史投递未知、历史目标未验，不把恢复输入通道写成历史动作成功。
- WindowsUAC或系统账户认证保留其系统流程，不伪装成普通工具批准。

## 架构边界与实施顺序

1. **权限层**：从父轮接纳时冻结的聊天室权限派生普通操作授权，不依赖模型声称自己已获得许可。先审计真实目标/参数的判定，避免页面文字或否定约束引发误判。目录权限继续受目录范围约束。
2. **恢复协调层**：集中在共享物理输入资源协调器，不由前端按钮或某个房间直接清库。停止/退出核验必须绑定PID与创建身份；仍活着、身份不明、跨进程锁冲突或实际输入租约未释放时不得宣布恢复。
3. **独立收尾层**：确定原执行者不能再次投递之后，独立收尾执行器核验必要鼠标/键盘释放、退出与屏障状态，产出真实证据及超时结果。先解决常驻WebView2输入执行者和控制台同进程的退出依赖，避免为了恢复浏览器必须反复重启整个控制台。需要评估独立输入进程的WebView2/UI线程接口约束，不能仅换PID登记来规避旧执行者核验。
4. **存储层**：为“机器恢复成功”设计独立决定来源和事务，不能伪造用户签名、复用原生确认proof或将人工记录改成自动记录。任何自动开放必须同时满足旧执行者退出、收尾确认、版本/epoch一致、无在途输入；历史效果继续未知，当前通道可恢复是另一个事实。完全访问的持续授权范围必须明确绑定父轮/房间及物理资源，不接受模型传参声明。
5. **UI层**：恢复进行中显示简短状态；自动成功后撤掉提醒；仅机器证据不足时显示醒目的“输入恢复需要处理”，附具体失败原因和唯一处理入口，不显示调试字段。

## 验收边界

用真实qwen3.8-flash在正式软件覆盖Browser/Paint：正常动作无额外审批；取消/超时后鼠标确实释放；自动恢复后只有新独立任务可继续，原失败轮不自动重放；退出未确认/收尾超时/资源冲突继续阻止输入，提示准确；多个聊天室权限与共享输入资源不能互相冒用。必须同时保留软件实拍、原生回执、机器恢复决定和历史未知记录。

此文是按本轮新增要求落地的方案与验收依据，**尚未实现自动故障恢复**。先验收已构建候选的两处窄修，再实施协调/收尾/存储的改动，不能用“完全访问”布尔值直接跳过恢复事务。
