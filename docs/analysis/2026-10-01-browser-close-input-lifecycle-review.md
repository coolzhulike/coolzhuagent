# 原生浏览器关闭与输入清理的衔接方案

2026-10-01，052 正式安装版、原 Qwen 真实实操 BP 暴露。主会话独立审查；Pro 审核仍按用户要求暂停。

## 实际失败与判断范围

关闭按钮操作时间 1790836278190。前两次点击均已 sent/released 且观察到页面改变；第三步从 1790836276317 开始，在关闭后返回 native_input_outcome_unknown、may_have_been_sent/unknown，最终停止且没有后续步骤。不能宣称第三次未派发，也不能凭关闭了窗口推导鼠标已释放。源步骤日志没有记录传输的 delivered 位，尚不能判定失败必定发生于宿主领取前还是 WebView 销毁期间。

代码审查确认两条路径均有缺口：后台尚未被宿主领取的输入请求遇到认证资源撤销时仅不再交付，最终超时；桌面立即销毁视图，可能截断已经入队的按下/释放确认。原隔离和禁止自动重放行为正确，保留。

## 最小修改与职责

1. 后台输入传输在原互斥锁内确认请求尚未 delivered，且同一认证宿主登记的资源已变更时，取走这一确切请求，返回 NotDispatched。沿用原请求的票据、执行实例、尝试和资源绑定，不伪造 Released。已经 delivered 的请求继续等待原宿主回执，绝不按资源消失结算为未输入；其它宿主的登记不能撤销它。
2. 桌面输入模块提供已有执行任务的互斥生命周期。关闭先撤销资源资格并隐藏视图，再等待当前执行任务的有界清理完成后销毁原 WebView 实例。预检/后续派发看到资源已撤销必须拒绝；按下后的释放仍使用原 controller，不被取消或关闭截断。关闭等待不能占住主 UI 线程或面板导航锁。

不修改安全库、不扩大许可、不延长输入票据、不自动重试，不把新网页实例用于清理旧输入。真正回执未知仍隔离；退出整个进程的崩溃路径仍遵循既有独立恢复屏障，不声称本修正覆盖系统崩溃。

## 验证范围

只补一项传输竞态回归：资源撤销前未领取可以证明零输入；已领取不得被改写，原动作仍可结算；其它宿主不能撤销。分别离线 build Web 与 Shell，工程测试在无真实输入任务时运行。随后正常打包安装，用同一 Qwen 重做执行期间关闭，保存关闭时点、软件截图和实际动作账本；释放未知不能作为通过结果。错误源 URL 和 Paint 依次继续。

冻结代码的验证已完成：Web 离线 build 50.60 秒、Shell 离线 build 47.44 秒均退出 0；完整 Web 1294 通过/0 失败/2 既有忽略，lib 8 和宿主接线 1 通过；完整 Shell 64 通过/0 失败。工程结果不替代下一包正式安装的真实 Qwen 关闭复验。
