# 发送目标与设置编辑对象一致性审查

日期：2026-09-27。GPT-6 Pro 审查会话“整合审查执行计划”，轮次 `d6493233-e80a-4897-91cc-cad413efba01`。

## 实际问题

安装版顶栏读取已勾选的发送对象，设置页读取 `activeSessionId`，两者可能显示不同模型。当前证据仅证明显示对象不一致，**没有证明用户选择 GLM 却实际发送给 Qwen**；Pro 回复中的这一推断不采纳。Qwen 实操在发送前已核对其为唯一发送对象。

## 最小修复边界

- 保留多目标发送。发送名单、当前编辑配置和已接受运行的实际目标分别沿用已有状态，不新增状态框架。
- 顶栏及发送前提示必须反映同一份发送目标集合；多选不能只显示第一个模型冒充唯一目标。
- 设置页清楚标识当前编辑的配置。查看或保存配置不能静默改变发送名单。
- 用户在顶栏明确切换成单目标时，可同步打开该目标的编辑配置；配置页浏览不做反向自动改写。此单向规则避免 Pro“单目标双向同步”建议与“编辑不改变发送”要求的冲突。
- 运行接受后按实际目标记录，期间更换编辑对象不能改变已接受运行；配置保存依照现有配置发布规则处理。
- 不凭旧缓存恢复已删除、不可选或禁用的目标；错误应在发送前可见。

## 验证出口

单目标切换：顶栏、发送请求及实际响应身份一致。多目标选择：准确显示集合，设置查看不修改名单。编辑配置：标题准确且无隐式发送对象变化。正在执行时切换编辑对象：本轮目标不漂移。使用实际界面与运行记录联合验收，不只验证某个字段值。

当前为经主会话校正的待实施方案，不是功能已通过证明。

## 源码实施进展

Sol Max 已修改顶栏高亮与发送名单的一致性、显式单目标选择时同步干净的配置编辑器、设置页编辑对象提示；发送前固定本轮目标，避免附件上传等待期间读取到后来变更的名单。多目标名单不因浏览配置而改变。

主会话复核后补充两处边界：仅不存在历史记录时允许首次默认；损坏、非数组或已失效的旧名单要求重选，不能回退到其他默认模型；前端可发送条件同时检查 `selectable` 和 `enabled`。设置区使用“当前管理的会话”等面向用户的文案，避免把内部生命周期术语写进界面。

首轮改动的语法检查和 Web 离线构建通过；后续边界小修已通过语法检查，待本轮合并编译和新构建原生界面验收。仍不能把旧安装包截图记为这些修复的证据。
