# coolzhuagent 整合改进执行计划

版本：2026-09-21 审查定稿 v1.1（追加用户侧栏与过程显示要求）。状态：**方案与验收设计完成，产品实施尚未启动**。

本计划采纳聊天页面 GPT6 Pro（界面显示“6 Pro”）的路线 A：保留 Rust、Tauri、SQLite 和当前产品，从真实 Web 路径提取共享运行服务，按收益吸收 DSH 的机制与组件。先解决工具执行事实、权限、取消与状态一致性，再优化 Computer Use，再扩展产品能力。当前不整体迁移到 DSH，也不默认启用双 Agent 主循环。

**给接手模型的阅读顺序**：先读本文件的定稿口径和契约，再选工作包及前置 PR，最后读取 06 对应案例与证据包。所有“拟新增”接口、门槛、人日与实验预算均为计划；不能据此声称代码已实现、测试已通过或花费已获本轮授权。

### 1.1 对 Pro 返回方案的明确收紧

下列条款是主代理整理时的定稿修改，优先于所附 Pro 原文和早期候选文档；没有重新提交 Pro 复审。工作包编号、依赖与人日仍沿用 Pro；具体接口实施前须在 S1.1 契约 PR 冻结。

1. **发送状态三值化但不丢部分输入事实**：`input_delivery = not_sent | may_have_been_sent | sent`；`partial` 和 `path_completed` 为独立布尔或 null，释放另记。Pro 的 `partial/unknown` 不作为第四、第五种发送状态，也不能把已确认部分输入降为“是否发送未知”。
2. **窗口外部效果与输入释放分别记录**：释放未知阻止新输入；取消终态不可逆，但迟到的真实输入回执、截图和 usage 仍可追加，不能重启 run 或自动改为任务成功。
3. **租约覆盖真实 executor**：父进程死亡不证明仍活着的 helper 已停止；只在确认旧执行者失去输入能力且释放状态已对账后允许新 owner。TTL 不能强抢活跃执行者。产品 broker 仅约束自身正式通道，不宣称能阻止人手和任意外部程序。
4. **超时覆盖进行中路径**：到期在下一个可取消安全点停发路径点；有界收尾只释放和记录。不能一边显示已取消、一边让整条长笔画继续。
5. **UIA 回退需要排除迟到执行**：除了确认当前无效果，还须确认旧语义操作已结束或不能再产生效果；仅凭超时后的空白截图不得追加物理点击。
6. **数据库物理集中不等于逻辑唯一权威**：先旧业务表权威＋同事务 outbox；按对象列明写者和字段来源。只有停写、无活动 run、基线一致的会话才可选择切到“基线＋事件”；其他领域无需强制全事件化。
7. **实验建议不等于承诺或本轮执行授权**：30 次确认样本、27/30 与 24/30、token 上限、P95、误拒率均待预注册和设备校准。十对探索不能证明稳定成功率；两组都须使用已经通过的可靠性底座。
8. **静态问题绑定源码身份**：S0 补齐审计快照、构建提交、MSI 与实验轮次的对应。Pro AR-01 指出的 19/20 工具数和 CLI 唯一入口残留，已在上传后的第二轮本地纠错中修正。

### 1.2 Paint 的当前结论

已存在真实输入接口：R3 的无效点击 flags 已修；R4/R5 有真实拖拽，R6 有一次真实点击。当前不能归因于“Agent 没有执行接口”，也不能断言仅是模型能力不足。Agent 侧仍有确认的计数、反馈/状态表达缺口，以及部分输入、并发所有权和恢复等必须故障注入的风险。

优先补事实和诊断，再用干净 Paint 初态验证短线/矩形。通过后再做复杂目标实验，区分宿主映射误差、模型选点、工具前置状态、规划、验收和预算。R6 选矩形工具可能是准备动作，不能据此判错；两次 stale 原因未知，不补写为“TTL 超时”。

## 2. 拟议公共契约与实施边界

### 2.1 运行身份、幂等和控制终态

统一身份至少包含 `workspace_id / room_id / session_id / public_turn_id / run_id / step_id / request_attempt_id / tool_call_id / action_id / owner_epoch`。供应商返回的 request/trace ID 仅做关联；一轮聊天中的 planner、verifier、视觉转述和重试分别登记 request attempt。

| 身份层 | 规则 |
|---|---|
| 网络重复提交 | `client_message_id + scope + content_digest`：同 ID 同内容返回同收据，不再次执行；同 ID 不同内容拒绝 |
| 动作重传 | 同 action_id 不重新注入输入；未知输入结果先观察/对账，不自动重放 |
| 未执行参数纠错 | 新的纠错 attempt，仍归同 run 的独立纠错预算；不计为真实输入 |
| 显式恢复/新尝试 | 新 recovery/attempt 身份，保留父关联、旧效果事实及剩余预算；不能命中旧失败缓存而永远无法恢复，也不能靠换 ID 重置预算 |

终态 first-wins 仅指控制状态。取消、超时后到达的事实追加到原 run，标明迟到、来源和接收时间；UI 不复活运行，统计不丢已发生的输入和计费用量。恢复启动新的受控尝试，不能改写旧终态来隐藏失败。

### 2.2 动作回执四维与恢复表

下表是统一的拟议 v1 字段口径；它替代早期材料及 Pro 原文中的同义枚举。字段命名变更必须走兼容 schema，不按显示文案猜测旧值。

| 维度 | 枚举/字段 | 含义 |
|---|---|---|
| 输入发送 | `not_sent / may_have_been_sent / sent` | 明确零输入／不知道是否发出／已确认至少有输入发出 |
| 动作完成细节 | `partial: bool|null`；路径动作另记 `path_completed: bool|null`、确认点数/位置 | partial适用所有动作；sent 不等于完整执行。非路径动作只有路径专用字段为 null |
| 应用效果 | `not_observed / effect_observed / no_effect_observed / inconclusive` | 绑定观察证据；光标或工具栏变化不自动等于画布进展 |
| 目标验收 | `not_checked / passed / failed / inconclusive` | 是否满足本轮声明标准；准备动作、已有图不冒领新产物 |
| 输入释放 | `not_needed / released / unknown` | 按键/鼠标释放事实；若需呈现进行中状态，另设生命周期字段，不给尚未确认的释放填 released |

这仍是四个正交业务维度（发送附带路径细节、效果、验收、释放）。`sent + partial=true` 表示已知部分执行；`sent + partial=null` 表示至少确认输入但不知道是否完成；`may_have_been_sent` 表示无足够证据判断发送。释放未知、效果未知、验收未知不可相互替代。

| 故障位置 | 最低回执 | 后续规则 |
|---|---|---|
| 发送前明确拒绝 | not_sent；无输入证据 | 修正条件、新观察、新动作 ID，受原 run 剩余预算限制 |
| 确认执行部分路径 | sent＋partial=true，保存最后确认阶段 | 停止原路径，确认释放与当前画布；不能整段重放 |
| 已确认 down 后失联 | sent，path_completed/partial 可 null | 追加迟到事实；未确认释放则隔离，不开始新动作 |
| 请求 helper 后无任何发送回执 | may_have_been_sent | 不能填 0；确认执行者退出和释放，重新观察后由恢复政策决定 |
| 完整输入后截图失败 | sent，保留路径完成/释放事实 | 效果/验收不确定；不通过重复输入来补截图 |

执行前获得稳定 action_id 并落库意图，执行后更新同一动作投影并按回执身份追加事实事件。`not_sent + confirmed_point_count>0`、`not_sent + partial=true`、`may_have_been_sent + path_completed=true` 等矛盾必须拒绝。路径采样点 0 不等于零输入：down 已确认但首个采样点前停止时，`sent + partial=true + path_completed=false + confirmed_point_count=0` 合法。另记输入事件数，不能将 down/up 混入路径点数；非路径动作的path_completed和路径点数/位置为 null，partial仍有意义。例如click的down已发/up未确认可为sent＋partial=true＋release_status=unknown。旧数据不能仅按旧 status 猜回执；缺证据保留 imported/unknown 来源。

释放仅处理本执行器追踪的自有按下状态，不能无条件替用户抬起残留修饰键。`not_needed` 只表示本动作没有释放义务，不证明旧 owner 或整个桌面无残留；进行中可暂为 null，最终必须明确三值之一。

R6 等价记账 fixture 必须在步骤、run 聚合、API、UI、导出五处同时显示 **3 attempts、1 次已确认输入、2 次 stale 拒绝**，重连不累加；这不是重跑 R6，也不证明 stale 子因。

### 2.3 Frame、UIA、反馈、独占与 deadline

FrameRef 绑定实际传给模型的图像变体、尺寸、捕获矩形、裁剪/缩放/填充变换、窗口/进程代际、DPI、观察代际、采集时间和 owner。模型只输出该光栅内整数坐标，宿主执行一次变换到物理坐标；旧归一化坐标经版本化适配，禁止猜测混用。

先实现 frame，再建设语义 ROI。客户区含工具栏时只能称“交互范围”；最大白色矩形不自动成为获准绘图区。UIA 先报告 selected/toggle/focused/supported_patterns，再按 Paint 版本实测 Invoke/Value/SelectionItem/Toggle；无支持可走受控物理输入，有不确定执行则不能直接回退。

stale 先记录身份、进程代际、几何、DPI、目标、光栅、消费代际、遮挡和人手介入等子原因。验证截图与发布给模型的新观察代际分别处理；这是新增测试风险，不是已确认的自我失效 bug。硬失配拒绝旧动作，内容变化需解释，不能一律忽略 ROI 外变化。

Planner 使用 `objective + criteria + constraints + current_observation + last_action + last_outcome + last_verdict + subgoal_state + remaining_budget`，反馈包含不能重试的原因。约 2K 新增反馈是实验起点，截断保留状态与证据引用，不能截坏 JSON 或回灌原始内部思考。双层重复检测分别防相同 action_id 重入与新 frame 上同意图无进展，不误杀合法连续笔画。

桌面独占按用户/登录交互桌面作用域覆盖所有正式输入执行者，携带不可复用 epoch。父死子活、子死父活、双实例恢复均需验证；旧 executor 可能继续输入或释放未知时拒绝接管。人手介入停止或重新观察，不自动抢回控制。Windows 完整性级别与残留修饰键另测，不能自动提权绕过；SendInput 的官方限制已复核，见来源链接。

一个单调 deadline 贯穿观察、规划、验收和输入，子请求上限不超过剩余预算。进行中路径在下一个安全取消点停止；释放和审计另设有上限宽限，分列执行耗时与收尾耗时。释放未知标记隔离，不续规划、不续验收、不发新业务输入；不可中断系统调用的限制必须实测报告。

### 2.4 配置、用量、事务与兼容

统一参数页保留现有行为并覆盖：协议与 endpoint、模型 ID、能力显式覆盖、思考模式/层级映射、采样/上下文/输出限制、工具能力、图片能力、默认视觉引用、超时/重试、来源与验证。音视频能力独立，不能由多模态开关推定已支持。模型能力与参数在实施日复核官方文档，不按名称硬猜。

`saved → resolved → wire` 三层有 revision 与非秘密快照。保持/替换/明确清空密钥是三种操作；空表单默认保持。TOML 以版本化原子发布，运行仅引用已发布 revision；文件发布和 SQLite 事务不假装原子。受保护秘密存储确认读取与恢复之前不得删除旧来源。Agnes 是当前默认视觉会话名称，核心使用稳定引用。

每次真实请求开始即登记 attempt 与用途，失败/超时也保留；缺 usage 为 unknown，不是 0。逻辑请求和网络重试分账；供应商 token、估算 token、已知/未知、价格版本分别记录。没有价格不能把输入占比当账单占比。

每个对象明确唯一 writer、权威模式和 epoch。一次业务写入与事件/outbox 同事务，提交后广播；消费者按流序号去重并补缺口。outbox 只保证可靠发布，不保证外部效果恰好一次。旧事件不完整，不编造历史工具/思考/时间/usage；FTS、统计和轨迹可重建，不修改权威事实。旧 epoch 的合法迟到回执经单独对账入口验证动作归属后追加原始事实，不能复活旧 writer 或覆盖新 epoch 控制状态。

普通消息型定时任务的现存临时授权已静态补证：共享内存 grant 的 key 是 workspace/session/tool，向会话 `*` 写入 full-access、TTL 300 秒，再在返回路径清理；这不等于修改持久配置或所有会话全局权限。S4.5 改为 grant_id 与 workspace/session/room/job/run 绑定的单次范围授权，清理只撤销自身 grant；并发借权、异常遗留等是待测风险，不标成已复现事故。

数据库 schema、事件、wire、投影、legacy JSON 各自版本化、列兼容矩阵。按会话切换权威前先停写、排空 run、备份并验证基线，拒绝旧入口继续独立写；Goal/beads 等领域可继续关系状态。影子模式仅重放录制输入比较，不产生第二次云请求自治循环或真实工具副作用。

## 3. 架构决定、模块落点和 23 个领域

以下采纳稿保留 Pro 的决定与接口范围，统一以第 1–2 节定稿口径解释。更细的调用图、源码定位和分项事实见 01/02/03 与证据包。现有实现转为回归基线，缺少能力或接口接线才进入开发；不把包数量、函数存在或历史测试数解释为完成率。
### 3.1 十二个架构决策

| 决策 | 结论 | 执行要求 |
| --- | --- | --- |
| **1. 权威状态模型** | **采纳，但收紧定义。** 保留 SQLite；先单写者，再追加事件和 outbox。 | 初期旧业务表仍是对应对象权威，事件不能冒充完整历史。达到切换门禁后，运行/会话域可采用“基线＋事件”的逻辑权威，旧表转投影。每个对象在任一时刻只有一个权威模式。 |
| **2. 扩展机制** | **采用双层扩展，不采用双主运行时。** | 首方受审 Rust 服务在进程内；第三方工具/脚本/MCP 在受控进程外。manifest 只是声明，最终权限由宿主执行闸门决定。Cordis 模块不直接等价为 Rust 插件。 |
| **3. 前端形态** | **采用原生 JS 模块化、注册表和独立构建。React 延后。** | 先拆资源和面板所有权，侧栏按3.8重设计，其余行为保留；不移植 55 个客户端包，不恢复旧 Provider 页或可见三栏。 |
| **4. 权限模型映射** | **修改为兼容解析层，而非枚举一对一重命名。** | 分离允许效果、审批政策、沙箱能力和 room/caller 授权。debug/release 分开测试。FullAccess 当前先于 Protected 的行为先保持；改变它必须另作显式安全变更。 |
| **5. 进程沙箱范围** | **采用，但先限 Windows 工具与脚本路径。** | shell、第三方插件、MCP、未来 PTC 逐步纳入。confinement 不可用时拒绝要求隔离的执行；GUI 输入 broker 作为单独高风险能力治理，不能宣称文件沙箱隔离了 Paint 的外部效果。 |
| **6. 配置归一层** | **保留 `coolzhu.toml` 与现有参数页，增加显式 resolve。** | 解析结果携带来源和 revision。会话覆盖暂不搬家，运行事件保存当次已解析快照，不成为第二套设置权威。配置写入增加版本冲突检测。 |

### 3.2 权限映射补充

权限映射必须按**实际决策真值表**验收：

- `Prompt` 主要表达审批要求，不应直接映射成某种文件可写范围。
- `Allow` 的旧调用语义需要确认，不能按名称迁成全权。
- `WorkspaceAuto / OutsideApproval` 应保留原执行规则，再逐项迁入新 resolver。
- `FullAccess` 保留已存在的兼容语义，但仍不能绕过 room 的 CU 能力要求、身份校验和取消。
- 未知/动态工具缺少最低权限元数据时，返回明确配置错误，不默认 ReadOnly。
- 普通消息型定时任务不再通过共享会话级临时 grant 提权；改为绑定到该次任务、范围受限、到期失效的授权。

### 3.5 SQLite 分步迁移

**步骤一：集中现有写路径。**

由一个 `SessionStore` 实现承接现有业务写入。保留当前关系表语义，在同一事务内追加必要事实和 outbox。这个阶段的事件尚不完整，不能声称可还原所有历史业务状态。

**步骤二：仅对运行/会话域建立可重建基线。**

对停写、无活动 run 的会话建立基线，包含经过验证的消息投影、已有运行状态和来源标记。缺失的历史 tool/action 对应关系标为未知，不能根据时间相近猜造关联。

**步骤三：按会话权威 epoch 切换。**

达到一致性门禁后，明确将该会话切到“基线＋事件”逻辑权威；旧消息表等变为投影，旧写入口拒绝继续独立修改。未切换会话仍走旧权威模式。

Goal、beads、ClawBot 等领域可以继续保留各自关系状态，不要求第一期全部事件溯源；但写者、跨域事务和审计关系必须明确。

建议新增或扩展的实体包括：

| 实体 | 用途与迁移规则 |
| --- | --- |
| `session_authority` | 标记会话权威模式、epoch、基线位置和写者；不是第二份会话数据。 |
| `session_events` / `event_outbox` | 同事务提交事件与待发布记录；SSE 可以重复投递，消费者按事件 ID/seq 去重。 |
| `request_attempts` | 所有请求尝试先登记，包括超时、取消、无 usage；区分用途和费用来源。 |
| 现有 CU steps/details | 增加可空的输入/释放/失配字段，保留旧审计；历史未知不得回填为零输入。 |
| 审批记录与客户端收据 | 持久化审批和去重身份；恢复后不得因审批存在就直接重放未知动作。 |

**outbox 提供可靠发布，不提供 GUI 或文件副作用的 exactly-once。** 执行前提交意图、执行后提交回执之间仍有崩溃窗口；遇到未知结果应观察或阻断，而不是自动重做。

### 3.8 用户追加：侧栏预览架构与临时过程区（v1.1）

本节来自用户在 Pro 审查完成后的明确要求，优先于原方案中“保持当前 DOM/全部面板”的笼统限制；尚未再次交 Pro 审查。本轮落方案，不直接改页面。统一参数、消息、搜索、用量等用户能力保留，非必要交互入口可以删除；视觉仍采用玉石控件、竹林背景和有对比度的内容层。

#### 目标信息结构

聊天是主区，右侧成为**任务关联的预览与操作工作区**。点击聊天中的文本文件、图片、视频或网址，直接在右栏打开对应内容，不要求先进入实验室、附件管理或工具调试页。顶部 Agent/工程/聊天室继续下拉切换，不能改回弹侧栏。

| 文件/产物 | 工程文件与本轮产物索引、文本/代码预览、图片/视频；从消息点击可直达内容和行号，不只打开文件列表 |

| 轨迹 | 按轮次/调用查看过程摘要、工具状态、错误、耗时、用量和证据；支持从选中轮次的上下文操作定位。token统计作为轨迹子页/区块，不必再占一个快捷icon |
| 设置 | 统一参数、默认视觉、权限等必须由用户配置的内容；普通用户操作和高级诊断分层 |
| 视觉实验室、记忆星图 | 从日常右栏及快捷轨移除，旧入口迁至确有需要的高级诊断或停止注册。不因删除页面而删除视觉服务、beads、用户记忆与历史数据 |
| 其他后台功能 | 按“用户在此做什么决定/操作”逐项评估；无明确日常交互价值不占常驻侧栏。诊断有必要时集中到设置的高级入口 |

#### 预览服务与面板架构

用统一 `PanelRegistry + PreviewRouter + ArtifactResolver + PreviewSessionStore` 替代按实验功能堆页面。名称为拟议设计，优先在现有前端模块和宿主桥内拆分，不为名称额外制造四个 crate。

- `PreviewIntent` 包含 workspace/room/session、源 message/turn、artifact_id 或经校验的 URL、媒体类型、版本/hash、可选行号与打开方式。消息渲染只发打开意图，不直接拼文件路径或读任意磁盘。
- `ArtifactResolver` 解析真实附件/文件身份、权限和 MIME，返回限定范围的读取句柄；同文件按身份和版本复用标签，重名不同文件不混淆。普通聊天提到的文件名不可直接伪造可打开链接，确有路径/附件引用才绑定。
- `PreviewRouter` 分发文本/Markdown/代码、图片、视频、网页 renderer。文本默认只读并支持查找、行号/定位与复制；图片缩放/适应/原尺寸；视频手动播放、暂停、进度/音量，不自动播音。编辑、下载、外部打开是独立显式操作。
- 每个 session 保存自己的预览标签/选中项/宽度，切换聊天室不串文件或轨迹；浏览器登录态与标签归属另按已有桥契约管理，不把“共享登录”误当“共享会话授权”。关闭面板释放媒体、对象URL和监听器，返回聊天保留滚动锚点与输入草稿。
- 右栏可拖宽、关闭、在文本/媒体/网页间切标签；低高度用横向标题和紧凑工具条，窄窗口以可返回聊天的单面板覆盖方式替代强挤三栏。悬浮预览只作辅助，不代替点击打开。
- 网页优先接现有浏览器桥及隔离的原生 WebView/标签；普通 Web 版遇到 iframe/CSP/站点拒绝嵌入时显示真实限制和“外部打开”动作，不绕过限制、不静默空白。Tauri和纯Web能力差异列入验收。
- Markdown/HTML/SVG/网址内容不能获得应用特权、Tauri命令或默认工作区读写。文本转义、受控链接协议、路径规范化、重解析边界、跨房间读取、大文件分页、损坏媒体与不支持编码分别处理。浏览器内可执行网页与静态文件预览分隔；仅点击预览不意味着授权 Agent 操作网页或将内容发给模型。

#### 思考和工具进度的显示契约

当前轮最多一个 `RunActivityStrip`，位于该轮最终回复之前，使用较浅的次级字体，**最少 1 行、最多 5 行可视高度**。字体在竹林内容层仍须清晰可读；浅色不等于降低到看不清。接收新过程摘要后向末尾滚动，内部缓冲有界，不能让聊天消息高度随日志增长。

只展示模型接口合法提供的可展示思考摘要、阶段说明与工具活动摘要；工具名/参数原始JSON、原始内部审计不成为聊天消息，不推导或伪造未返回的隐藏思考。工具开始、执行中、结果到达以稳定调用ID更新同一条活动，而非不断追加气泡。

| 事件 | 聊天临时区 | 轨迹与事实 |
|---|---|---|
| 开始思考/工具运行 | 启用动态1–5行区；并行工具聚合显示当前活动，最多5行 | 按真实seq、turn/call ID写轨迹，不按UI到达顺序改写执行事实 |
| 某项完成、轮次仍有其他活动 | 从活动集移除已完成项，显示仍在进行的项；无活动即收起 | 完成项留在轨迹；已有最终回答片段不被重排到过程之前 |
| 完成回复 | 思考/工具临时内容全部消失，不留占位空白或完成的过程气泡；保留回答、产物和耗时 | 可从轨迹入口定位该轮；不删除审计、不修改发送给模型的历史投影 |
| 取消/失败/断线 | 收起已终止过程；尚需用户处理的失败/审批用独立简短交互状态呈现，不能随日志消失 | 原因和已知/未知效果留轨迹；断线不伪装任务完成 |
| 重连或迟到结果 | 根据权威run活动重建；终态后不复活临时区 | 去重补事实/usage，不重复统计、不复活旧轮次 |

自动滚动只跟随当前过程区；用户选择文本或查看历史时不强抢主聊天滚动，支持暂停跟随、键盘和减少动态效果偏好。思考完成但工具仍运行时只剩工具活动；最终回复到达过程中出现新工具时保持真实阶段顺序，完成后聊天仅留最终内容。尚待审批的问题必须仍可操作，不能因“最多5行”裁掉按钮。

#### 对齐依据及边界

DSH已审计材料列有右侧 docking、文档预览、文件树和浏览器客户端模块；借鉴按内容组织和会话绑定，不把包存在当跨格式通过。ZCode官方[浏览器自动化](https://zcode.z.ai/cn/docs/browser-use)说明了浏览器和右侧过程展示。OpenAI官方[Browser](https://learn.chatgpt.com/docs/browser)及[更新记录](https://learn.chatgpt.com/docs/whats-new)支持内置浏览器、实时预览和文件预览方向，2026-09-21核验。

这些来源不证明三者都用同一套侧栏实现、支持所有视频格式或统一显示1–5行思考。本文将这些具体交互作为用户的产品需求，并用本项目自身验收确认。

### 5.3 如何逐步缩小 `main.rs`

按“**纯函数 → 有状态服务 → 外部执行 → 运行循环 → 路由适配**”的顺序提取：

1. 先迁请求解析、历史投影、参数归一和 usage 计算，保持输入输出完全一致。
2. 再迁工具调度、审批和存储事务；原函数变成薄转发。
3. 再迁异步 TurnRunner，Web 只保留 SSE/HTTP 适配。
4. CLI 与子 Agent 接同一服务后，才能废弃旧循环。
5. 每次删除旧代码都必须有调用图和回放证明，不以“减少多少行”为验收目标。

**影子模式只能比较解析、计划、投影和请求快照。** 不允许影子模型再次请求真实云服务后自主调用工具，更不允许重复文件写入或键鼠输入。

## 6. Paint 实验设计与候选门槛

本节数值均为 Pro 提议，不能据此宣称已经冻结或通过。L0 → L1 → L2 顺序不可跳过；若只做复杂任务探索，不计正式归因分母。

### 先分三层验收，不以低层通过代替高层

| 层级 | 任务 | 建议门槛 |
| --- | --- | --- |
| **L0：输入与映射** | 受控靶场点击、按下/移动/释放、坐标变换、取消、故障注入 | 固定测试集全部满足事实与安全不变量；坐标变换误差在可控环境内 ≤1 物理像素。这里不评价模型选点。 |

### 预算安排

保留默认任务 120 秒、12 动作等现有约束作为第一轮对照条件；在观察、规划、验收和输入前都检查同一个 deadline。收尾释放可有单独、明确的短宽限，但 deadline 之后不得启动新的业务动作。

每个工作包必须附以下字段，其他模型可直接据此建立任务和测试。缺少前置或证据只能记未执行/阻断，不能填通过。

小型PR只交相关字段和测试，不为凑齐模板创建重复测试。接口或数据变化必须有契约测试；真实键鼠、权限、迁移必须有相应故障证据。

### 可并行与必须串行的边界

允许并行：脱敏fixture/测试靶场、独立UI模块原型、官方资料和许可证清单、已冻结契约下的Windows后端适配、文档与非写入投影。每项明确负责人和文件所有者。

必须串行：公共动作结果枚举、运行身份、事件序号与schema迁移、配置优先级、生产工具权限解析、主循环执行权切换。一个PR合入契约后，其他分支才能基于该版本修改。禁止两个代理同时编辑巨型main.rs的同一职责段；由集成负责人只做薄层接线，功能代码先在独立模块完成。不要一次移动全部87k行后再修行为。

副作用并行还有运行约束：一个真实turn只有一个执行owner；同一交互桌面的键鼠只能有一个输入owner；两个独立工作区文件写入也需遵循各自任务授权与冲突管理。影子运行只能处理录制输入并比较请求/投影，不能调用真实工具执行器。

### 数据迁移的实际演练步骤

1. 选择脱敏副本，记录JSON、SQLite及附件目录的身份、大小、schema版本、会话/消息/配置计数；备份方式必须保证SQLite与WAL一致，不能在活跃写入时随手复制主文件。
2. 对副本执行迁移；旧秘密引用与百炼Base URL进行语义比对，API Key不打印、不重新录入、不以空值覆盖。找不到原秘密来源就标记需用户补充，不能生成虚假值。
3. 执行旧消息打开、检索、模型配置解析、附件引用、Goal恢复和工具审计查询。旧记录缺失usage或精确动作事实时保持unknown/imported标识。
4. 在事务和事件广播关键点注入崩溃；恢复后不丢已提交记录，不重复外部副作用，不生成第二个控制终态，但保留迟到事实；搜索等派生索引可重建。
5. 演练更高schema被旧程序拒绝写入；退回时先停止写者，按兼容矩阵选择兼容旧代码或匹配的数据备份。恢复不是随意覆盖正在运行的用户库。
6. 验收后才在安装流程中启用真实数据迁移；安装失败保留原数据与可执行恢复指引。生产迁移的最终范围在对应PR中审阅。

### Paint分层实验登记

| 层次 | 初态与目标 | 必须保留的证据 | 不能作为通过依据 |
|---|---|---|---|
| L0 输入契约 | 可控靶场；down前/后、路径中、释放、后截图处注入故障 | action_id、发送事实、最后确认点、释放结果、错误子类、租约生命周期 | mock通过就声称Paint可用 |
| L1 最低真实闭环 | 新空白Paint，固定窗口/DPI；选工具并确认；画一条短线和矩形 | 起点/中间/终点图、绘图区ROI、实际工具状态、真实输入记录、目标变化 | 工具栏变了、光标动了或API返回ok |
| L2 复杂任务归因 | 相同Qwen配置和初态下低质量海绵宝宝；只改变一个Agent因素 | 每组预注册样本、模型参数/提示版本、全流程证据、已知/未知usage、独立验收 | 脚本生成图片、上一轮已有图、只挑成功轮、临时降低标准 |

L1先稳定通过，L2才具备归因基础。若L1在确定性指令下失败，优先修宿主接口；L1通过而模型选点错误仍存在，再比较反馈/UIA/ROI；Agent不变量通过且模型持续输出错误计划时，将剩余项标为模型限制。不是要求画作审美质量达标，而是要求目标在真实画布有可核实的新内容。

原始03中的10次规划、2K新增反馈、≤1像素、≤5%误拒、≥30%token下降与1秒释放是实验候选。不得未测即写发布承诺。预注册时依据设备、模型、网络与测试集说明样本量和误差；确定性的权限、身份、独占、无盲重放、无虚假成功在该测试集内要求零违例。有限样本零违例不能推论现实世界永不失败。
