# Browser动态页面：按验收证据复核新鲜度

正式0.2.119的真实SWE-2-medium、唯一island-kayak长程任务在第一次点击订单输入框后失败。网页行情文字每100ms刷新，订单区域不移动；宿主已确认点击投递及释放，尚未输入订单码，随后返回native_browser_observation_stale。根因是验收员作出判断后，ensure_fresh要求整个nodes数组完全相同，无关行情的文字变化也会使负判失效。失败保留，不能把已聚焦算作订单完成。

修补仍使用现有模型判断前后的两份认证宿主快照，不新增轮询、重试、队列、锁或超时。宿主、工程、聊天室、资源代际、导航修订、URL、标题、文档身份、视口及焦点继续一致。焦点除了索引也比较该索引的控件事实。正向引文核对原索引处的实际节点；跨节点拼接同时核对中间节点，不能沿用消失或改变的成功证据。标题/URL/视口证据依赖已保持一致的对应字段。

未满足判词不需要固定整页无关文字，因为它不授予完成状态。身份复核后用最新节点重新生成结果；模型的met=false不会因为新文字出现而被升级为true，正向判断仍须在新快照中匹配原文。节点移位影响正向证据或焦点时仍停止，不凭相同文字猜测新控件身份。输入阶段的命中、遮挡、文档及原生目标校验不在此次修改范围内，2秒内部和5秒外层限制保持。

验证包括一项必要边界回归：无关行情可变化；成功证据消失、焦点事实变化和文档替换仍拒绝。完整既有Web回归及模块联动需实际退出0；低内存重跑保留首次LLVM编译内存不足的非0事实。随后在正常候选软件中使用同一SWE/原唯一远端运行新的三步动态订单，检查真实事件、终态、释放、ACP收尾和软件原图。候选通过后再出包独立复验，不以局部断言关闭正式验收。

范围限制：visible_progress现有整页变化判定仍可能把行情刷新算作中间进展。本修补只解决旧观察误阻塞及成功证据新鲜度，不宣称该进展判定或严格原生竞态全部闭环；实际动作上限、总预算和完成验收仍有效。进一步改动需要围绕动作相关事实单独设计，不能用文字变化替代目标完成。
