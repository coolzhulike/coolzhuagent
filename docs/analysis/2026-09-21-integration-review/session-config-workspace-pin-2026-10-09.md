# 模型配置与工程切换作用域固定

正式115独立服务真实复现：两个工程使用相同会话ID，但名称、本地容量、temperature及revision不同。六路读取与180次正常工程切换并发，2041次读取中各读者均捕获混合（最多保存8个/读者，合计48样本）。会话名称来自旧工程，参数和生效容量来自新工程；不能用同进程store锁保证工程一致性。首次准备JSON把必填api_key_ref置null导致会话未加载/404，属于驱动准备失败，修正后上述混读才是产品复现，保留两次原事实。

最小方案：SessionConfigService创建时复用现有workspace_activity::WorkspacePin，工程切换进行中拒绝配置操作409；配置操作进行中拒绝切换409，结束后按正常入口重试。Pin只维护既有活动计数，不持MutexGuard、不添加第二锁/缓存/队列，参数校验、发布顺序和原缺项回退不变。统一读取handler保留service直到插件目录枚举与JSON派生结束，统一保存handler保留到保存后的响应重读结束；旧容量入口保留至本次完整响应产生。

风险：不能仅在read/save方法内部短暂pin，handler后续插件目录读取或保存响应重读会重新暴露工程窗口。使用Rust RAII生命周期覆盖完整handler，不用std guard跨await。嵌套只读服务pin沿用可重入计数，最后持有者释放才允许切换；错误退出自动释放，不添加隐式等待、后台重试或用户权限开关。短时工程409是明确冲突，不应以阻塞全局Mutex等待替代。

本项只解决操作进行期间工程配置与会话的混合，不宣称客户端迟到请求/ABA作用域检查、全部入口、跨进程单写者/outbox/epoch及跨资源崩溃已经完成。后续仍需expected_workspace身份及统一领域边界。配置专项零模型，不借Qwen或模型夹具替代真实供应商验收。验证须先实际offline build/既有完整回归，再独立真实服务相同竞争、保存期间工程切换、正常GUI及同EXE重启；正式115尚不包含新候选。
