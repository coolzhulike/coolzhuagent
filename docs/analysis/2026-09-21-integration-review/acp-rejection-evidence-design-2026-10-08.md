# ACP 登记前拒绝的最小证据补齐

正式101源码变化实测观察到零派发/零网络请求，但桥在 `policy.live/tool_live` 拒绝时直接返回 MCP 错误，尚未登记 tool_calls，具体拒绝回执没有独立持久化。模型转述不能代替宿主证据。问题属于观测缺口，不是工具越权或网络抓取失败。

采用现有 runtime_run_events 的 `tool.dispatch_rejected` 事件，不新增表、状态机、重试、权限入口或前端调试控件。只在派发前拒绝写入；已接纳后的失败继续使用原工具台账及监督器。字段仅含固定阶段、固定原因码、executed=false、冻结 attempt_id、声明过的工具名及请求ID的SHA摘要；未声明名称统一占位，不保存参数、原始请求ID、拒绝错误文本、URL或认证信息。

写入失败仍拒绝执行，并在原拒绝文字后标明审计保存失败，不能把审计失败变成放行，也不能伪造已有持久化证据。重复请求可以留下多条尝试事件，但相同请求摘要保持一致；这些事件不新增逻辑执行次数或token计数。运行事件继续归属被冻结的原工程、原父run，不写当前新工程，不修改原终态。

风险审查：新增磁盘写入只在拒绝路径，不插入鼠标按下/释放之间；使用原append事件函数及原广播，不另造账本。避免保存动态错误文本泄露文件名或密钥。源码竞态中的失效资格仍由原门判断，记录不声称仅凭 generic tool_not_live 能区分所有撤销原因。首次正式101历史不补写、不追认通过。少量必要断言验证零执行、摘要关联、脱敏及日志库不可写时仍拒绝；后续正式版实操才可关闭独立宿主回执缺口。

本次实现只覆盖通用 dispatch 入口最前面的 live/tool_live 两处拒绝；RPC格式检查、已终态桥、CU等待/规划控制入口及随后执行器的拒绝仍沿用各自原路径，不宣称全部拒绝矩阵已有独立事件。现有本地宿主执行回归中补断言，无新增模型夹具；offline build成功、完整控制台1418/0/6既有忽略通过。见[验证及原始日志](../../testing/2026-10-08-acp-rejection-evidence/report.md)。源码候选尚未出包实机。
