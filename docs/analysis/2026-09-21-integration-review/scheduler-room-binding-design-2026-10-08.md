# 定时任务复用既有聊天室的实施前审查

当前 poll 定时任务固定投递 `room-scheduled-tasks`，创建请求及持久配置没有房间字段。Devin 绑定按工程/房间/Agent作用域隔离，因此直接使用当前 SWE 配置做真实定时触发，会在系统房间创建另一云端绑定，不满足用户只保留唯一测试云会话的要求。不能把原房间绑定复制到系统房间，也不能为验收改数据库。

## 最小实施方案

- poll任务新增可选 `chat_room_id`，创建页明确选择结果聊天室；新建任务可预选当前房间，列表显示固定目标。旧配置字段缺省时继续原系统房间，不修改已有任务。
- 配置字段使用 serde default 并对 None 跳过序列化。现有领取 fingerprint 是完整任务 JSON 的SHA；若新增字段默认序列化为 null，将改变所有旧任务指纹，导致已领取的结果不能正常复用。须断言旧任务序列化字节保持原形，不能重写旧领取记录迁就新代码。
- 创建时验证房间属于当前工作区；执行时在既有 workspace pin 内再次验证，SendMessageRequest 明确传 expected_workspace_id 及目标房间。房间已删除则记录明确失败，不回退到其它房间，也不创建新云会话。
- 单次 ScheduledExecutionGrant 的 room_id 使用固定目标，其原有效期和撤销规则保持；不修改聊天室权限表。原会话正在运行时沿用现有准入/绑定互斥，拒绝或等待的实际行为须另核，不新增隐式重试。
- Goal型任务仍沿用原Goal执行与消息镜像方案；不能在本次poll字段上宣称支持Devin Goal/Relay。前端仅在poll显示房间选择，Goal请求带不适用房间时明确拒绝。
- 定时任务失败状态消息应落原目标房间。目标房间不存在时只保留持久领取结果/任务状态，不为显示错误自动创建房间。不可通过“最佳努力写系统室”泄漏跨房间上下文。
- native_browser_panel仍false，后台定时任务不会借创建时的前台状态永久接管可见浏览器。实际Browser后台授权/可见资源设计另行审查，不在本修补扩大。

## 验收顺序与风险

先实现配置/创建与投递的房间职责，少量本地断言覆盖旧指纹、无效房间零派发及scope匹配。再正式版界面建立只绑定原SWE房间的一次真实任务，任务做有实际工具反馈的项目审查，核唯一领取、最终回复可见、唯一island不增加云会话。最后核执行后重启不重放与运行中未知结果不自动再提交。先前停机到期/投影恢复证据保持，不重复当作全新功能。

本文件为实施前风险识别，尚未修改配置/API/页面，不算上述功能完成。当前正式101保持唯一原绑定。Opus暂停，主会话独立审查；不为测试创建第二远端会话。
