# 工具原文可读性与源码审查误判修补

当前为源码候选，正式运行仍是 0.2.101。不增加工具、权限、桥接方法或前端调试项，不修改唯一 Devin 绑定。

## 原文保存和模型可读性是两个条件

`tool_result_spill::for_context` 原本对超过8000字符的结果保存内容寻址原文，再只交回前6000字符和 `read_file` 续读提示。保存成功不能证明模型有读取入口：当前 SWE 白名单 revision35 只有 CU、CLI状态和计算器，未声明 `read_file`。

最小修补仍使用受理时冻结的数据库目录和现有内容寻址存储。ACP 用现有 `FrozenPolicy::tool_live("read_file")` 查询冻结声明、当前定义和权限；没有可用读取资格时，保存成功后也完整交回结果，不附未开放工具的续读提示。最后复核又发现内外两次投影会保存提示包装过的第二份原文，因此ACP内层DSH派发不做投影，仅由外层桥对完整结构化回执保存与投影一次。保存失败原有完整回退保持。

它不承诺后续读取一定成功：路径权限、文件状态或之后撤销仍可能导致明确拒绝。完整结果也可能超过模型窗口，不能声称无限上下文或无上限容量。其它HTTP Provider的通用派发入口尚不携带实际声明的读取能力证明，现按保守false保存并完整交回，不再默认true、生成无法证明可用的续读指针；完整真实声明矩阵仍开放，不能回读新配置扩大旧轮。这会增加大结果上下文占用，后续容量策略须独立设计，不能通过静默丢弃原文处理。

本轮不为只读原文另造模型可用API，不绕过已有文件边界，不声称引用图或自动GC完成。附件GC当前只做候选演练，完整Goal/导出/待发送引用图仍缺。

## 真实审查发现额外结账缺陷

在正式101向原 SWE-2-medium / island-kayak 发送实际源码审查，单次 `plugin__cli_anything_status({"command":"rust-analyzer"})` 的宿主台账 `completed`、审计 `ok/allow-auto`，ACP `end_turn`、进程已排空、绑定解锁。但源码材料含 `computer_use_perform` 与 `click`，旧启发式把它们合并为本轮电脑操作意图，添加“本轮尚未执行桌面或浏览器操作”并将父运行错误记为 `failed`。

这不是模型或CLI工具执行失败。旧失败事实保留，不直接改写数据库追认成功。源码修补仅限这段未执行提醒：复用现有附件意图分界，剔除Markdown代码围栏；入口与动作须在同一句正文中，保留全局否定和说明型前缀。它只控制提醒/失败结账，不能授予或禁止实际工具执行，不更改CU准入。

这仍是保守的自然语言启发式，不是完整语义解析器。其已覆盖缺陷和真实明确操作要求分别回归，不能据此外推全部自然语言或多语言提示。对取消、未知执行和失败审计的既有处理保持。

## 审查采纳和后续验收

同一SWE实际审查建议保留原文、默认不扩权，并指出非ACP默认可续读、上下文容量和引用回收边界。主会话采纳这些边界，拒绝把“未发现阻断缺陷”或单次状态查询视作大结果验收。模型仅看提供的源码片段，其“未见GC”也不代表全仓库不存在GC候选逻辑。

离线编译和少量必要断言验证字符边界、保存失败完整回退、无读取入口时原文完整、材料不产生CU失败及真实操作仍有未执行提醒。统一正式交付后，用实际大结果工具核对完整尾文、磁盘SHA及没有未声明 `read_file` 请求；源码审查回归要同时核正常可见回复、父运行终态和唯一绑定。未完成实机前，两项均不能关闭验收缺口。

真实失败原回执、审查回复和正常软件截图见[专项记录](../../testing/2026-10-08-spill-capability/report.md)。Browser严格时序候选切换此前被自动审批拒绝，未执行；本修补不借其它接口重试该动作。
