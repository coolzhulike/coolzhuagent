# 模型配置旧页面迟到请求：最小改进方案

正式0.2.116（Web SHA d931957b13ec7268edaa518783d43839c8a8ef32a0117e343038c318e375129f）已真实复现跨工程错写：工程A/B使用相同会话ID、同为revision 10，A页面取快照后正常切B，旧A保存返回200并把B的名称、temperature改成A草稿。运行中的工程pin只能阻止操作交错，无法识别操作开始前已迟到的客户端。基线保存在tmp/2026-10-09-session-config-late/before116，零模型调用，不改原验收工程。

复用workspace_activity的短时锁与RAII pin；增加一个非凭据的加载标识，进程启动后第一次pin生成，工程成功切换或重载时更新。标识只用于配置页版本匹配，不是权限，也不替代长期权威epoch。切换失败不更新标识。Pin捕获标识，不持MutexGuard跨await。

GET工程响应提供configuration_scope，统一配置页在打开时绑定工程ID和标识。已有配置读取/保存、旧容量入口及统一页新建会话入口，若带X-Coolzhu-Workspace-Id或X-Coolzhu-Configuration-Scope，必须在持pin时匹配，否则409。新建也要匹配，避免保存新草稿的第一步先在错误工程创建会话。保留不带这些头的既有HTTP客户端兼容性，明确不宣称旧客户端全部获保护。统一配置页三个入口传入顶栏的完整工程路径；先匹配/api/workspace的完整路径，再绑定响应工程ID和标识，避免把截断编码的草稿缓存键误当工程ID。顶栏路径尚未就绪时不挂载配置页；获取标识时若工程已改变，拒绝绑定。作用域不会在重试中自动刷新，拒绝时保留草稿并提示“请刷新页面后重新打开配置页”；不会通过自动续期把旧草稿转到新工程。

风险与边界：标识不能拼接外部路径或用于权限放宽；不用额外缓存、排队、重发、等待和审批。成功保存后的响应复读也保持同一个pin。先校验作用域，再创建或发布，错误RAII释放。A→B→A、同工程重载、进程重启必须拒绝旧标识；同一工程内正常编辑仍由configuration_revision决定冲突，不因一次保存使其它页作用域失效。新建会话与参数保存现有两步非原子问题继续单列，不能借本项声称完成完整SessionConfigService/单写者/outbox。其它会话修改、模型发现和Devin云API不顺带改协议，另行审视。

验证：实际offline build及已有回归；真实隔离HTTP工程同ID同revision跨工程迟到、ABA、重载、重启、无头兼容、错误后pin释放；核验SQLite/配置文件确实不被错误请求写入；正常GUI配置页加载、保存和重开，以及同EXE重启后参数恢复实拍。本专项零模型，不充当供应商连通或Browser严格时序通过证据。新修复尚未进入正式116。
