# 模型参数保存顺序及失败恢复

现有SessionStore::save在SQLite事务失败时恢复committed_state；事务提交后JSON兼容镜像失败只警告，不对外声称业务未提交。因此不重复设计缓存回滚。

实际缺口：统一模型设置在取出会话并释放存储锁后发布参数，再重新取得存储锁更新会话。期间普通会话修改或删除可以插入，校验对象可能过时；旧参数在配置锁外读取，未提供expected_revision的兼容请求可能回退到错误旧值。第二次存储锁取得失败还会越过参数回退。原参数不存在时回退插入default，也未恢复原有缺项。

本阶段保留既有会话存储锁作为同进程会话写入边界，在同一同步块内完成会话查找/校验、参数发布、会话SQLite更新及失败回退。锁顺序沿用store→config；config锁只由既有mutate函数短暂持有，绝不以config→store顺序嵌套。同步块结束后再await读取返回值，不持有std MutexGuard跨await。旧参数Option在配置mutator内与revision同批取得，失败回退恢复Some或删除原本不存在的项。若其它配置写入已经推进revision，沿用409提示，禁止覆盖其新值。

这只关闭同进程会话写入插队、旧值捕获和可恢复失败边界。配置文件与SQLite仍是两个资源，崩溃于中间仍需后续统一权威存储/事务outbox；普通GET及运行器跨资源读快照也未因此成为完全原子，跨进程单写者、共享Runner仍开放。不改变模型超时、权限、密钥或Devin绑定。

验证采用真实候选服务的隔离工作区，实际SQLite写入故障后核对会话内存/数据库/参数回退，再正常保存与同revision并发保存；用正常界面截图核对。无模型夹具，不调用模型、不触碰原SWE会话。编译、回归与候选实操通过后再统一正式出包，不能追认0.2.111包含此修补。
