# Part A：三个新增待决策项（本轮执行中暴露）

## A-1 迁移前遗留的"NULL 归属且未收尾"CU 运行会**长期阻断**该 scope

### 现象（可观测）
迁移 v22 之前写入的 CU 运行行，`workspace_id` 为 `NULL`。其中**未收尾**的那些会被新互锁命中（判据：未收尾 **且** 归属未记录）⇒ **该 `(session_id, turn_id)` scope 内的新 CU 输入被永久阻断**，错误码 `workspace_unrecorded_active_run`。

### 背景（前因链）
1. F03 按裁决 §5.1 落地"归属必须记录"，并把**读回**分档为 `Recorded{…}` / `Unrecorded`（呈现为常量 `"历史归属未记录"`）。**只加列、不发 UPDATE ⇒ 没有批量回填路径**（这是裁决明确要求的：历史归属不猜造）。
2. 随之而来的必然结果是：历史行读回即 `Unrecorded`，而互锁为了避免"在无法确认归属的 run 上继续注入输入"，会**阻断该 scope 的新输入** —— 这在安全方向上是正确的。
3. **但没有任何机制会关闭这类行**。已核实：`main.rs` 对 `computer_use_runs` 的引用数 = **0**；全 crate 搜 `computer_use_run*` 与 `orphan|stale|recover|reconcile|sweep` **零命中**。对照：聊天运行有 `recover_incomplete_runtime_runs`（`main.rs`）负责把上次进程遗留的非终态 `runtime_runs` 收敛为 orphaned，**但那是 `runtime_runs`，不是 `computer_use_runs`**。
4. 因此触发条件一旦出现（升级前有未收尾的 CU 运行），阻断**不会自行解除**。

### 为什么必须你来定（不能由实施者自定）
"什么条件下可以判定这类 run 不再是活动风险"牵涉**安全与事实诚实**两条已被裁决固定过的边界：
- 裁决明确禁止"按时间、当前窗口或当前登录状态猜配"，也禁止"从 UI 曾显示完成推断成功"；
- 但如果不给任何关闭规则，就变成"永久阻断"。**这两者的取舍不能由实施模型单方面决定**。

### 方案阻塞点
- 关闭这类行**必须写终态事实**，而终态不得是"成功"（无证据）：需要一个**非成功但明确**的终态口径（例如"归属未记录、执行结果不可确认"）——这属于**契约层的终态语义选择**，`RunTerminalStatus` 现有变体里最贴近的是 `Interrupted`，但用它表达"因归属缺失而不可对账"是否准确，需要你确认。
- 若选择"由人工追加解除事实"（RPR-05b-1 的模式），则需要 RPR-05c 的原生恢复入口配合——**该入口尚未实现**（决策第 11 项已把它与互锁列为同一可发布单元）。
- 若选择"启动时自动收敛"，必须同时规定**不得因此推进 Goal、不得触发成功记忆、不得让旧 run 复活**（这些在 B-5/§10.2 已有口径，可直接沿用）。

### 选项与建议
| 选项 | 风险 |
| --- | --- |
| (a) 启动时把"归属未记录且未收尾"的 CU 行收敛为**明确的非成功终态**（带原因码，不猜执行结果），并记录收敛事实 | 需要确认终态口径；可能与"不能凭时间判定"存在张力（收敛依据是**收尾状态**而非时间，可缓解） |
| (b) 只提供**人工解除入口**（追加解除事实），不自动收敛 | 在 RPR-05c 就绪前，scope 一直阻断（可用性问题） |
| (c) 维持现状（永久阻断），要求人工修库 | 与"不需人工干预"的产品目标冲突，且修库属高风险操作 |

**我的建议**：(a) **加** (b)。即启动时把这类行收敛为"非成功、原因明确"的终态（依据是"未收尾 + 归属缺失"，**不是**时间猜测），同时保留一个人工解除入口给异常情况；两者都不得让旧 run 重新获得执行资格。**但在你确认终态口径前，我不会实现 (a)**。

### 当前状态
**未做任何代码改动**。互锁已按裁决生效（fail-closed），这只影响**升级前遗留**的行，新运行的归属都会被记录（F03 已验证"崩溃遗留的**新**运行有归属、不会触发互锁"）。

## A-2 归属值的 `ws-<ASCII 字母数字>` **形状校验**比裁决要求更严（需确认或否决）

### 现象
`CuWorkspaceAttribution::from_parent_run` 会拒绝任何不匹配 `ws-<ASCII 字母数字>` 的归属值，错误码 `workspace_attribution_not_canonical`。也就是说：**归属值的格式被硬编码耦合到 `workspace_identity()` 当前的产物形状**。

### 背景
裁决明确把"**窗口名 / 模型提供字符串**"列为禁止的 workspace 取值。F03 的判断是：**形状检查是唯一能当场拦住它们**的判据（因为"窗口名"和"模型提供字符串"在结构上都可能是非空、无路径分隔符的普通字符串）。它主动把这一点作为"比工单要求更严"申报，并要求确认或否决。

### 为什么需要你确认
这是一个**格式耦合**：将来若 `workspace_identity()` 的产物变化（加前缀、换成长 ULID、允许 `-`/`_`、长度变化），CU 会**fail-closed 拒绝**（错误码清晰，但功能中断）。是否接受这种耦合，取决于产品对 workspace 标识格式的稳定承诺——这是产品决策。

### 方案阻塞点
- 若保持现状而**不加**一条"格式契约测试"，那么格式变化会在**CU 路径**上炸，而那里离 `workspace_identity()` 很远，排障成本高。
- 若放宽为"仅结构校验"（非空、无路径分隔符、非占位值），就失去当场拦住"窗口名/模型提供字符串"的能力（裁决点名的禁止值）。

### 选项与建议
| 选项 | 说明 |
| --- | --- |
| (a) 保持形状校验，**并在 `main.rs` 加一条测试**断言 `workspace_identity()` 的产物匹配该形状 | 把隐式耦合变成**显式、有测试守卫的契约**：格式变化会先在离源头最近的地方失败，且信息明确 |
| (b) 放宽为仅结构校验 | 失去当场拦截窗口名/模型串的能力 |
| (c) 形状校验 + 允许"格式注册表"（多格式白名单） | 增加机制复杂度，当前只有一种格式，收益不明 |

**我的建议**：(a)。它保留了裁决要求的拦截能力，同时把"格式变了会怎样"从**运行时 CU 中断**变成**源头测试失败**。

### 当前状态
形状校验已实现并通过测试（F03，含逐项拒绝与码可辨）；**我尚未添加那条源头契约测试**。

## A-3 "历史归属未记录"的**呈现面尚未接线到任何读者**

### 现象
`StoredWorkspaceAttribution::text()`（产出 `"历史归属未记录"`）目前**只有测试在用**；代码里带 `#[allow(dead_code)]` 与注释。也就是说：裁决要求的"**呈现**未记录"在**数据层已具备**，但**用户/运维看不到**。

### 背景
F03 的允许文件清单里**不包含显示入口**（CU 运行列表 / 诊断 API 都在 `main.rs`）⇒ 它只能把能力做好并如实标注"没有读者"，**没有**为了消灭告警而删掉它（这个克制是对的）。

### 为什么需要你定
这不是"要不要做"（裁决已要求呈现），而是**呈现在哪里**：不同落点会影响用户对"运行结果"的理解，属于产品表面决策：
- 放在 **CU 运行列表**：用户能看到"这条运行的历史归属未记录"；
- 放在 **诊断/自检**：运维能看到，但普通用户看不到；
- 放在 **错误/阻断提示里**：只在被互锁阻断时才可见。

### 方案阻塞点
无技术阻塞；它是我的 `main.rs` 工作（不属于任何子代理的允许范围）。唯一约束是**不得把"历史归属未记录"渲染成某个具体工作区**（F03 在数据层已保证没有这条路径）。

### 我的建议
在 **CU 运行列表 + 诊断**两处呈现（前者面向用户、后者面向运维），文案就用 store 的常量，**不推断、不回填**。我建议把它并入 **F09（终态与恢复消费者收口）** 一起做，而不是单独开一个显示补丁。

### 当前状态
**未接线**；`text()` 带注释的 `#[allow(dead_code)]` 保留。
