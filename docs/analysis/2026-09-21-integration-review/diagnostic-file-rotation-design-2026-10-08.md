# 文件诊断轮转的边界与实施

本轮检查发现`coolzhu-diagnostics::FileOutput`持有无界追加句柄，Web控制台`diag_log`也直接追加`err.log`。长程与反复启动会持续放大文件。先由独立diagnostics模块统一文件写入责任，Web只调用接口，不将轮转代码塞进巨型main.rs。

采用8 MiB活动文件与三代备份、64 KiB单记录上限。超长结构化记录以固定JSON省略事件和原始字节数代替，不在UTF-8中间截断，不输出原正文。既有超大历史文件首次轮转仍完整保留并按代自然淘汰；这是新写入有界，不是整个日志目录的硬磁盘配额。

Windows改名不能依赖仍被其它进程打开的长期文件句柄。写入前持有同目录稳定`.lock`文件的OS锁，活动文件只在锁范围内打开/追加/关闭，下一条重新打开。线程内串行，进程间try_lock不等待，竞争或磁盘错误立即返回，避免日志改变工具deadline。结构化输出仅stderr限次提示，不递归诊断、不显示正式前端调试信息。

会话、工具/输入安全、用量等SQLite和领域审计仍使用原事务/留存规则，绝不送进此轮转器。当前不追加通用日志导出入口，不默认打包聊天或凭据。全局配额/脱敏导出、其它生产者和异常磁盘环境继续开放。

核验先覆盖整条中文记录的新旧代顺序、独立OS锁句柄竞争以及超长记录后继续写入，再实际build控制台，用独立workspace和日志目录启动候选EXE观察真实轮转与正常页面。正式包复验前只称源码候选，不追认0.2.109包含。Opus按用户要求暂停，主会话自行完成设计审查与实施，不用子代理。
