## 可直接用于实施的契约细化（主审查补充）

以下是早期拟议设计，不代表当前字段或接口已经存在。正式口径以04第1–2节为准：释放为独立第四业务维度、路径点数不等于输入事件数、迟到事实可追加、旧epoch回执经对账入口接收。下文“只更新这一条状态”指同一动作身份的投影，不禁止追加事实。

### 运行身份与副作用事实

统一身份包含 `workspace_id / room_id / session_id / turn_id / run_id / step_id / tool_call_id / provider_request_id`。公开轮次、模型供应商请求和内部规划请求分别保留，禁止复用一个 ID 假装同一层次。

动作结果分三个正交维度：

- 发送事实：`not_sent / may_have_been_sent / sent`。部分路径执行另记已知点数/最后确认位置和 `partial=true`，不知道时写 unknown；`sent` 仅表示输入发出。
- 观察结果：`not_observed / effect_observed / no_effect_observed / inconclusive`。后截图失败不能抹掉已输入事实。
- 目标验收：`not_checked / passed / failed / inconclusive`。任务 passed 必须满足声明的验收条件和证据，不能从步骤数推导。

错误增加稳定的 `error_code / stage / retry_directive / evidence_ref / input_delivery`。默认未知发送状态不自动重试非幂等动作；先重新观察和对账。有错误不能一律写成零动作。取消不是撤销外部副作用；取消后拒绝新动作，允许有界释放及记录。

调用记录在执行前获得稳定 `action_id`，后续只更新这一条状态；重复 HTTP/SSE 或重连不生成第二次执行。真实输入没有通用“恰好一次”保证，崩溃窗口按结果未知处理。审计需区分 submitted、accepted、attempted、sent、partial、verified，不再让 `action_count` 承担全部含义。

### 状态事务与事件投影

先保持现有 SQLite 为权威，不同时让 JSONL 成为第二写入权威。一次业务状态变化和对应事件/outbox在同一数据库事务提交，之后才广播。消费者按 `(stream_id, seq)` 去重，允许断线后从持久游标续读；发现序号缺口先补读。HTTP/SSE只是运输层，不是事实来源。

必须先决定每个字段由状态表还是事件推导拥有，避免“都在同一SQLite里”却仍有两套相互覆盖的真值。新事件只覆盖新写路径；旧历史转为有来源标记的导入基线，不能编造当时没有记录的工具调用、思考、usage或精确时间。搜索索引、轨迹、统计可重建，重建失败不得修改会话权威数据。

故障注入点：提交前、提交后广播前、广播后游标前、工具发出前、工具已发出未回报、终态落库前。要求不丢已提交事件、不重复执行副作用、结果不确定时可解释。数据库版本号以实施时实际 schema 为准，不在计划中假定一个固定的新版本号。

### Planner 与视觉证据

规划上下文建议为 `objective + criteria + constraints + current_observation + last_action + last_outcome + last_verdict + subgoal_state + remaining_budget`。不加入跨轮原始思考；工具结果用有界事实摘要；稳定指令、观察和失败说明分别限额，保留截断标志。文字反馈可以改善决策，但必须用控制实验确认贡献。

图像引用需绑定 `frame_id / captured_at / app_ref / window_identity / raster_size / transform_id`。若使用裁剪 ROI，再记录其相对原图的变换；模型返回图内像素坐标，宿主执行唯一变换到物理像素。旧归一化动作可经兼容解码器一次转换，不混用全屏、窗口、客户区、裁剪图和缩放预览坐标。

语义 UIA 操作先确认对应 pattern 能力，调用后重新读取状态；语义不可用才用受控物理输入，禁止两个后端都执行一次。Paint前置状态必须包含实际绘图区、当前工具/颜色与模态窗口；工具栏状态变化只能算准备动作，不能当作画布新增内容。

失配分类先补诊断，再优化。窗口身份、DPI、几何、目标所有权/遮挡等硬条件不能被模型豁免。整窗像素变化可触发有界重观察或目标重定位；不得简单忽略变化直接重用旧坐标。背景闪烁误拒率属于待测指标，不是放松校验的先验理由。

### 桌面控制所有权

输入是同一交互式桌面的共享资源，应通过操作系统支持的跨进程独占机制保护，按用户/登录桌面定义作用域。owner携带room/turn/run/进程身份与不可复用代际；第二个run返回明确busy并保持零输入。心跳或TTL只用于诊断，不能在持有进程仍活着时强行抢走租约。

取得租约、观察、输入及释放必须处于同一受控生命周期。持有者死亡后由OS回收句柄，后继run仍需检查残留输入和新的界面状态，不能复活旧队列。人手介入和目标变化应导致停止或重新观察；屏幕锁定时不发送输入。

### Deadline 与用量

以单调时钟的任务deadline约束观察、规划、验收和输入启动；子请求超时不得超过任务剩余预算。收尾释放/审计有独立且有上限的宽限，明确从任务耗时中单列，不宣传精确120秒硬界限直到通过实测。

每次真实模型请求开始就记录attempt与用途（chat/planner/verifier/vision_bridge），失败/超时也保留。只有供应商返回usage才计“已知token”；没有usage记 unknown，不填0。若调用带重试，区分逻辑请求和每次网络尝试。价格表版本化且独立于token计数，没有有效价格不得推算账单。

预算、模型路由、试验开关进入 typed `coolzhu.toml`，不引入新业务环境变量。`Agnes` 是用户当前默认视觉会话的名字，代码依赖其稳定会话引用与能力，不写死名称或厂商。图片能力开关不扩充为音视频全链路声明。

### 发布与回滚约束

性能实验可退回上一已验收策略；权限闸门、未知副作用不重放、独占、坐标身份、取消释放和诚实终态不能作为可关闭的安全补丁。新旧主循环可做只读投影对比，但一个真实turn只能由一个所有者产生副作用。

迁移先跑副本，记录备份身份与旧二进制；前向版本不兼容时拒绝降级写入。需要退回旧代码时同时判断数据库是否向后兼容，否则停写并恢复匹配的数据快照；不能声称“换回exe”足以撤销数据库迁移。

每个PR交付功能ID、修改模块、配置/协议变化、失败复现、验证证据、已知局限和回滚步骤。MSI、源码commit、各二进制/资源hash、安装前后用户数据比对和真实前端验收属于同一发布门禁。保留历史0.2.14证据，但后续变更需重新执行受影响验证，不能借旧1175通过替新版本背书。
