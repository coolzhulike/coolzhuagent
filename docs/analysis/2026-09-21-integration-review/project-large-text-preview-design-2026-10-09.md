# 大文本只读预览增量方案

正式125实拍拒绝1.8MiB的真实SBOM：1MiB阈值作用在整个文件，虽已有字节分页与`:行号`窗口接口，却在分页前被元信息门拒绝。现有元信息还先无界读取全文件再判断大小，行窗口的任意范围也没有响应字节上限。

本次将读取职责提取到`project_file_snapshot.rs`，使用同一文件句柄获取元信息与有界读取结果，允许最多64MiB的UTF-8文本进入既有只读分页。读取最多64MiB加一字节，增长的文件也不会无界分配；超限结果不生成完整文件SHA/编码的假声明。没有新增存储层、后台任务或新的权限路径。

工程API继续通过原工作区路径解析，编辑上限保持256KiB、只读资格及写入版本冲突保持；meta与本次分页内容来自同一次读取，避免一次请求两次打开文件取得不同版本。此边界不宣称能锁住其它程序的原地改写或防止所有外部竞争。

字节响应维持256KiB上限和UTF-8字符边界；行窗口最多801行，并在拼接前累计字节，超过256KiB明确失败，不默默截断某一行后冒称完整。前端复用既有只读代码窗口和`:行号`跳转，不将`next_offset`调试数字显示给正式用户。单行超长文本仍可走字节API分页，完整长行的GUI翻页方案未在本次实现，不外推所有文件格式完成。

以完整SBOM的元信息、冻结SHA、开头与尾部行窗口及独立原字节比对为主要验收；正式旧版拒绝截图保留，新候选实拍另归档。再用自有超限稀疏文件及超长单行文件验证只读边界，正常小文件编辑/冲突由既有功能检查覆盖，不增加镜像模型夹具。完成offline构建、相关Web与联动测试后，候选与记忆边界合并下一批正常出包，正式125不追认含修复。
