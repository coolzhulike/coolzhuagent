# A2：工作区来源与冻结父上下文——生效执行口径

- **版本**：v1（2026-09-25），来源＝第六轮答复第二部分（正式执行确认与细化）
- **性质**：本文件是 A-2 的**权威执行口径**。台账与后续实施（含交给实施模型的工作）应引用**本标题与版本**，不再引用"第五轮 §五"这类章节编号。
- **适用**：A-2 的全部实施与验收；与既有 ID 不冲突——既有 ID 不改号，普通 CU 必需身份要求不降低，**不新增平行的 `FrozenParentContext`**。

## 0. 一句话目标

把"CU 自己复制的 `ws-<Alnum>` 形状硬编码"替换为：**源头统一解析 → 宿主在真实接纳点构造可信冻结上下文 → 逐层传递 → 按实际上下文类型校验必需维度与实体关联 → CU 接纳固化归属**。

固定链路（不得跳过任一环）：

```
原始工作区标识 / 已保存工作区记录
   ↓
源头唯一的规范解析与身份解析
   ↓
宿主在真实接纳点建立可信、冻结的上下文
   ↓
逐层传递 FrozenParentContext
   ↓
按实际上下文类型校验必需维度与实体关联
   ↓
CU 接纳并固化归属
   ↓
现有权限、来源、预算、所有权和输入前检查
```

## 1. 四条不得违反的原则

1. **源头格式规则仍然存在**。删除的是 **CU 自己复制的那份** `ws-<Alnum>` 硬编码，**不是**删除所有结构校验。
2. **规范解析成功 ≠ 获得执行权限**。模型提供的字符串即使格式合法、甚至恰好等于一个真实工作区 ID，也**不能**直接成为可信父上下文。
3. **可信上下文必须由实际接纳链构造**。叫作 `FrozenParentContext`、字段不可变、或"在 Rust 内部持有"，都**不能单独**证明它来自正确的接纳入口。
4. **不修改既有工作区 ID、不批量回填历史 NULL、不改变工作区默认位置。**

## 2. 模块职责与本轮允许修改的范围

| 层 | 本轮修改要求 |
| --- | --- |
| `workspace_identity()` 及其源头模块 | 集中生成、解析与兼容规则；现有格式继续支持 |
| `FrozenParentContext` | 复用现有载体；**收紧构造入口**，保留真实缺省，不复制一套同字段新结构 |
| 聊天／接力／Goal 接纳入口 | 从实际已解析、已授权的上下文构造；**不从模型参数或并行执行时的 UI 状态构造** |
| 工具分派链 | 完整转发，不能覆盖成当前工作区或丢掉可用维度 |
| CU 接纳／执行器 | 消费来源与关系校验结果，缺必需身份时**在输入前**拒绝 |
| `ActionOriginAuthority`／存储关联层 | 复用既定生产查询边界，核对真实父对象与归属；**不用待验证对象自行生成一份"可信记录"自证** |
| 测试 | 覆盖**实际构造与生产消费入口**，不只测试正则或结构体 getter |

**授权**：必要的构造器、可见性、调用签名、校验入口与相应测试。
**不授权**：换 ID 算法、另建身份权威、重写共享 `TurnRunner`、抢占新的数据库迁移版本号。
**跨 crate**：保持原依赖方向——核心契约**不能**反向依赖 Web 的 `main.rs`；已有核心可信上下文／authority 接口应复用，不要为迁就 `crate::FrozenParentContext` 把整个 Web 依赖下沉。

## 3. 对 `FrozenParentContext` 的具体要求

**构造来源**：普通请求中的原始字段只能作为**待解析候选**，不得通过反序列化直接得到可信状态。原生工作区选择或用户请求携带工作区 ID **并非一律禁止**——它必须经过宿主解析与授权后才能进入冻结上下文。禁止的是"客户端／模型给了什么，执行器就信什么"。

**构造器可见性**：生产构造器应尽量限制在**真实接纳模块**内。测试需要构造错误对象时使用**测试支持接口**；**不新增**生产可用的 `trusted=true` 或"绕过来源"参数。

**四个可选维度必须有真实消费**（字段名沿现有定义）：

| 维度 | 有值时校验什么 | 缺省时怎么处理 |
| --- | --- | --- |
| 房间 | 当前调用是否确实属于该房间、调用者是否有相应能力 | 按入口和上下文类型判断是否适用 |
| 会话 | 会话与工作区、房间及当前调用的**真实关系** | 本应有会话的普通聊天 CU **不得跳过** |
| 公开轮次 | 是否是该已接纳请求的**实际**公开轮次 | 没有建立时保留缺失，**不复制其他 ID** |
| 父运行 | 该运行是否属于对应工作区／会话／轮次，当前是否具有相应执行资格 | 没有实际父运行时，**不生成假的父运行关系** |

这些检查必须来自**可信接纳结果或真实权威关联查询**，不是"拿同一个结构体里的字段互相比较一次"就算验证。

**工作区切换不能重绑定旧运行**：若新权限使旧运行不能继续，应明确取消或拒绝后续执行，而**不是**把旧运行改挂到新工作区。

## 4. 三条非流式路径：真实 `None` 保留，但不据此放宽 CU

事实：`api_chat_send`、接力、目标阶段当前**不建立** chat runtime run，因而相关父运行与公开轮次缺省。该事实不得隐去。

本轮决定：A-2 **不顺带**为这三个入口建立完整聊天运行生命周期；**也不批准**把它们的真实缺省当成普通模型 CU 的普遍豁免条件。

| 情形 | 本轮行为 |
| --- | --- |
| 普通文本生成确实不需要 CU 的必需执行维度 | 按原能力继续，不被无关 CU 条件一并阻断 |
| 普通模型 CU 缺现行契约要求的执行身份 | 继续 fail-closed，**明确指出缺哪个维度、哪个接纳入口尚未建立它** |
| 接力／Goal 已有真实、可适用的父执行实体 | 只能按已有或显式定义的关系契约关联；**不能把任意 Goal ID 填进 chat run 字段** |
| 模型驱动任务缺聊天身份 | **不能**改标 `ControlPlane` 或 `UserDirect` 绕过 |
| 真实人工直操／安全恢复 | 仍走此前裁定的 ControlPlane 接纳与资源级恢复契约 |

后续补齐这些入口的真实执行接纳，继续挂在 RD4-04 的剩余生产闭环／RPR-13 下。新 ID 可以在**真实新请求接纳时**生成并持久化；**不能**在输入前临时补几个字符串冒充原本已存在的父运行。

**验收措辞**：本项通过后可称"**A-2 来源分层完成**"，**不自动**称"三条非流式 CU 已恢复可用"。

## 5. 六组固定验收测试

固定为**六组**（每组可有参数化子用例）。**不得靠拆分函数增加测试数来代替覆盖。**

| 编号 | 测试组 | 核心断言 |
| --- | --- | --- |
| **A2-T1** | 源头生成与规范解析 | 当前 `workspace_identity()` 生成值可被唯一解析器接受；无效结构明确拒绝；**CU 不再持有第二份私有格式规则**。未来格式变更由源头兼容测试约束，不为本次测试随意开放新生产格式。 |
| **A2-T2** | 持久化与历史兼容 | 既有工作区 ID 往返不变；旧合法记录仍可读；历史 NULL 仍为 `Unrecorded`，**不根据当前工作区补值**；解析不能悄悄改号。 |
| **A2-T3** | 真实冻结链与切换边界 | 从**实际接纳入口**经现有调用链到 CU 消费端，验证所有实际存在的维度；中途改变 UI 当前工作区或让任务进入并行分支，**原归属不变**。不能只测试 `Clone`。 |
| **A2-T4** | 合法形状但不可信的来源 | 模型／普通原始输入直接提供 `ws-…`、窗口名伪装值或复制真实 ID，均**不能**直接构造可信上下文；经授权选择入口正常解析的真实用户选择**仍可工作**。 |
| **A2-T5** | 父运行关系错误 | 工作区正确但房间、会话、轮次或父运行关系错误时拒绝；引用其他工作区的真实运行也拒绝。**拒绝发生在原生输入之前，输入 spy 为零。** |
| **A2-T6** | 缺省适用性与入口差异 | 流式路径漏掉必需维度会失败；三条现有非流式路径保留真实 `None`，**不被补哨兵**；缺 CU 必需身份时零输入；合法 ControlPlane 不伪造聊天身份，且普通模型任务**不能伪装成** ControlPlane。 |

**六组之外**：既有 Turn、StepAction、来源、取消、预算、权限与回执回归**继续执行**，不能因层级重构而删除。

## 6. 合并顺序（硬约束）

1. **先**新增并接入源头解析、可信构造与关系校验；
2. **最后**删除 CU 私有正则。

**禁止出现中间可执行版本**：旧正则已删、新来源检查还没接上。

**A-2 的关闭证据必须包含生产消费点**：把字段读出来用于 debug、日志或消除 `dead_code` 警告，**不算**来源校验接线。（这与当前"保留未消费字段的警告"一致——最终目标不是靠注释长期保存这些字段，也不是为了消警告随便读一次，而是让它们**实际参与语义校验**。）

## 7. v23/v21 相关的四条边界（第六轮答复 §六）

v21 修复方向已被接受，**不重开、不分配 v24**；但关闭前须明确：

| 边界 | 要求 |
| --- | --- |
| 单步守卫 | 每一步使用**自己的固定目标版本**或统一阶梯元数据，不能随终点常量变化而重跑旧步 |
| 整体守卫 | 整体是否需要升级、是否遇到超前版本，**仍可**正确比较 `SESSION_SCHEMA_VERSION`；**结构测试不能误禁这些合法判断** |
| 独立打开路径 | `ComputerUseRunStore::open()` 与主入口**复用相同迁移实现与前置规则**，不能形成两套逐渐漂移的阶梯 |
| 错误传播 | 迁移或对象检查失败**不得静默继续**；后续依赖 v23 的恢复／写入不得假装成功 |

至少补或确认四类行为测试：

1. **22→23**：版本正确，实际列、表、约束及必要索引存在。
2. **23 再次打开**：不发生版本回退，不重建、不丢失已有数据。
3. **迁移途中失败**：不出现"版本已声明升级、但必要对象没有完成"的可接纳状态。
4. **超前版本或不完整 schema**：两个打开入口都**明确拒绝**不兼容操作，**不通过把版本号降下来"修复"**。

独立入口直接调用 v23 是否已检查所有前置迁移，**本轮无源码证据，要求验证，不断言其已有跳步缺陷**。

**保持原边界**：v23 schema 就位**不等于**遗留运行可以仅凭 NULL 与未收尾自动中断；RD4-03 仍需执行上一轮的 owner、资源状态与恢复事实规则。

## 9. 同批的其他裁决（非本文件主体，记录以便执行）

- **打包政策（第六轮 §三）**：**维持拒绝发布**不稳定输入所生成的包；**允许且应当输出失败诊断报告**；**不允许**用 `quiescent=false` 给混合输入产物补一张可发布收据。失败诊断至少记录：运行 ID、阶段与失败原因、声明的源码／构建输入范围、已观察到的输入变化、各阶段退出码、已产生但未获准发布的临时产物、`release_eligible=false`。差异若来自前后采样，须标明是"已观察变化"而非完整写入历史。失败后不得覆盖上一份成功报告、不得更新"最新有效包"、不得进入签名／安装／分发；临时产物与可发布产物**分区**且不自动晋升。可分开表达：`live_worktree_changed` / `build_snapshot_integrity` / `build_input_digest` / `validation_snapshot_digest` / `release_eligible`（同义字段复用，不强制照搬命名）。已建立完整不可变构建快照、构建与测试只用该快照时，**允许**活动开发树继续编辑。
- **PKG-L07c（第六轮 §四）**：批准独立工单，**默认 P1**（打包完整性门禁）；若核查发现失败时仍可能发布错配的 DLL／收据／manifest，则升级为 **P0 产物完整性缺陷**；不阻塞 A-2；修复前正式发布使用单一打包者、独立输出并验证内容／收据，**不得宣称已通过并发导出能力验收**。并发政策：同一实际导出目标**只允许一个发布者**，锁范围按实际共享输出槽位（规范目标根、target、profile），不能只按 build ID 加锁；流程为"取得发布权 → 本次运行独立暂存区生成与核对 → 发布匹配的产物与收据 → 校验完成 → 释放发布权"；争用者可返回明确 `Busy` 且不修改赢家文件。允许结果：一成功一 `Busy`，或受控串行后各自成功且每次消费得到自洽的一组产物与收据；**不允许**两个调用各自成功却留下 A 的 DLL 与 B 的收据。仅连续替换两个文件**不得**被描述成跨文件原子提交。

也**不得**称 T6 已全部完成（ControlPlane 身份分类那半尚未接线）。

**零输入的证明口径（如实说明）**：以 `attempts == 0`、`steps_completed == 0`、**无运行行**、**无步骤行** 四项为零证明（沿用本文件既有口径），未使用额外的原生输入 spy。

**自证**：Step A 期间 `CanonicalWorkspaceId`/`InvalidWorkspaceIdentity` 只有测试引用，生产构建有 `never used` 警告；Step B/C 接线后这些警告**自动消失**，生产构建警告数回到接线前的 99（仅剩四维字段的预期警告）。这正是"读取字段用于 debug/消警告不算接线"的反面证据。

## 10. 实施设计（读源码后定型，供本文件 §2–§6 的落地）

### 10.1 两个端点的事实（已核读源码）

| 端点 | 现状 |
| --- | --- |
| 源头生成 | `main.rs` 的 `workspace_identity(&Path) -> String`：canonicalize → 反斜杠转正斜杠 → 小写 → `format!("ws-{:016x}", hash_bytes(..))`，即 `ws-` + **16 位小写十六进制**。 |
| CU 私有校验 | `computer_use_store.rs` 的 `is_canonical_workspace_identity(value)`：`strip_prefix("ws-")` 后要求后缀**非空且全为 ASCII 字母数字**（另有 `MAX_WORKSPACE_ID_CHARS` 长度上限）。它比源头**更宽**（任何字母数字后缀都收，例如 `ws-ABC`），因此既格式耦合、又并不真正证明来源。 |
| 现有拒绝码 | `InvalidWorkspaceAttribution`：`NotCanonicalIdentity` / `ControlCharacters` / `FilesystemPath` / `Placeholder` / 过长等，被接纳路径与测试断言引用。 |

### 10.2 定型设计：让 CU **在类型上拿不到未解析的字符串**

1. **源头新增唯一解析器**（`main.rs`，与 `workspace_identity` 同处）：
   - `pub(crate) struct CanonicalWorkspaceId(String)`——**只能**由解析器构造，无公开构造函数；
   - `pub(crate) fn canonical_workspace_identity(&str) -> Result<CanonicalWorkspaceId, InvalidWorkspaceIdentity>`：把现有形状规则（前缀、非空、ASCII 字母数字、控制字符、长度上限）**整体搬到源头**，错误分类保持可区分；
   - `impl CanonicalWorkspaceId { pub(crate) fn as_str(&self) -> &str }`；
   - `workspace_identity(&Path)` 的产出必须能被该解析器接受——由 **A2-T1 的兼容测试**钉住（源头生成 ↔ 源头解析）。
2. **`FrozenParentContext` 收紧构造入口，且保留真实缺省**：字段类型改为 `CanonicalWorkspaceId`；`new(workspace_id: &str, ...)` 内部调用源头解析器，**解析失败即返回 `None`**（fail-closed）。生产构造器仍只在四个接纳入口调用；测试要构造"错误对象"时走**测试支持接口**（不新增 `trusted=true` 之类生产可用旁路）。
3. **CU 侧删除私有格式规则**：`CuWorkspaceAttribution::from_parent_run` 改为接收 `&CanonicalWorkspaceId`（不再接收 `&str`），因此**不可能**收到未解析值。CU 只保留它自己的**来源/归属**判定（如"这是文件系统路径"这类不属于格式范畴的拒绝），映射到既有错误码。
4. **既有格式测试搬家**：`ws-`、`ws-abc-def`、`ws-a\u{7}b`、过长等用例移到**源头解析器**的测试（A2-T1/T2），CU 侧只留"接收已解析身份"的用例。`Notepad` 这类窗口名会在**源头**被拒（非规范结构）；接纳路径的错误码通过映射保持原有可区分性。
5. **合并顺序**：先加解析器与 `CanonicalWorkspaceId`、收紧 `new`、改 `from_parent_run` 签名（此期间 CU 的旧私有规则**仍在**，树始终可执行）→ 再把旧私有规则与旧格式测试删除（最后一步）。**不出现"旧正则已删、新检查没接上"的中间可执行版本。**

### 10.3 六组测试的落点规划

| 组 | 落点 |
| --- | --- |
| A2-T1 | `main.rs`：源头生成 × 源头解析的兼容/拒绝双向用例（生成值必被接受；无效结构明确拒绝且分类正确） |
| A2-T2 | `computer_use_store.rs`：既有 `ws-` 记录往返不变、`Unrecorded` 不被按当前工作区补值、解析不改号 |
| A2-T3 | 接纳入口 → 调用链 → CU 消费端：沿用既有"运行中切换当前工作区、归属不变"的实测用例（`admission_entry_records_the_frozen_workspace_in_the_frozen_database`）并补并行分支 |
| A2-T4 | 源头解析器 + 接纳构造：模型/普通输入直接给 `ws-…`、窗口名、复制真实 ID 均**不能**构造上下文；经授权选择入口的真实选择仍可用 |
| A2-T5 | 执行器：房间/会话/轮次/父运行关系不符即拒绝，且**原生输入锁不存在时零输入**（用输入 spy 计数） |

### 10.4 需要显式决定的点——**已决定**（读源码＋按答复 §2.2 表定案，不再留歧义）

**决定一：审计码的归属。** 答复 §2.2 明确 CU 保留"来源/归属判定（如'这是文件系统路径'这类不属于格式范畴的拒绝）"，因此**不是**把 CU 的错误码整体搬走了事。定案如下：

- **源头解析器**承担全部六类判定（空 / 控制字符 / 占位值 / 路径形状 / 过长 / 形状），并逐字保留既有审计码（`code()` 已与 CU 侧逐字对应）——**已实施**（`main.rs` 的 `canonical_workspace_identity` + `InvalidWorkspaceIdentity`，A2-T1 两条用例已绿）。
- **CU 侧删除复写**：`is_canonical_workspace_identity`、`MAX_WORKSPACE_ID_CHARS` 与那六类重复判定在 CU 内不再保留；`CuWorkspaceAttribution::from_parent_run` 改收 `&CanonicalWorkspaceId`，**在类型上不可能**收到未解析值。
- **执行器的 `input_context_incomplete` 只表示"没有冻结上下文"**，不再承担"值不合规"的审计职责。值不合规的**审计信息**由**接纳点**在构造 `FrozenParentContext` 失败时取得（那里能拿到 `InvalidWorkspaceIdentity` 分类），并如实记录"缺哪个维度、哪个接纳入口未建立它"。
- **受影响的既有测试**（下一步一并改，不删断言强度）：执行器那张"五种非法值 → 五种错误码"的拒绝表，拆成 ① 源头解析器分类表（A2-T1/T4，已部分到位）＋ ② 执行器"无上下文即拒绝、零输入"（保留原地）。**不保留**"非法值经执行器返回 `workspace_attribution_*`"这条路径，因为它正是"CU 自己复写格式规则"的残留。

**决定二：四维可信关系查询的边界。** 房间/会话/轮次/父运行的校验一律走**既有读回/权威查询接口**（`computer_use_store` 已有的读回函数与 `ActionOriginAuthority` 生产查询边界），**不得**用"同一个结构体里的字段互相比一次"充数。逐维度口径：房间→用房间能力/成员关系的既有查询核对"本次调用确实属于该房间"，缺省时按入口类型判断是否适用；会话→用会话存在性与"会话↔工作区↔房间"的真实关系核对，普通聊天 CU **不得**跳过；公开轮次→只接受接纳点**实际建立**的轮次，没有就保留缺失、**不复制**其他 ID；父运行→用运行行核对"该运行属于该工作区/会话/轮次且当前有执行资格"，没有实际父运行就**不生成假关系**。

**决定三：三条非流式路径的能力缺口文案**：缺 CU 必需身份时，拒绝信息必须**指明缺哪个维度、哪个入口尚未建立它**（例如"父运行：`api_chat_send` 尚未建立 chat runtime run 行"），且**不得**改标 `ControlPlane`/`UserDirect`。
