# ACP工具回执分页：实测失败后的最小改进

正式102真实net_fetch返回44498字节资料，HTTP200/truncated=false；宿主保存111227字节完整结构化回执，实际body与独立服务器逐字节相同，只有一个原文对象。SWE-2却明确报告下游输出被截短、末尾final_record不可见，未猜测或调用计算器。故“宿主完整返回”仍不足以验收模型可读，旧轮保持失败；不将模型报告的具体截短长度当宿主独立测量。

方案沿用已验证的CU规划分页模式，新建独立result_pages模块，职责只有本轮工具回执的存储引用和UTF-8分页。原content_blob_store原子发布及摘要命名复用。每个FrozenPolicy持有本轮结果映射，不接受文件路径、不扫描磁盘寻找旧结果，不增加Provider、配置页或执行器。

ACP桥在真实执行返回后，对较大回执保存原文一次，返回首个只读页和result_id/offset/next_offset/total_bytes/SHA。每页按JSON编码后6000字节限额，转义内容也纳入预算。新增tool_result_read为桥协议续读，与CU的read_request一样不重复执行原工具、不授予任意read_file。输入只有本轮result_id与UTF-8字节offset，可按需读尾部或顺序还原。普通短结果保持原格式，保存失败明确完整回退并提示下游截短风险。

风险控制复用当前轮live/预算/取消/owner检查与原工具tool_live资格，原工具撤销后不能续读；读取前后复核，结束后桥消失，旧ID不能进入另一桥。磁盘原文实际读入后校验同一份字节摘要，损坏/替换不返回内容。只记录页ID、来源工具和偏移，不记录正文、密钥或模型思考；不另造执行台账或审批路径。分页错误允许重新读取，不可据此重提有副作用的原工具。

本方案解决模型可见的传输大小，不承诺无限上下文、全部Provider均可分页或GC引用图已完成。当前仅ACP入口接入；其它HTTP Provider沿用原完整回退，后续独立核验。原结果结构可能有重复业务内容，本次先保全准确性，不在未理解协议字段前删除内容。
