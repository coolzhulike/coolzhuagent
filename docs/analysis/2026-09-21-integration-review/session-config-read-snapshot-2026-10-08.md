# 会话配置读取快照：实现边界与验证

正式112保存接口已用既有会话存储锁串行化参数发布和SQLite会话更新，但GET先释放会话锁再读取参数，预算又另外读取参数和本地服务配置。并发保存期间，同一响应可能组合旧会话、新参数及另一版本预算。实际112六路GET与180次正常保存捕获了参数context_window=16384/max_output_tokens=1024，而effective_context_window=8192/effective_max_output_tokens=512；原响应完整保留，不依赖模型转述。

实现仍按store→config顺序：GET持有会话存储锁，在一次配置读取内捕获参数、revision和标准化本地容量，再释放两把锁。会话摘要和执行DTO新增接收已捕获参数的转换入口，连接地址、协议、参数与生效预算不在转换过程中再次取参数；插件目录枚举在释放锁后进行。预算默认值/覆盖规则放session_model_config纯规则模块，主层负责全局状态与锁。本地服务上限以及更小用户预算规则保持；运行时预算计算也改为一次配置快照，避免内部再次读取。

不引入新全局门、不持std锁跨await、不将HTTP或持久化职责放进纯规则模块。现有锁顺序与保存一致，减少锁外二次取值；代价为GET短暂等待配置持久化/会话保存，这正是读取完整已发布状态所需的同步边界。插件IO不增加持锁时间。

验证使用独立工作区和安全库的真实EXE/API/SQLite，六路并发读取、180次名称/采样/容量联合保存，检查每条响应参数与预算一致；复验本地容量8192对用户32768的约束、用户输出1024、正常GUI读取和同EXE重启。配置测试不发送模型请求、不模拟供应商响应；不替代真实长程模型/工具验收。实际结果在对应测试报告记录。

本项仅收敛统一model-settings读取的会话名称、连接参数、采样、容量、配置revision与预算内部快照；密钥状态、记忆模式和显示品牌等派生状态仍按各自既有读取职责提供，不声称整个响应所有子系统状态具备事务快照。旧容量端点、跨工作区竞争、跨进程单写者、跨文件崩溃一致性、完整SessionConfigService/SharedTurnRunner/outbox仍需分别完成，不据本项宣布总体架构验收通过。正式112不含此候选，需后续统一新包复验。
