# Devin 单一云端测试会话与重新绑定（2026-10-06）

用户已清除 Devin 云端会话，要求重新创建并绑定一个会话，不再出现多个云端测试会话。本轮主会话独立实施；Opus 暂停，不切换到 Qwen，不使用模型夹具作为验收证据。

## 问题与实施方案

原聊天绑定能按工程、聊天室、Agent 续接，但 Computer Use 内部规划使用 `internal-v1:<attempt_id>`，每次规划和验收都会轮换远端会话。仅把编号改成常量只能减少到主聊天和内部规划两个会话，仍不能满足严格单会话要求。不能并发向同一个远端会话发送外层聊天及内层规划请求，也不能让取消中的旧任务借新绑定继续输入。

采用当前聊天模型回答宿主规划请求：现有 Computer Use 执行器继续产生规划/验收提示，独立的 `planning_exchange` 只负责把本次提示交回已连接的 Devin 模型，接收回复。`computer_use_perform` / `computer_use_wait` 返回当前 `job_id` 与一次性 `request_id`；模型通过 `computer_use_respond` 返回指定格式原文。宿主仍使用原解析、节点归属、动作证明、权限、取消、时限、效果验证和输入释放链路。规划回复不等于执行成功，不新增直接键鼠入口。

当前桥从 task-local 进入 blocking worker 后，再跨 `tokio::spawn` 时显式传递 Exchange。缺少当前桥或模型/运行身份不匹配直接报错，不回退到另一个云端会话。内部请求不再执行 ACP `session/new` / `session/load`；唯一 ACP 会话是当前聊天室主模型。规划回复的请求编号与摘要进入原父运行轨迹；用量记在真实外层会话，不伪造独立供应商用量。

新增明确的重新绑定入口，当前聊天室和模型会话共同定位旧绑定。操作前核对用户读取的绑定集合；事务内拒绝仍在途或未知的 ACP、尚未结束的聊天室任务。旧 ID 归档，本地消息、记忆、失败和安全记录保留。该入口本身不创建云端会话，下一次正常聊天发送才创建一次，此后续接新 ID。恢复失败仍明确报错，不自动创建替代会话。

## 风险与验收

- 同一模型既回答聊天也回答规划，必须按本次宿主快照输出；不沿用历史控件引用。宿主照旧拒绝失效引用、错误页面事实与格式错误。
- `job_id` 和 `request_id` 必须归属当前桥和未完成任务；旧、跨任务及改变已接受内容的回复不能触发新动作。重复相同回复只返回原处理状态。取消后清除未回答请求，迟到回复不能恢复执行。
- 等待仍持有同一执行 future，不在 HTTP 断连后另起动作任务；返回规划请求不销毁 CU future。主模型提前结束时沿用原取消收尾。
- 浏览器文字/AX 规划通过当前 MCP 请求交回；桌面原图改走当前 ACP 连接的标准图片提示块。模型先让出本段生成，宿主才串行发送图片续轮；不并发提示、不新建内部会话、不重新提交 perform。图片尚未发送时拒绝验收回复；每次请求仅允许一次原图交接，取消清理未回答请求。
- 用真实 SWE-2-medium、正常聊天室链路完成一轮 Browser Use，并在第二轮续接同一远端 ID。核对新增 ACP 绑定、尝试及台账；每轮不能出现内部远端会话。保留截图、真实可信网页事件、逐动作回执、最终页面事实及原失败。

修复将原图通过同一个 SessionService 的 `session/prompt` 串行续轮送入。Exchange仅交换规划请求，桥负责校验同一未完成job和当前冻结权限；协议服务负责会话与提交状态。只有宿主图片交接信号和当前生成end_turn同时成立，才保留原attempt为submitted而让出生成；正常完成、拒绝和取消仍按原终态处理。续轮必须来自刚让出的submitted连接，核对同一执行锁，不能从terminal复活或重新claim。沿用原总时限、取消、图片能力声明、8MiB出站限制及文字1MiB限制；每轮最多128次图片交接。丢弃交接连接或续轮失败按unknown收尾，不能继续输入。
