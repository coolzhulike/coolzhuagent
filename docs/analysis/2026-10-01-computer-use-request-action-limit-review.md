# Computer Use 单请求动作上限实施审查

依据058真实Qwen CJ现场：用户要求每个部件只落笔一次，第一笔视觉验收未通过后，同一个CU仍继续规划并发送第二笔。原有constraints是模型提示，宿主默认max_actions=12并没有表达本轮更小上限。选点是否正确属于模型能力；停止边界必须由Agent负责。

在既有ComputerUseRequest增加可选max_actions，最小1，省略保持旧请求行为。控制器取请求上限与宿主上限的较小值，不允许扩大宿主预算。一段连续路径算一次动作尝试；预输入失败的尝试也消耗额度，不能借恢复绕过上限。该参数不是工具调用数，也不限制模型HTTP次数或改变120秒截止时间。

复用RunBudgetGuard：在规划前检查已用动作数、无进展和截止时间；输入前再次检查并计数。最后一次动作后仍做原有重新观察和逐项视觉验收。目标已达成则正常成功；未达成且额度耗尽则Supervisor/budget_exhausted、retry_owner=none，保留步骤、投递、释放及视觉失败记录，禁止内部再规划。没有增加第二个执行循环、前端状态机或数据库表。

外层工具schema公布整数下限及“一次输入/连续笔画使用1”的说明；内部规划提示携带请求值。当前轮明确JSON契约的类型比较自动覆盖该字段，删除或增大字段仍拒绝。幂等目标键不因上限变化创建新目标，不能通过改配额重放同一轮已执行的目标。普通自然语言不通过正则猜数字；模型未给结构化值时保留宿主默认，不能声称任意自然语言限制都已硬执行。

主要风险：低额度下过期观察需要恢复时会停止，这是保守的尝试限额语义；不得偷偷恢复余额。达上限不应省略验图，否则会把输入完成误判目标完成。外层模型仍可能另开不同目标或工具调用，单请求上限不替代现有本轮契约、调用额度及父轮停止规则。规划耗时仍可能耗尽验图预算；本修复不调整模型或思考程度。

验证只补必要的边界：请求1只执行1次且未调用第二次规划；请求99无法放大宿主1；最后一次动作验图成功仍成功；0非法、旧请求兼容；明确本轮参数不能删/增额度。核心检查是工程边界验证，正式通过标准仍为安装版真实Qwen的原图、真实输入回执及终态；不得用受控helper结果代替Paint或Browser Use验收。
