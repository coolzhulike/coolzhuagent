1. `native_browser_input.rs:213–222`在同一UI闭包中顺序排队按下/释放，不等按下回调再释放；同线程其它命令无法插在这两次入队之间。但浏览器异步处理仍存在区间，不能推断所有网页事件也不可交错。
2. `browser_panel.rs:511–530`关闭撤销原资源后走`retire_view`；`native_browser_input.rs:39–44`先隐藏、等待执行门再实际关闭。**隐藏与资源撤销可以在途发生**，仍需真实回执和下一轮验收。
3. `browser_panel.rs:686–713`同scope页面导航受PanelStore命令门控制，没有在该分支领取输入execution_gate；目前这是页面替换在途风险的源码依据，**是否造成新文档错投尚未实测**，不能直接宣布已发生事故。
4. 第二轮未读的`main.rs:1270 existing.close()`已由主会话核实是`EXTERNAL_BROWSER_LABEL`独立浏览器窗口，不能当右栏关闭路径漏洞。
5. 不采纳第二轮“每项约20次”机械重复和“网页事件不成对必为NotDispatched”的建议：已按下或回执不确定时不能报未发送。优先有界独立场景、实测时序及原回执；未命中明确保留缺口，不刷次数获取通过。
6. 不采纳“没有draw_region就一律不判新增完成”：画布候选缺失不代表原图视觉验收无效，会形成新增过度防护。新增证据必须来自本轮基线/最新原图及实际任务事实；几何候选只是接地辅助，不能把其缺失当通用观察失败。

前两轮只汇报与审查，没有将讨论建议写成已经实现。后续最小变更应明确职责：桌面桥提供真实几何/输入落点，规划层解释坐标与目标，控制器保留本轮基线/逐步进展，验收层判目标，轨迹层呈现事实；不在通用运行时加入Paint专用模型动作。
