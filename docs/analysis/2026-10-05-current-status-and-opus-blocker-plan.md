## Opus讨论与主会话决策

已通过coolzhuagent真实`claude-opus-5-5-high`会话只读审查最新438f6ec源码快照；源文件3823项，manifest SHA256为`9593618ca49592539b91ca75b9fad7d38ade31c03c7ea76144a5acf78beaaaca`。第一轮实际宿主只读调用36项（read17/grep17/glob2），不是模型自估32；requested/effective精确一致，end_turn且进程排空。原始最终回复和收据见[Opus审查](2026-10-05-devin-blocker-review/opus-blocker-review.md)。没有把只读审查当实操通过。

主会话已反馈以下修正，并取得同一真实模型的第二轮回复。第二轮实际只读12项（read5/grep7），两轮共48项；两轮均end_turn且排空，没有CU动作。第二轮原文见[阻塞讨论](2026-10-05-devin-blocker-review/opus-blocker-discussion.md)。模型的自估调用数与宿主台账不一致，以收据为准。

- **采纳方向**：明确客户区与绘图区、新成果的结构化声明、本轮基线、真实输入落点反馈；核实际UIA候选再决定最小实现。
- **需要修正**：保留原坐标/FrameRef兼容，不整体替换points解释；Document/Image匹配不等于语义绘图区可信；近白矩形只作为候选，不做硬几何权威。
- **不采纳**：晚于up关闭算竞争通过；ReleaseUnknown算正常通过；先Paint后Browser；在聊天新增工具调试卡片；依据两次失败就自动认定纯模型能力。
- **保持**：精确模型、根预算、一次派发、取消收尾、实际释放与来源世代、未知不重放。没有事实支持的保护简化低优先处理，不全面删除守卫。

第二轮已确认Browser优先、未知不算正常通过、关闭晚于释放不能算竞争、旧坐标兼容和基线/逐步进展分离。主会话继续复核外壳源码，得到以下更精确的边界：

1. `native_browser_input.rs:213–222`在同一UI闭包中顺序排队按下/释放，不等按下回调再释放；同线程其它命令无法插在这两次入队之间。但浏览器异步处理仍存在区间，不能推断所有网页事件也不可交错。
2. `browser_panel.rs:511–530`关闭撤销原资源后走`retire_view`；`native_browser_input.rs:39–44`先隐藏、等待执行门再实际关闭。**隐藏与资源撤销可以在途发生**，仍需真实回执和下一轮验收。
3. `browser_panel.rs:686–713`同scope页面导航受PanelStore命令门控制，没有在该分支领取输入execution_gate；目前这是页面替换在途风险的源码依据，**是否造成新文档错投尚未实测**，不能直接宣布已发生事故。
4. 第二轮未读的`main.rs:1270 existing.close()`已由主会话核实是`EXTERNAL_BROWSER_LABEL`独立浏览器窗口，不能当右栏关闭路径漏洞。
5. 不采纳第二轮“每项约20次”机械重复和“网页事件不成对必为NotDispatched”的建议：已按下或回执不确定时不能报未发送。优先有界独立场景、实测时序及原回执；未命中明确保留缺口，不刷次数获取通过。
6. 不采纳“没有draw_region就一律不判新增完成”：画布候选缺失不代表原图视觉验收无效，会形成新增过度防护。新增证据必须来自本轮基线/最新原图及实际任务事实；几何候选只是接地辅助，不能把其缺失当通用观察失败。

本轮只汇报与审查，不将讨论建议写成已经实现。后续最小变更应明确职责：桌面桥提供真实几何/输入落点，规划层解释坐标与目标，控制器保留本轮基线/逐步进展，验收层判目标，轨迹层呈现事实；不在通用运行时加入Paint专用模型动作。

最终执行排序为Browser边界闭环 → Paint接地/新成果与完整绘画 → 收敛新包及正式CU联合回归 → DSH市场 → 动画、界面与所有右栏入口总回归 → 总体审核与PR准备。PR #78继续草稿，不自动合并。
