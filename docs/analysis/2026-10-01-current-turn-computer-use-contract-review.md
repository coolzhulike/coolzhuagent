# 本轮 Computer Use 参数契约审查

## 触发问题与证据

0.2.55 正式安装版中，BU055-REOPEN-BU 请求只点击一次并给出完整参数 JSON，实际模型却生成 BU054-CLOSE-BT 的“点击到 10”目标。入库的新用户消息完整，实际工具参数是旧目标；累计发生 3 次点击后正常中止，CU 为 cancelled、父运行为 interrupted。原记录保留，不将中止算作功能通过。证据见 release-0.2.55/installed-native/BU055-REOPEN-BU-facts.json 和 03-reopen-bu-extra-clicks-aborted.jpg。

代码检查显示，当前用户消息在历史投影后独立追加，OpenAI 兼容协议逐块保留其正文；已有历史边界提示不能保证模型遵守。没有保存完整网络请求正文，因此不能把代码检查称为对实际网络正文的逐字核验。原工具准入只校验当前选择的原生浏览器和只读权限，没有核对本轮明确参数与模型参数是否一致。

## 最小实施方案

接纳前，从原始本轮正文冻结 ComputerUseTurnScope，随后放入父运行。不能使用拼接引用历史后的 user_content，也不能使用仅保留 220 字的引用摘要。原生浏览器绑定、会话归属、安全资源、权限和取消链路保持原职责。

当本轮明确写出 computer_use_perform（兼容旧点号名），紧随明确参数标签，并包含单个合法 ComputerUseRequest 对象时，冻结该对象。执行器在任何适配器观察或原生输入之前，对模型提交的完整协议对象做等值核验。目标、对象、成功条件或约束被修改即 current_turn_computer_use_request_mismatch，retry_owner=none；保留拒绝记录，不改写模型参数，不隐藏补发动作。协议默认字段正常反序列化，不要求 JSON 键顺序一致；字符串与数组仍严格对应用户明确参数。

该核验放在既有验证条件归一化之前，避免归一化使原始契约失真。没有明确单个参数对象的普通自然语言任务继续沿用现有路径，多个合法对象的比较示例也不任意挑选为授权。此改动不是通用自然语言权限编译器，不能声称解决所有模型违反动作次数的问题。

## 风险与验收

- 用户明确提供参数时，模型即使只是改写语句，也可能被拒绝；这是明确参数契约的边界，错误反馈不包含用户完整参数。
- 不新建 Provider 层规则或额外数据库，不将浏览器前端耦合到模型目标解释器。Scope 使用共享不可变对象，不复制大型参数正文。
- 仅增两项不调用模型的准入边界检查，用于验证同一浏览器上的旧目标也拒绝，以及普通 JSON 不创建契约。真实模型验收仍为 qwen3.8-flash 和正式软件截图，不使用模型夹具替代。
- 正式 0.2.56 验收保留同一聊天室历史：关闭后自动重开网页，最新单击任务参数与本轮一致，实际计数 0→1，工具回执和截图对应。若模型仍提交旧目标，必须零输入拒绝，并继续记录为执行未通过。
- 浏览器通过后，再做真实 Paint 连续多点闭合笔画，并联验全桌面泛光提示；不以直线或单纯 released 代替闭合矩形。
