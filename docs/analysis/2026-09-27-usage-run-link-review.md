# 请求用量与执行轨迹关联补审

日期：2026-09-27。审查对象为后续分支源码，不代表已安装的 0.2.17。

## 已确认的问题

`chat_usage_events.turn_id` 原来保存供应商调用内部追踪标识，而轨迹页按 `runtime_runs.legacy_turn_id` 的公开聊天轮次标识读取。两者不同，导致父请求、子 Agent 或工具反馈的用量在单轮轨迹中遗漏。房间统计按工作区、房间及会话聚合，不能据此认定总量也漏计。

## 主会话与 Pro 收口方案

在现有事实表增加可空 `run_id`，由接纳时冻结的执行上下文写入；保留原 `turn_id` 和事件唯一性，不增加第二份账本。轨迹优先按 `run_id` 关联，同时限定工作区和房间。历史空值仅接受明确的公开轮次关系，或 `call_id → tool_calls → run_id` 关系；使用 `EXISTS` 避免重复，不按时间、相邻记录或当前房间猜测归属。

GPT-6 Pro 的审查位于聊天“整合审查执行计划”，轮次 `63b1b969-0eb4-4db1-ad8a-415b166cc9b1`。其建议单独引入 `child_run` 是通用结构建议，不是当前代码事实；本轮仍按既有父执行归属记录子请求，不为此次修补新建子运行框架。
