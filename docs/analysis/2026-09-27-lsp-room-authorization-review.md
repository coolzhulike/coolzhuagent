## 0.2.20 原生复验：工程存储键误用于请求身份

安装窗口从工程下拉切到隔离工程 A、打开 `src/main.rs` 后，点击启动返回 `409 工作区已切换，请刷新后重新启动语言服务`，见 `docs/testing/release-0.2.20/installed-native/02-lsp-start-409-after-workspace-switch.png`。该失败先于权限检查，不能据此认为聊天室授权已在原生路径通过。

主会话只读定位到 `startLspPreview()` 使用 `activeWorkspaceKey` 填充 `expected_workspace`。但 `updateActiveWorkspaceKey()` 的调用方先经过 `composerDraftWorkspaceKey()`，其返回值为 `encodeURIComponent(raw).slice(0,180)`；这是草稿/布局存储键，不是服务端 `display_path(canonical_workspace)`。此前直接 HTTP 夹具提交真实路径，因此没有覆盖此接线错误。

最小修正：从同次捕获的 `projectRequestScope().workspace` 取得真实工程路径，用于启动提交和存在性检查；保留布局键、工程代次、Agent、房间、文件与启动序号的迟到响应校验。不能对已截断存储键做解码恢复，也不能删除后端身份校验或用当前服务端路径替代调用方的预期值。代码与执行交 GPT-6 Sol Max，后续候选需重新编译、打包并原生复验。

针对性验证只补真实前端请求体这一缺口，覆盖含空格/中文以及超过存储键长度的路径，并确认缺工程和迟到响应仍拒绝。刷新页面不会修复该源码错误。0.2.20 本项保留失败，后续通过必须绑定新包身份。
