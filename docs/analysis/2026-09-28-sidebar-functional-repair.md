### 插件与 SKILL 的实施决策（待实现与验收）

管理接口集中到独立模块，复用 `PluginManager` 的安装事务、注册记录和启停能力，构造规则与 CLI 的 `ConfigLoader::default_for(workspace)` 保持一致。工程切换后必须按新工程读取；写入请求携带预期工程，旧界面不得写入新工程。技能详情只读取当前枚举得到的文件，不开放任意路径读取。

### 原生浏览器重定向回原地址的后续修复

桌面浏览器已有连续导航保护，但原状态用 `pending_previous_url == page_url` 排除旧页面事件，也会排除合法的 A → B → HTTP 302 回 A：WebView2 的 `NavigationStarting` 能报告 B 和重定向后的 A，而 `ContentLoading` 可能只报告最终 A，故地址栏会停在 B 且加载状态无法收尾。

后续源码修复给同一网页视图的导航命令分配 revision，仅在该请求的 `on_navigation` 先观察到 B、随后观察到允许的重定向终点 A，且 `ContentLoading` 报告 A、WebView 当前 URL 也是 A 时，才把 A 接为新页面。重定向的 `NavigationCompleted` 不能单独清掉待处理请求，防止旧 A 的迟到完成事件提前结束 B。连续导航的新命令会替换旧 revision；命令返回晚于页面事件时也不能写回旧地址。桌面壳离线构建通过；此修复尚未进入已经生成的 0.2.24 安装包，亦未由原生 UI 验收。

剩余边界：Tauri/Wry 的页面加载回调未向此层提供 WebView2 `NavigationId`，URL 与请求 revision 不能在极端事件交错下构成原生导航身份的完全证明。Luna 后续需用独立本地测试页验证 A → B302 → A、B → C 的普通重定向及快速连续导航，核对最终地址、加载状态和历史/表单保持；本批不重新打包、不占用其原生测试窗口。
