# 2026-09-26 文件、MCP 与 OAuth 小范围审查决策

来源：[整合审查执行计划](https://chatgpt.com/c/6ab013c6-8dc4-83ea-a220-a33c9940783f)。这是实施代理整理的决策摘要，不是 Pro 原文，也不代表功能已经验收。

## 文件条件写入

代码核查发现：原 `read_file` 无内容版本，`write_file` 可未读覆盖，`edit_file` 描述唯一匹配却实际替换第一处，写入使用直接覆盖。采用原字节 SHA256、`expected_version`、产品跨进程互斥、同目录临时文件同步后原子发布。

- 已有文件缺版本或版本改变则拒绝；模型需重新读文件并重新评估修改。
- 新文件未提供版本时只允许不存在的目标，不能退化为覆盖。
- 默认 edit 多匹配拒绝；用户明确 `replace_all=true` 时仍允许全部替换。这是对 Pro 泛化“多匹配拒绝”的兼容收紧，保留原协议的明确意图。
- 读取部分内容仍返回完整原始字节版本，保留 BOM/CRLF 的版本差异。
- 发布前再检查内容。产品锁不能约束外部编辑器，不能宣称消除检查与替换之间的全部外部竞争。
- 不建设文件事务数据库，不将原子替换当成版本校验的替代。

已执行的低层验证：core 文件操作 5/5、工具注册真实读写编辑 1/1 通过。此结果不是最终桌面 UI 验收。

## MCP 进程与协议

复用现有 Windows Job 监督。进程挂起创建、加入 Job 后再恢复；正常关闭进行有界收尾，随后回收整个 Job，Drop 仅做兜底。协议头累计 16 KiB、帧 8 MiB，必须在分配缓冲区前验证长度；重复长度、错配响应 ID、半帧错误污染该流，禁止继续复用。不得只杀直接子进程后声称整个调用已停止。

## OAuth

只扩展 OAuth 保存字段：Windows 用户域 DPAPI、格式版本、凭据 revision；其他字段及来源优先级保留。旧明文成功读取后，只有密文原子发布成功才能替换旧值。凭据文件短写锁与刷新锁分开，刷新前复查版本，返回后条件保存，登录/注销改变版本后旧刷新不能覆盖或复活旧令牌。

DPAPI 保护不等于抵御同一用户的恶意程序，也不保证复制文件到其他设备即可恢复。非 Windows 的 0600 仅是文件权限保护，必须明确区别。此模块不自动证明模型配置中的 API Key 已迁移，统一配置的秘密引用仍需单独接线和验证。

## 长输出与附件

长工具结果保存原文、SHA256 校验与受控定位信息，模型只收到节选；保存失败保留业务原结果并单列保存失败，不能改写工具执行事实。字符分段按 Unicode scalar 计数，不按 UTF-8 字节硬切，解决单行 JSON 反复完整读取的问题。

定位路径必须由冻结的运行存储位置和宿主生成的内容摘要建立，并经过原有读取权限核对；不接受模型提供任意保存路径，也不把摘要视为访问授权。原文发布前后均核对摘要。附件沿用旧 URL 读取，新对象增加内容寻址和摘要核对，不批量搬迁历史文件。

附件引用图尚未覆盖所有 Goal、导出、待发送对象时，GC 只登记候选，不自动删除。原来的消息删除联动磁盘删除需要停用，报告删除数量为零，不能把候选数量冒充实际删除。
