新增独立 `modules/tooling/packages/dsh-plugin-host`，使用17个固定官方依赖加载工具模块、提取真实工具清单、执行与释放。Core新增 `dsh_host_process`，复用 `managed_process::ProtocolChild` 的既有Windows Job、根取消和截止控制；不在Core做市场下载或模型循环，也不在Node做权限批准和记忆管理。该代码尚未接入Web插件目录、正式MSI与真实Qwen请求，状态为P3进程底座完成、产品接线未完成。

## 风险与取舍

1. 单次执行资格在首个await前保留，避免来源校验期间并发抢入；dispose先撤资格和触发真实AbortSignal，再有界排空并释放真实子fiber。已用同一真实计算器核验并发拒绝、校验期间停用及服务清空。
2. 原始stdout不承载IPC；私有调用目录的nonce与workspace/room/run/call贯穿握手、执行、取消和终态。JSON均256KiB有界、原子发布；未知身份拒绝。取消优先，迟到成功不复活调用。Windows Job终止子树，不以发送kill冒称已退出。
3. 新进程世代不能沿用目录查询的已结束宿主世代。跨进程冻结来源修订、真实包身份和完整工具定义；随后执行命令使用本次live握手世代。这允许一次性进程保持明确职责，同时拒绝旧包换内容但版本号未变的情况。
4. 根取消/截止不会因子进程新建而重开；Node协作AbortSignal加Rust1秒收尾上限。现有计算器立即返回，本轮验证预取消；**执行中的插件忽略取消及孙进程收尾尚未用远程真实插件实操**，不能由预取消追认。
5. 子进程不继承模型环境密钥或Node预载脚本；只保留系统和临时目录。Node与用户同权限，不是OS沙箱。第三方代码仍可产生外部副作用；Job收尾不回滚该副作用，工程cleanup_confirmed仅表示受控进程树已回收。
6. 宿主仅支持已验证tools依赖。目录兼容检查必须不执行模块；仅显式启用后可加载以取得真实注册工具。安装器尚需全树来源和SDK产物身份、事务锁/恢复、来源认证、默认停用及相应页面。
