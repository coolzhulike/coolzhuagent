# coolzhuagent 整合改进：Opus 源码审查后的执行计划

本计划由主会话依据真实 Devin claude-opus-5-5-high 审查和直接代码核查整理。原始报告独立保存，不把模型建议直接当成已证实缺陷。仓库读取使用固定完整源码快照；架构覆盖不等于逐行阅读所有文件，更不等于 Browser/Paint 已通过软件验收。

## 当前事实

- 当前分支已含主线 PR72/77，原用户工作区的未提交改动没有被覆盖。
- 登录账号目录与应用发现结果实际都是721个精确ID，集合差异0；Opus High统一配置、两份摘录审查和源码审查已真实完成。
- MCP只读桥接线成功：模型真实读取、搜索仓库；客户端提出2025-11-25，服务返回并使用2025-06-18，鉴权保持。
- 第一轮源码审查65次只读调用，第二轮60次，第三轮22次，合计147次，宿主均完成且结果ok。第三轮报告列出17个指定入口的读取与未深入实现，实际覆盖范围见各轮报告；不是全仓逐行审计。
- ACP每轮新远端会话、宿主提供已组装历史，避免远端load加宿主全量历史双重注入。
- Browser/Paint执行接口已存在。新的关键阻塞是模型子请求只走HTTP：computer_use_planner.rs的request_model调用provider_client_for_agent，后者require_http拒绝Devin；仅开放MCP工具名字无法接通真实规划和验图。
- 0.2.69已构建包不包含本轮只读桥，正式安装版尚不能沿用开发服务成功结论。

| 事项 | 决策与理由 |
|---|---|
| 工具指南与真实能力不一致 | 已修ACP专用工具指南；不继承HTTP的写文件、命令和CU指引。真实执行仍以MCP目录和宿主回执为准。 |
| MCP协议协商 | 已修并真实验证，保持Host、Bearer和Origin门禁；不以删鉴权解决握手失败。 |
| readonly路径 | 已限定当前工程，glob模式补绝对路径和..检查，复用已有搜索边界规则。 |
| 保存只读白名单扩权 | 已修；保存其它参数保持载入的合法工具子集，新启用审查才采用默认三项。 |
| 原生工具仅靠提示词禁用 | 不采纳这个断言。CLI controlled_config 已 deny 原生文件/命令工具，宿主 denied_client_request 对权限请求返回 cancelled。模型看到工具清单不等于工具可执行；内层规划仍复用这些强制限制，并需补真实拒绝证据。 |
| 只读审查产生工具结果文件 | 属于宿主运行产物，不修改源码；指南和报告明确 .coolzhu/tool-results/台账写入，不把只读表述成工作区零写入。 |
| 初始模型配置校验 | 可以拆开“找到请求可用选项”和“确认最终生效模型”的职责；最终requested/effective精确比较保持。原首次错误没有当次完整投影，不能断言其具体根因已确认。先使用新安全回执核对。 |
| CLI哈希、版本及目录缓存 | 不直接按路径/mtime永久缓存，更不接受任意新版本开关。优化前需明确文件身份、账号、版本、失效条件和真实验证；当前先保持可信CLI与精确模型确认。 |
| ACP与Devin Cloud | 两条协议和认证分别保留。Cloud远程任务不能借用CLI账号模型目录或混用凭据，也不能冒充本地会话工具执行。 |
| HTTP规划会话替代Devin | 不采纳默认换模型方案。用户已指定后续执行用Devin SWE-2；审查用Opus High。规划请求服务应支持ACP，不静默切Qwen。 |
| Browser和Paint同一轮混用 | 当前分两轮验收，暂不扩有序跨资源序列。避免为了验收扩大工具授权范围。 |
| stale恢复 | 保留“确定零输入才可重观察”；多步任务的有限恢复应由现有重规划预算控制，不因一次恢复永久禁用后续零输入恢复。无回执不等于未发送。 |
| Paint预算 | 使用通用任务预算和根预算，不在核心硬编码mspaint特权；预留验图余量，按实际剩余时间确定笔画数。 |
| 遗留输入隔离 | 只能根据资源和实际输入释放事实收敛。已知其他资源可分离；资源未知时不能猜一个scope自动放行。完全访问覆盖普通工具审批，不能伪造按键已释放。 |
| 审批状态 | 审批记录需要具体call、参数摘要、父运行及owner/epoch；完成后根据真实终态撤除提醒，不把所有失败都展示为“待人工复核”。当前只读桥不承担写操作审批。 |

## 阶段一：会话请求服务与ACP子请求

目标：同一已配置Devin会话可发起内部规划/验图请求，不走HTTP ProviderClient，不递归触发宿主工具。

1. 在web-console增加薄的会话请求服务，按AgentSessionBackend分发。HTTP分支继续使用既有客户端、请求用量记录和响应；ACP分支复用SessionService、受管进程、精确目录/模型确认。不要把协议分支散入每个controller或native适配器。
2. ACP聊天室流和内部一次性completion共用进程/协议生命周期，分别组装内容。内部请求不加载聊天室远端历史，不挂MCP，不开放原生工具；返回真实文本/用量/停止事实，工具通知不能被当成内部规划结果。
3. 从已接纳父运行派生内部请求身份，绑定同库父运行、根预算、取消令牌和真实request kind。每个请求有独立attempt；未知失败不自动重发，迟到结果不得成为新动作。
4. 将CurrentSessionComputerUsePlanner.request_model切到该服务，保持既有JSON解析、动作接地、响应身份、预算与诊断。模型ID仍为用户选中的Devin会话，诊断同时记录后台类型和精确生效ID。
5. 增加初始化能力的安全投影，真实核对promptCapabilities.image。协议支持图片不等于该CLI/账号/模型已通过验图，缺省按不支持处理。图片只按协议的image/mimeType/data发送，不包装成文本冒充视觉输入。

官方依据：[ACP初始化能力协商](https://agentclientprotocol.com/protocol/v1/initialization)、[ACP内容类型](https://agentclientprotocol.com/protocol/v1/content)。图片输入要求image能力，遗漏能力视为不支持。

通过标准：真实SWE-2单次文本completion有requested/effective回执、父请求台账、end_turn、受管进程排空；停止/超时后无后续动作。图像另用用户授权的验收截图实测，并记录是否真能识别目标；不能以命名推断多模态。

回退：文本可用而图像不支持时，先完成Browser的结构化只读能力；Paint保留为明确阻塞，不静默换模型。若采用既有默认视觉模型描述路径，必须独立记录视觉请求、模型、费用和结果，且保留原始画面/坐标接地要求。

## 阶段二：Browser Use优先闭环

目标：从正式Devin聊天室调用已存在的内置浏览器执行链，并保持来源页面、资源身份和输入释放事实。

1. 阶段一真实规划通过后，按会话参数显式开放computer_use_perform；只读审查模式与操作模式分别选择。继续复用原父预算、监督执行和工具台账，不从远端tool_call通知构造执行权限。
2. 接入既有execute_in_room与native-browser协议。只读任务不得规划点击/输入/滚动；用户否定约束仍由范围解析和执行策略共同约束。
3. 先完成普通只读与交互验收，再验证取消、面板关闭/页面替换的真实竞争边界。面板身份或epoch改变必须使旧动作失效；仅“关闭时动作早已结束”不算竞争通过。
4. stale恢复仅允许明确匹配当前动作的NotSent+NotNeeded回执；MayHaveBeenSent、ReleaseUnknown、回执不匹配立即终止。恢复次数仍由已有重规划上限控制。

真实验收矩阵：

| 场景 | 通过证据 |
|---|---|
| 只读网页，明确不点击/输入/滚动 | 真实模型给出页面内容；原浏览器截图；输入台账为零。 |
| 点击→填写→滚动→导航 | 同一真实页面中的可见结果、动作/页面身份、每次输入释放回执。 |
| 输入down/up之间取消 | 取消命中真实区间，释放完成，父轮终止，无后续动作。 |
| down/up之间关闭面板或替换页面 | 时序确实覆盖输入区间；释放/拒绝事实完整，旧资源动作不继续。 |
| 完全访问下普通操作 | 不出现无依据的人工复核；未知释放仍按真实隔离处理。 |

测试使用正式安装版截图，真实SWE-2；工程契约测试只能支持判断，不能替代以上实操。

## 阶段三：Paint与电脑控制提示联合验收

1. 先观察正确Paint窗口及真实画布。优先UIA画布语义；fallback不能把整个client区或所有Document/Image一律当画布。窗口身份、画布矩形、截图generation和DPI映射共同接地。
2. 保持最大化，只有最小化窗口才恢复；聚焦不能改变已有布局。每笔前观察足够新，确定零输入stale可有界重新观察。
3. 通用绘图任务预算容纳完整简化人物：轮廓、眼睛、嘴、衣裤、手脚；按笔画/规划/验图消耗预留验证时间，不能画两三笔后预算耗尽仍报完成。
4. 复用Windows四边泛光及顶部“Coolzhu Agent is using your computer”指示。提示生命周期跟实际输入控制任务绑定：开始出现，结束/取消/异常收尾后撤除，不挡住画布。
5. 软件验收用真实SWE-2，模型应报告画布与实际结果。保存完整人物截图、绘图期间提示截图、结束撤除截图及Released回执；不追求专业质量，但不能空白画布或缺完整结构。

失败分类分别记录：画布/坐标错误、图形规划能力、预算耗尽、输入前stale、输入释放未知。不能都归为模型能力，也不能为通过测试伪造释放事实。

## 阶段四：正式界面、安装与报告

1. 保留卷轴金玉Logo、竹林背景、足够文字对比；左侧首页/定时任务/设置/统计/微信/更多/升级，更多包含浏览器/终端/SKILL/插件市场。微信原功能不测试。
2. 配置页只做当前模型会话连接/参数；TTS/STT、工具审批不挤入此页。发送对象只保留复选框。工程/聊天室切换、设置加载、模型发现、统计都需无Failed to fetch真实截图。
3. 内置浏览器保持干净URL栏；复杂页面在独立无宿主权限WebView内正常显示。文件/图片/视频/网址从聊天内容进入右侧栏；插件市场对接DSH目录，并区分可浏览与可安装能力。
4. 思考/工具活动只在进行中展示1–5行，完成后归档轨迹；消息搜索/定位、轮耗时、真实token用量保留。正式前端不显示构建调试信息、原始门禁标识或占底边的诊断条。
5. 方案B开机动画需实际看到Q版人物舞剑、Logo和可感知停留。源码中存在6500/7800ms配置不等于验收；用正式启动窗口的连续姿态截图/录屏确认，资源加载失败或减少动态快速跳过要单独记录。
6. 稳定后冻结输入、重编译、构建新版MSI，核验source/build-input/payload/安装版本；不把0.2.69旧包当本轮功能版本。安装后复测关键链路，交付可供其它模型设计测试用例的变更及未完成项报告，推送当前PR，不自动合入。

## 尚需核实、暂不盲改

- 初次ACP模型配置失败的原始投影缺失；新回执解决未来取证，不能重建历史。
- launcher仅凭进程名识别CleanupKnownHolder是否会终止无关监听者，需要精确所有权核查。
- WindowTarget 的无 .exe 记事本推断可用标题/类名匹配，已读到路径；后续收敛到真实可执行文件身份，并验证标题伪匹配拒绝，不能仅以 Paint 显式目标覆盖其它路径。
- SKILL/插件快照、上下文压缩调用链和遗留审批需具体路径审查，不能仅grep未命中就宣称没有实现。
- 工具台账unknown与not_executed的区分需执行边界证据；不能只凭Drop路径文字批量清除隔离。
- 全模块入口覆盖后的内部实现盲区在各轮报告保留。没有实操证据的UI/Browser/Paint项目维持未验收。
