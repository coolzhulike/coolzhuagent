# 普通编辑框聚焦与动作反馈补充审查

触发证据为048-AX：两个真实click、零text_input、页面仍为空，随后no_progress；048-AY真实导航通过。不能把输入失败称作权限不足或宿主文字派发失败，也不能凭此认定模型能力不足。

当前链路宿主AX投影只保留role/name，整个properties被排除；这是隐私保护的正确默认，但普通输入必须先click聚焦，规划观察缺乏进入下一动作的事实。上一动作反馈没有类型，模型无法明确区别一次真实focus click与文字动作。

采取小范围补充：协议增加可选focused_node_index，只接受已登记textbox/searchbox节点；宿主只采集AX的focused=true布尔属性，歧义或缺失保持未知。索引映射到新elements引用的focused布尔值；不转发原值、选区、其它AX属性或backend ID。模型提示解释聚焦只是准备，需选择text_input；执行时仍由EditorState重新核对真实activeElement、普通输入类型、原值与选区，再走两阶段授权。新增字段不授予权限、不构造动作、不降低失败标准。

步骤反馈从原action_type列解析白名单ComputerUseActionKind；未知历史值为None，不传自由字符串，不新增表或迁移。模型能知道上一步真实动作种类，目标完成仍以最新页面实际内容判定。焦点变化不计为文字任务完成或可见进展，不提高no_progress阈值。

风险：AXfocused不证明可编辑或可见，因此不替代执行前守卫；旧宿主缺字段仍可反序列化，不能默认真；多个聚焦编辑节点不作选择。工程编译与既有隐私检查只证明接线与契约，必须后续正常安装新包、原Qwen实际click→text_input并以回显截图验收。
