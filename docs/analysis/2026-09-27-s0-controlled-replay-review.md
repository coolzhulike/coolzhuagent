## 核查事实

`tests/fixtures/s0-golden/manifest.json` 的六类是流式工具配对、非流式工具配对、图片路由、空总结、跨轮过滤和长文件任务。当前清单主要包含合成事件分类和调用 ID，`recorded-only` 是元数据。静态契约核验以及假模型协议连接测试不能证明六类各自经过真实 Web 接纳、工具反馈、落库终态和副作用核对。

后续已有图像转述、工具失败后的空回复、长文件历史裁剪及 CLI/Web 子 Agent 对账等相邻实测，保留其价值和对应版本，不将它们拼接为本清单六项完整回放。Paint R1–R6 属于另一组历史失败资料，缺失的提示、UIA、几何与标签不能补造。

GPT-6 Sol Max 的逐项只读审计保存在本机 `tmp/2026-09-27-golden-coverage-current-audit.md`。该审计未发现新的确定产品缺陷，不能据此阻止本次视觉/LSP 局部候选；但 WBS 0.2 及 32 包整体完成仍不可宣称。

## 实际 Pro 审查

主会话向原“整合审查执行计划”会话发送上述事实和最小测试驱动方案，并实际收到《Desktop04 S0 验收缺口窄审查（不影响 021 冻结）》回复。对方认可在测试设施层使用共享驱动，复用产品真实 Web 接纳、工具派发、轨迹和 SQLite，避免另一套 Agent 运行器。原始页面文本与回执留在本机 `tmp/2026-09-27-pro-s0-controlled-replay.*`；公开文档不带私人聊天地址。

采纳：场景清单、隔离环境启动、结果断言三部分共用；使用本地假模型、随机端口、独立临时工程与数据库。流式及非流式工具场景须实际派发并收到工具反馈，不直接填入工具结果来制造成功。长文件须核对文件事实和边界，图片须分别核原图与转述请求、用量和归属。录制来源明确称为“新受控录制”，不称历史用户回放、云模型验证或 Paint 实验。

主会话校正两条容易过度解释的建议：

1. 跨轮断言排除的是内部审计、隐藏条目及按现有规则应裁剪的临时长输出。合法用户历史及符合协议的工具配对不应被一概禁止；按 `chat_tool_history.rs` 和实际 provider payload 判断，不照抄“所有前轮工具结果都不能进入下一轮”。
2. 假模型发送前的指纹/参数/临时路径白名单是**测试回放边界**。它不能证明正常产品具有同样的白名单执行沙箱，也不能把测试代理拒绝描述成产品权限拒绝。

## 本轮执行范围与出口

先在 `tmp/s0-controlled-replay-20260927/` 完成可执行原型，使用已构建 021 release Web 的独立副本；只写该临时目录和指定测试报告目录，不改产品、Cargo、正式 tests/scripts/config 或 CI。先跑最小完整工具场景，再扩展六类，记录实际二进制哈希、请求、调用结果配对、run/turn、终态、provider payload 和受控文件变化。

副作用只允许命名的临时文件与隔离数据库；测试代理在向产品返回工具调用前检查固定指纹和参数。最小负例覆盖未登记指纹、参数偏移、超临时路径范围，负例哨兵也只能位于另一个命名临时目录。缺 final 与跨轮污染通过真实结果断言识别，不能以固定成功响应代替。不得触碰 8765、原用户工程、密钥、输入安全库或原生桌面。

发现新产品缺陷时先报告具体复现，不修改冻结源码。原型通过后再决定正式测试设施与 CI 接入；原型通过不等于已具备 CI 门禁，也不等于 WBS 0.2 全部关闭。现有静态清单保留作为协议说明。用户要求的原生实操截图仍由安装验收提供，本项只补接纳和请求边界证据。

## 执行中的事实校正

最小流式读取已经过 021 release Web 的真实聊天入口、`read_file` 派发和模型工具反馈请求；终态及持久化配对仍按实际字段核对，不只凭回复中的成功标记判定。

非流式原样回放发现旧 manifest 的 `list_directory` 不在当前真实聊天暴露工具中，工具调用表为空；文本恢复也不能制造该工具已经执行的事实。保留原样失败，不向产品增加同名工具迎合旧夹具。新的受控录制以当前 `glob_search` 的真实参数验证目录查询和非流式往返，明确标记来源 ID 与实际工具名的映射：这可覆盖原行为目标，但不是历史清单逐字回放。

初始临时工程、SQLite、会话 JSON 与工具审计已隔离，但结构化日志追加到了用户 home 下既有诊断日志，说明仅隔离 cwd 和运行目录不足。执行代理只核对路径与元数据，未读原日志内容或删除该文件；不能仅凭这些事实证明当时没有其他 home 配置读取。后续驱动将 `USERPROFILE`、`HOME`、`CLAW_CONFIG_HOME`、`APPDATA`、`LOCALAPPDATA`、`COOLZHU_RUNTIME_DIR` 和 `COOLZHU_LOG_DIR` 显式指向临时目录，在服务 ready 后确认日志确实落于该目录再执行场景。前两轮保留原始记录，不称为全路径隔离成功；正式结果需使用修正环境重跑并记录实际目录与收尾事实。
