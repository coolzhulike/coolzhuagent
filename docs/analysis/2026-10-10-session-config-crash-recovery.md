# 配置文件与会话库的崩溃恢复候选

原统一配置保存先发布 `coolzhu.toml`，再更新会话 SQLite；同进程失败虽有回退，但两步之间进程退出会留下参数与会话不一致。本次复用原库 `metadata` 添加单条 `session_config_journal` 操作日志，不创建第二套会话或凭据。

保存持有原会话锁与配置锁。先把操作 ID、旧配置、新配置和未提交状态写入原 SQLite，再原子发布 TOML。两份配置使用已有 Windows DPAPI 保护整段文本，日志错误不输出内容。会话事务写入数据时同时把相同操作标记为已提交；全量会话保存保留该日志。成功后更新内存配置并清理日志；失败按未提交状态恢复旧配置。提交内部不生成会重入配置锁的 DTO，普通会话更新在持久化后生成响应。

启动及工程切换先取得原库写者锁，然后恢复日志，再加载配置和启动任务。未提交操作恢复旧配置，已提交操作保留新配置。恢复再次执行结果相同。当前文件若既不是旧内容也不是新内容，保留独立编辑及日志并报错，不把未知配置覆盖。日志尚未解决时拒绝其他配置发布与普通会话缓存保存。

验证证据：

- 初版 `cargo build -p coolzhu-web-console --offline -j1` 实际退出 0，1分34秒；后续锁重入审查修正需以最终构建日志为准。
- 首次专项测试编译失败：测试模块漏导入 `rusqlite::Connection`，失败日志 `tmp/analysis-config-journal-tests.txt` 保留。
- 修正后专项实际退出 0，7项测试通过，其中两个为仅子进程执行的探针；有意义的父测试覆盖事务回滚/提交、突然退出、重复恢复、外部修改保护，以及原配置服务保存。日志 `tmp/analysis-config-journal-tests-retry.txt`。
- 突然退出测试启动当前测试二进制的独立子进程，在发布后分别于 SQLite 提交前后以退出码71直接结束，不执行析构；下一进程取得写者并检查配置及同事务数据是否一起恢复。仅操作临时库，不接触正式服务或真实模型。
- 最新源码最终构建及完整Web回归日志分别为 `tmp/analysis-config-journal-final-build.txt`、`tmp/analysis-config-journal-full-regression.txt`，运行终态后登记结论。最新服务用例还注入会话 INSERT 失败，核会话缓存、参数、版本与磁盘回退。

尚未完成：正式已安装软件的同协议升级、真实配置窗口重启恢复、断电/磁盘满/杀毒拦截矩阵、全部非Web写入来源与独立旧版本协同。突然退出测试不能证明断电持久性。非Windows继续沿用已有凭据保护行为，不宣称日志加密。当前旧0.2.127未使用新写者协议，不能由本候选推出混合版本单写者保证。

本候选只覆盖统一会话配置的参数加会话更新；其他配置和业务资源的跨资源事务仍逐项开放。32WBS整体不由此视为完成。

最终证据补充：完整Web回归实际0，1444通过/0失败/6忽略，66.33秒。随后补充日志路径绑定及写入错误却存在提交标记时保留日志的保护，最终offline build实际0/39.26秒，专项7/7实际0（含子进程真实服务保存及INSERT失败回退，0.37秒）。对应日志为tmp/analysis-config-journal-path-build.txt与tmp/analysis-config-journal-path-tests.txt。完整回归覆盖前述最终保护补充之前的源码，最终保护由专项复验，不把两者表述为同一源码的完整重复回归。
