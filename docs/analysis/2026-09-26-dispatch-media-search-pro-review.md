# 2026-09-26 执行登记、微信图片与历史索引审查

来源：ChatGPT「整合审查执行计划」，会话 6ab013c6-8dc4-83ea-a220-a33c9940783f。用户授权技术方案审查。本文件是决策摘要，实际代码和产品验收另记，不以审查同意作为已通过。

## 接受的最小方案

- 工具调用首次 INSERT 成功后才派发；登记失败零执行。相同 call_id 返回原状态而不再次执行，异主不得覆盖；迟到收尾只作用于原 run、工具名、输入摘要。
- 流式、非流式、接力复用真实接纳服务，创建 turn/run 并登记取消。relay 模型角色不是新的执行根，不能重置预算；超时先取消、有界收尾，不重放可能已产生副作用的步骤。缺 conversation session 时拒绝 CU，不伪造来源。
- 视频后台任务显式传递冻结的根预算；取消等待不等于工作者已经结束。已启动任务仍受监督，不能获取新的完整超时。
- 微信 provider 仅可信 CDN、有界下载解密并验证实际图片；SHA256 用作内容身份，不能冒充来源证明。sidecar 的 base64 有总量与单张上限；入站存摘要，联系人/聊天室授权后进入既有附件库和多模态路由。禁止后端任意 URL 下载和本地路径读取，拒绝跳转、非图片、超长内容。
- 10 万历史 FTS 是可重建派生物。冷建每 500 行短事务提交，查询前同步 dirty；未追平则扫描完整源表，不能用部分索引报告完整结果。

## 本轮发现与验证边界

登记失败仍派发、非流式缺真实运行归属、微信图片只有 metadata、FTS 冷建持写锁超过 busy_timeout 均来自源码或实际测量。对应补丁正在集成。验收需要数据库冲突不重复派发、真实 API 图片字节流、冷建并发消息写入、重启保留完整历史等结果；未运行项不得标为通过。
