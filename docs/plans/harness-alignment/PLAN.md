# Harness 对齐实施方案书 v2

初版日期：2026-10-17（America/Los_Angeles）。实施已启动，执行状态与验收结果以 [state.json](state.json) 为准。2026-10-18 补充 [HA-04 继续实施决策](HA-04-DIRECTION-2026-10-18.md)，澄清首个模型响应绑定及后续验证顺序，保留原有 60 条合同。

目标是在既有授权、取消、预算和执行身份约束内释放模型能力，减少错误提示、无收益的模型往返、重复确认及重复验证。沿用 coolzhu 的执行底座，以小批改动证明收益。普通任务完成必要工作即可结束，不因剩余预算进入额外角色或验证循环。

本方案依据 [GPT-6 Pro 审核原文](../../analysis/2026-10-17-gpt6-pro-harness-review-original.md) 和 [审核决策表](../../analysis/2026-10-17-gpt6-pro-harness-review-decision.md)，取代三方报告中旧版 T01–T08 的实施范围。Pro 审核的是固定源码包；下面的拆分、编号、实验数量与交接机制是本次工程细化，并非 Pro 已验证的实现或性能结论。

接替入口：[START_HERE.md](START_HERE.md)。逐条合同：[ACCEPTANCE.md](ACCEPTANCE.md)。证据规范：[EVIDENCE.md](EVIDENCE.md)。基线：[baseline.json](baseline.json)。

## 3. 不得退化的行为

1. 工具暴露、既有授权和当前执行资格分别判断。请求快照、摘要、模型回复和缓存均不能新授予权限。
2. 撤销被宿主接纳后，未开始的相关操作不能再领取执行资格。已开始的操作按工具能力取消并记录实际/未知效果；停止等待不等于效果撤销。使用现有登记、版本或局部同步明确先后，不跨人工审批、模型调用、长工具持有全局锁。
3. 同一个逻辑操作在断流、重连、post-hook 失败后先查询既有身份和回执。未知效果保持未知，不换 ID 重放；本地去重不宣称外部服务端到端恰好一次。
4. 原始人类输入及可信更新可延续任务；摘要、工具、子代理及合成 `user` 消息不能伪造授权。取消/完成的旧任务不会被摘要自动复活。
5. 验证通过必须有真实执行或适用检查证据。禁用、空命令、读取失败、未运行和模型声称完成均不算通过。
6. 保持模型及推理配置不变再比较 Harness；不靠降低 effort、少完成工作或跳过必要验证换耗时。

## 5. 每项实施说明

### HA-00 当前基线与调用链

查阅 `W/main.rs` 的真实请求构造、SSE 入口、工具预检与 Goal 门控，以及 `tool_dispatch_service.rs`、`tool_invocation_identity.rs`、`tool_dispatch_settlement.rs`、`scheduled_execution.rs`、`dispatch_hooks.rs`、`goal_command.rs`、`chat_tool_history.rs`、`session_config_service.rs`，补齐 Pro 包未覆盖的权限及执行收尾链。沿本项相关调用关系追踪，不通读全仓。

产出 `evidence/HA-00/current-gap-map.md`：四条后端路径、既有能力、真实缺口、修复/只补测/无须修改的理由、测试定位。确认当前审批合并粒度与一次/会话语义，不重复设计。保存可复现源码基线、相关配置、既有测试清单与实验材料；先运行确定性基线样例，按第 7 节采集模型基线或明确待运行位置。已有结论相符可复用证据，不复跑无关发布验收。

验收 HA00-01 至 HA00-04。工作包未验收前不得把“源码存在”当“运行保证”。无业务修改，无需回滚。

### HA-01 提示词最小化与实际投影

入口：`W/main.rs::AGENT_GUIDE_INLINE`、`agent_tool_usage_instruction`、`build_context_assembly_with_roster`、Goal 阶段提示；`A/providers/openai_compat.rs::translate_message` 及实际 provider 覆盖入口。

以少量确定性函数组装稳定规则、能力指导、用户目标和来源标明的资料。先梳理注入来源，再让通用规则只出现一次，Goal 只加阶段差异。CU 段依据最终暴露能力生成；没有 CU 时不出现 CU 操作要求。删除“最后 user 消息等于唯一任务”“所有多步任务先搜索/计划”的绝对指导，改为按目标与已有上下文选择必要行动。保留真实动作、来源、权限、取消与效果核实规则。

检查序列化后的 wire 消息，不用内部 role 名称证明信任隔离。后端可覆盖模板，但需走同样的来源和能力规则。允许保留用户明确要求的详细计划，不强迫简单内容任务先跑工具。验收 HA01-01 至 HA01-05。按模板/后端回退具体改动；不得恢复已确认的错误绝对断言。

### HA-02 活跃任务连续性

入口：现有任务/运行接纳、消息接纳、Goal 取消/完成、摘要恢复与 `chat_tool_history.rs`，准确函数由 HA-00 记录。

在原任务记录上关联原始人类消息、可信补充消息、已完成证据、授权记录引用和当前状态；原字段足够时直接复用。常规语义由当前模型处理，不新增逐消息分类请求。状态追问只追加输入；真正替换/取消通过已有控制入口更新。合成消息保留来源标记，不能写入宿主授权记录。验证压缩后当前目标仍可恢复且旧取消状态优先。

验收 HA02-01 至 HA02-05。若需要数据字段，采用兼容旧记录的可选字段或既有迁移机制，缺失来源不推断授权。回退展示/组装变更可行；不能撤销来源校验或取消有效性。

### HA-03 明确的工具能力配置

入口：`W/main.rs::messages_have_tool_intent`、`select_tools_for_request`、最终工具过滤与发现入口。

复用现有配置机制提供明确策略选择；名称由实现者根据已有类型确定，不用模型名推断能力。对选定配置移除动作关键词硬门，保留实际可用的基础工具与发现工具。最终仍受用户开关、allowlist、权限、provider 支持、schema 预算约束。小窗口保留独立策略；发现结果只能补充已允许的工具，不能增加授权。

验收 HA03-01 至 HA03-05。对比基础工具数量/schema 体积与实际调用，避免为放开能力而无差别注入。可按配置切回原暴露策略；所有宿主权限检查始终保留。

### HA-04 绑定真正发送的请求

入口：最终 `MessageRequest` 构造、SSE 首次发送与共享工具循环、`tool_invocation_identity.rs`、`HostModelSnapshot`。

复用最终请求及已有能力对象，在最终过滤完成后记录请求身份、尝试身份、父关联、工具声明摘要及有效参数摘要。SSE 的首个模型响应进入共享工具循环时必须携带原发送请求的绑定及必要能力引用，循环实际消费它，禁止用下一次设置重新推导旧响应的暴露面。这里的“首响应”不是运行接纳事件 `started`；允许保留早期 `started`，以 `request_bound` 报告绑定并先于对应模型内容/工具事件。仅增加事件或响应字段不满足本项。摘要须与 adapter 最终序列化后的有效字段对应，不保存密钥或原始敏感提示。

区分同一请求的传输重试、重新采样的新请求和子请求：输入只接纳一次；新采样/子请求有自己的身份和当前配置，保留关联与能力上限。执行时读取当前撤销/停用状态，旧快照不能放行。新增封装不得复制权限存储。

验收 HA04-01 至 HA04-05。可撤回新增摘要字段或封装，保持调用身份与 live gate；旧格式记录不能被升级成新的授权证明。

后续按 [HA-04 继续实施决策](HA-04-DIRECTION-2026-10-18.md) 的小批顺序推进：先绑定传递与 wire 对照，再补真实调用路径上的身份/接纳计数、在途撤销及受影响入口回归。ACP/订阅按各自原生协议证明身份、权限及收尾，不要求伪造 HTTP `MessageRequest`。HA-05/09 的依赖仍为 HA-00，不因 HA-04 未验收而全局停工。

### HA-05 修正 L1 与合法等待

入口：共享工具循环中的 L1 signature/repeat 判断、工具等待状态及现有根预算。

先移除“相同参数必定无进展、必须改方法”的断言，再按工具可消费状态区分等待/查询、可修复失败、不可恢复失败和未知。合理期限内同参数查询仍运行属合法等待；能直接长等待时复用宿主等待路径。无关时间戳变化不能清空无效循环计数。未知状态不编造语义进展。

验收 HA05-01 至 HA05-04。不新增通用语义检测模型。策略可收缩为较保守的有条件提示，不能回退为已证错误的绝对提示；根预算/取消始终生效。

### HA-06 恢复、终态与效果身份

入口：文本恢复调用点、`ToolDispatchService::dispatch`、`ModelToolIdentity`、`ToolDispatchSettlement`、hook 与受控执行。

为恢复条件建立小型确定性分支：明确不可恢复终态使用宿主事实回执；参数/协议错误且未产生效果时允许一次有目标修复；传输重试遵守现有上限与根期限。修复后的再次失败直接给具体阻塞，不新增无依据重试。实际效果已发生或未知时查询原回执/效果，不以换工具/ID 规避。

分别记录派发进入次数、实际效果次数、恢复模型请求和终态；不使用 `model_tool_calls_executed` 布尔值冒充实际效果计数。用隔离临时资源和可计数的假工具注入断流/post-hook 失败，避免拿用户真实外部系统做非幂等故障实验。

验收 HA06-01 至 HA06-05。恢复策略可回退，但不能移除身份去重、根预算或已发生效果的保护。

### HA-07 同一批准复用与撤销

入口：`W/main.rs` 现有 session grants/pending approvals、房间配置版本、权限预检；`C/permissions.rs`、`permission_gate.rs`、`conversation.rs`；pre/post hook。

先复核当前审批合并实现。优先修复同一逻辑调用在 hook 前后重复询问；复核仍必须运行。只在现有语义允许的同范围会话授权中合并并发 pending；一次性批准只覆盖自己的逻辑调用。key/适用性需包含实际资源、作用域、主体、权限、实例及相关版本；按既有结构扩展必要字段，不建设通用缓存。

hook 改路径/命令/目标/权限需求后重新判断覆盖范围。用可控屏障分别停在审批、hook、队列及领取资格前撤销，证明接纳撤销与执行领取之间有明确先后。审批超时、拒绝、房间切换和重启不可残留可用的旧批准。

验收 HA07-01 至 HA07-05。可关闭复用/合并，退回单独询问；不能关闭实时检查。生产中现有明确批准仍按既有范围有效，不能因本项引入普遍重新确认。

### HA-08 Web 有限并发

入口：`dispatch_model_tool_calls_parallel` 及带取消版本、插件宿主、hook 元数据、浏览器/进程资源约束。

只允许证明确无副作用且无冲突的读取并行。未知工具、未知 hook 或共享独占宿主默认有序；已知资源使用最小局部屏障，沿用现有预算/取消和收尾。明确 DSH `HOST_BUSY` 是忙错误而非自动队列；不得用重试掩盖冲突。CLI 同步 executor 保留，若以后改并行需另立项。

验收 HA08-01 至 HA08-04。采用测试屏障/事件先后证明并行与有序，避免依赖脆弱的毫秒阈值。整体可切回串行，权限、取消和调用身份不变。

### HA-09 明确验证状态与执行者

入口：`goal_phase_command_failures`、`run_goal_phase_command_gate`、`goal_command.rs`、Goal phase 结果消费及现有 evidence 字段。

将空失败列表表达的多种含义拆成明确结果：`passed`、`failed`、`not_required`、`skipped`、`unable`（具体 Rust 名称可适应现有类型）。成功须有命令/检查回执。命令非零、超时、取消等保存具体原因；读取目标/阶段失败、无法启动或无法确认执行为 `unable`。明确 Command 合同却没有命令属于配置无效，不能成功。明确要求的门被禁用属于 `skipped` 且阻止该合同通过；未要求 Command 时 `not_required` 仅表示该门不适用，不替其他验收通过。

为每个验证合同指定模型或 runtime 中一个执行者；模型已做相同验证且能提供宿主回执时允许提交证据，否则 runtime 执行，提示词不再指示机械预跑。普通聊天不增加 verifier 角色。

验收 HA09-01 至 HA09-05。消费端同步迁移，旧 `Vec<String>` 兼容必须保留“不知道是否执行”的含义。回退证据复用可重新执行必要检查，不回退为空列表即通过。

### HA-10 当前任务内有限复用

入口：HA-09 的结果消费、已有证据字段、命令执行回执。

仅复用当前任务内、明确可复用检查的成功证据。依据验证对象/合同、命令参数、cwd、相关文件内容、测试/构建配置、锁文件、工具链和相关环境判断。依赖集合不能确定或命令依赖网络/外部状态时不复用。验证前后相关输入不同则证据不确定。FilesExist 等廉价检查直接复查。

任务追问、摘要更新、角色切换、任务 revision 改变不是单独失效原因；HEAD 不变不能保护已改动内容。用户要求重验则重验一次。本文用于工程交接的持久证据文件不等于给产品增加跨会话运行时缓存。

验收 HA10-01 至 HA10-05。可关闭复用并执行必要验证；已有失败不得被模型文字或旧成功覆盖。

### HA-11 集成与性能对照

按第 7 节在相同模型、版本、effort、材料、工具与配置上比较基线/候选。复用既有 request purpose、tool feedback 和执行记录，仅补足缺失关联，不建设新观测平台。结合确定性故障用例检查硬边界，再用真实模型检查完成质量和重复工作。

验收 HA11-01 至 HA11-04。没有模型额度/环境时如实标记阻塞，不用 mock 延迟替代真实收益。若质量下降或新增无理由调用，定位并只回退对应策略；未证实性能收益时不扩大部署或开启 T08。

### HA-12 接替演练与交付收口

交付过程中持续更新 state 和证据，最后按 START_HERE 做一次只依赖磁盘文件的恢复演练：选已通过项核查证据和源内容；选未完项确定下一条动作；模拟无效证据不能被关闭；确认未知效果不会重放。

无须为审查再启动一个模型。若已有另一会话接替，由它执行相同流程。最后运行结构检查与 `--complete` 收口检查，确认 HA-00 至 HA-12 都有证据。HA12 的实质验收先记入状态，再运行最终检查，避免把“先全通过才能测试自己”变成循环依赖。

验收 HA12-01 至 HA12-04。生成 `evidence/final-report.md`：完成项、剩余延期项、实测结果、回退入口、仍未知的风险。任务完成后停止，不继续加功能或重复验收。

## 6. 逐项完成定义

每个工作包经历 `pending → in_progress → implemented → accepted`；需要外部条件时可 `blocked`，证据被相关改动影响时可 `needs_recheck`。`implemented` 只表示改动已写入；`accepted` 必须满足本项所有验收条目、依赖项和有效证据。缺少任一项就不能以“基本完成”关闭。候选项只能是 `deferred`。

一项只做与其行为有关的修复、针对性测试及受影响构建。遵守仓库 AGENT.md：代码改动执行相关 crate 的 `cargo build -p <crate> --offline`，按测试所在 crate 做定向测试；文档变更不触发全项目构建。已通过检查仅在相关改动、新失败或明确重验要求出现时重跑。若测试过滤器匹配 0 个测试，即使退出 0 也不是测试通过。

用 [ACCEPTANCE.md](ACCEPTANCE.md) 的可观测结果验收；每个条目关联 [EVIDENCE.md](EVIDENCE.md) 规定的证据。一个可信执行可以证明多个条目，不需要为每个编号重复执行同一命令。不能通过减少验收条目、改成可选或填写 `not_required` 来关闭必做项；合理范围变更须记录理由与依据，并同步方案、验收表和状态。

## 7. 对照实验与推广判据

基线由 HA-00 在改业务代码前保存。优先使用隔离的当前工作区源码快照或可复现的补丁及文件哈希；只复制构建所需源码，不包含密钥、数据库和编译产物。HEAD checkout 会丢失现有用户改动，不能冒充基线。必须能从冻结资料复原当时行为；只有哈希不算可重现实验基线。对同一受控输入进行基线/候选配对，交替执行顺序并记录热/冷缓存、负载和人工等待。若 HA-00 时缺模型额度，模型实验记为待运行，HA-11 补跑两组版本后才能判断收益。

| 场景 | 固定材料与验收对象 | 重点度量 |
|---|---|---|
| B01 纯聊天/纯内容 | 答案约束与输出内容 | 不因 Harness 强制计划、搜索、Goal 或验证 |
| B02 无动作词但需查证 | 隔离资料中的可核实问题 | 完成率、首次有效动作、是否真实读取 |
| B03 单文件修改 | 固定缺陷及一个针对性检查 | 最终内容、验证启动数、额外确认 |
| B04 多文件任务＋进度追问 | 固定小任务，在同一节点插入追问 | 连续性、已完成工作是否重复、最终验收 |
| B05 合法长任务等待 | 可控开始/运行/完成状态 | 无错误 L1 纠偏、模型请求数、等待策略 |
| B06 有效果后断流/失败 | 可计数隔离副作用样例 | 实际效果一次、回执未知保留、恢复次数 |
| B07 审批合并与撤销 | 隔离资源及可控屏障 | 用户交互数、复核数、撤销后的执行资格 |
| B08 Goal 验证与证据变化 | 同输入复用、相关修改、坏配置 | 真实状态、实际验证启动数、证据失效 |

B01–B05 各 3 组基线/候选配对，首轮共 15 组；这是工程筛查规模，不是统计显著性声明。B06–B08 以确定性故障/并发测试为主；至少保留一条受影响真实链路的完整追踪，不能只测新 helper。若同一模型版本不可锁定，记录 provider 返回的可用身份并标注可比性限制，不能强行归因。

首轮判据：固定必做场景均达到任务合同；样例中未授权执行、错误复活、重复非幂等效果、未执行被标通过均为零。已识别的冗余动作应在对应确定性场景中消除：同一批准重复询问为零、明确终态额外恢复请求为零、有效相同证据的重复验证启动为零。必要参数/协议修复最多一次且受原根预算限制。其他模型自发工具行为据任务必要性判断，不机械强制所有场景零调用。

每次记录真实结果、端到端耗时、首次有效动作时间、模型请求用途及次数、用户审批次数、自动审核请求数、工具进入/效果次数、验证启动数、token 已知/未知、排队/执行/审批/模型/退避/验证区间。并行区间看关键路径，不直接求和。失败与成功分开，人工等待单列；token 缺失不能填零。

15 组筛查报告逐次结果和描述性中位数/范围，不给稳定 p95 或确定提速百分比。默认推广要求质量合同成立且目标冗余计数下降；若成功任务耗时方向相反，先解释模型抖动、资源负载或新瓶颈，并定向复测受影响场景。无法解释或证据不足则保持受控配置、记录待测，不扩大默认范围。无需为“统计更漂亮”重复全部实验。

## 8. T08 重新评估条件

| 候选项 | 进入实施前所需证据 | 独立验收 | 回退 |
|---|---|---|---|
| D08-A 异步子任务 handle / wait / cancel | 父模型等待在目标任务中有实质占比，且父模型有可并行的有效工作 | 所有权、结果只提交一次、取消/预算传播、无孤儿执行，完成率与总成本不退化 | 同步委派 |

这些候选项须经新的明确范围决策再实施。不能因别的 Harness 有此功能就移植；也不能把子任务 handle 的收益推导为 PTC 的收益。

## 9. 当前交付与授权边界

本轮完成方案、验收合同、证据/状态文件及接替检查工具；并不自动执行安装、发布、付费基准或修改业务功能。后续开始实施后可在既有授权范围内连续完成工作包，例行可逆修复无需逐步询问。发布及真实外部副作用仍按用户届时授权和现有项目规则处理，不额外发明审批流程。

文件能使其他会话恢复上下文并审查完成质量，但不能让平台在额度耗尽时自动换模型或保证某个模型不犯错。防线是及时落盘、明确验收、可信证据和接替时复核；机制本身不进入产品每次推理的运行路径。
