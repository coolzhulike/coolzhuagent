# Harness 对齐逐项验收合同

本表规定可关闭工作包的标准；所有条目初始为待执行，实时状态见 [state.json](state.json)。`HAxx-yy` 是稳定条目 ID，不因换模型/会话改变。执行方法、原始结果和输入哈希按 [EVIDENCE.md](EVIDENCE.md) 保存，一个执行可覆盖多个条目。

通过只证明对应范围。模拟 provider/工具可验证确定性分支，但不能证明真实模型收益；源码阅读可证明实现位置，不能代替并发、撤销或实际效果实验。首轮下列条目全部必做，不能用 `not_required` 关闭；“确实不适用的路径保持明确不可用”本身是需证据的断言。

## HA-04 请求绑定（5 项）

| ID | 操作/输入 | 必须观察到的结果 | 最小证据 |
|---|---|---|---|
| HA04-01 | 普通/SSE 请求发送后更改下一步工具设置 | 原响应按原发送集合解释；新增工具不追溯成为旧响应可调用项 | 两入口 wire 摘要、响应绑定和执行结果 |
| HA04-02 | 最终过滤改变工具集合或有效模型参数 | 请求摘要反映过滤后的实际内容；不记录密钥；不是早期 context id 的替身 | 与 adapter 发送点逐字段对照 |
| HA04-03 | 传输重试、重新采样、子请求 | 输入只接纳一次；身份关系可追踪；新请求独立且有正确上限 | 请求/尝试/父关联及接纳计数 |
| HA04-04 | 请求在途时撤销权限或停用工具 | 旧暴露资格不能覆盖当前拒绝；撤销后未开始动作效果为 0 | 可控屏障事件与宿主回执 |
| HA04-05 | CLI/ACP/订阅路径经过受影响共享接口 | 现有身份/权限/收尾不退化；不支持原生工具的订阅入口仍明确不可用 | 每条路径定向测试或真实不支持响应 |

解释边界：HA04-01 约束首个模型响应及后续响应的解释和派发，不要求把绑定塞入运行接纳事件 `started`。可用 `request_bound` 报告，但后端必须把实际发送请求的绑定及能力引用传给响应消费方，单有事件不算通过。HA04-02 的“实际内容”包含 adapter 转换/覆盖后的有效字段。HA04-03 应复用真实请求/尝试链，不能以手工构造 ID 的单测代替实际接纳计数。HA04-05 按各入口自身协议回归，不以是否存在 HTTP `MessageRequest` 作为统一通过条件。实施与测试细化见 [HA-04 继续实施决策](HA-04-DIRECTION-2026-10-18.md)。
