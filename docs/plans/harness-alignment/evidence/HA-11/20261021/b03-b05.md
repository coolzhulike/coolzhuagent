## 结论与限制（系列 3，最终）

- 18 次（B03–B05 各 3 对）全部 HTTP completed；我方独立 `cargo test --offline` 退出码均为 0；按“模型确实执行了 shell（ok 或 failed，非 dry-run）”判定，18/18 满足合同。B05 中 `shell 成功=0, 失败=1` 的两次（候选 1、基线 3）已人工核对回复：模型如实报告了真实的 75.00s 慢测试与三段 `test result: ok`，并指出工具层回显 exit_code:1 是 PowerShell 把 cargo 的 stderr 进度输出（经 `2>&1`）当作 NativeCommandError。这是既有的工具层行为（两侧相同），不是 Harness 差异，但会让模型看到“失败”状态，列为残留风险。
- 系列 1/2 暴露的放行白名单过窄问题已通过放宽解决：系列 3 的 dry-run（require-confirm）次数 B03 候选 0、基线 2；B04 候选 1、基线 0；B05 候选 2、基线 1，均由模型选用了未放行写法（如管道到 `Select-Object`/`Tee-Object`、`cmd /c`、`run_in_background`、`cd && type`，见 `shell-gate-not-exempt-*.log`）。
- B04 追问（要求不再运行命令）期间工具调用 6/6 为 0。
- 耗时：系列 3 的绝对耗时（B03 约 118–193s）明显高于系列 2（约 29–78s），同一提示词跨时段差异大，说明远程 qwen 延迟/负载随时间波动。回归编译在系列 3 开始前已结束，未与实验并发。因此只做描述性对照：B03 中位 基线 183.7s/候选 164.9s，B04 103.9s/91.3s，B05 239.5s/312.2s；样本仅 3 组，不声称稳定差异或 p95；token 未统计（响应只含上下文占用，无逐轮 token 明细，视为未知）。
- “shell 成功/失败”是按审计状态计数，未逐条核对命令内容；审计只存输入长度（被拒命令见 `shell-gate-not-exempt-*.log`，仅覆盖未放行命令）。
- 基线为补齐依赖的重建版且打了同一 shell 放行补丁；候选为当前工作区调试二进制。
