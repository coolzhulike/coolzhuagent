## 结论与限制

- 18 次（B03–B05 各 3 对）全部 HTTP completed，我方独立 `cargo test --offline` 退出码均为 0（模型最终文件正确）；但按"模型真正运行了测试"判定，4/18 未满足合同（B03 基线 2、B04 候选 2、B05 基线 1、B05 候选 2）。原因是共享的放行白名单：模型常追加 `; Write-Output "EXIT=$LASTEXITCODE"`、`Set-Location/cd`、`dir/ls`、`run_in_background`、`dangerouslyDisableSandbox`，这些被保守地留给审批（见 `shell-gate-not-exempt-*.log`）。基线与候选同补丁，因此该问题不是 Harness 差异，但 **HA11-01 的“所有必做任务合同满足”未达成，不能通过**。
- “shell 成功”是代理指标（任一 bash/PowerShell 调用 status=ok），未逐条核验命令内容；审计只存输入长度。
- 追问（B04）期间工具调用均为 0（6/6），符合“状态追问不重跑验证”。
- 耗时/工具调用只是 3 组描述性数据，方差大（例如 B05 候选 211.7s 是反复被 require-confirm 导致），不声称稳定差异或 p95；token 未统计（API 未返回逐轮 token，视为未知）。
- 基线为补齐依赖的重建版且打了补丁；主机是 Windows 单机，qwen 为远程模型，网络延迟计入耗时。
