## 继续一个工作包

先看 `active_task`、`next_task`、`handoff`、阻塞原因、在途命令及未知效果。确认上一会话是否仍在工作，避免两个执行者同时写 `main.rs`；不自动抢占其他会话。选依赖已满足的未完项，将它和当前 owner 写入 state 后开始。

用函数/类型名称定位并限量读取大文件；Pro 行号只对应固定包。现有代码若已满足目标，补齐可复核证据即可，不为凑改动重写。已通过项只核对相关输入和证据；相关输入未变时不重新跑昂贵测试。

如果哈希变化，先检查差异是否影响该证据的证明对象。无关变动可以作一次带依据的证据复核记录，引用原测试回执；不能简单刷新哈希冒充新测试。有关或无法判定则标 `needs_recheck`，只复测受影响条目。跨工作包共享同一执行证据，不按编号重复构建。

每次实际修改后执行必要的定向测试与相关 crate 构建。常见 crate 为 `coolzhu-web-console`、`coolzhu-core-runtime`、`coolzhu-llm-adapter`。命令需根据实际测试名称确定；过滤器匹配 0 项不算成功。遵守项目离线构建规则，环境缺失记为阻塞，不静默安装大量依赖。

完成后先归档证据，再标条目 `passed`；全部条目和依赖满足才将工作包标 `accepted`。一次保存 state：先写同目录临时文件，确认能解析后替换，保留上次可读版本；不要覆盖别人刚更新的状态。文件替换完成后运行轻量检查一次。

## 检查点与额度中断

不依赖平台一定提前报告额度。以下节点及时落盘：开始/结束工作包、每个可独立验证的改动完成、测试结果出现、启动长耗时操作前、出现阻塞或效果不确定时。无需每次读取文件都写日志，也不要求新增监管模型。

每个检查点仅记录：当前项、修改文件/源码版本、已验证条目与证据 ID、失败及原因、下一条具体动作、在途操作、未确认效果。临时输出可在 `tmp/`，用于关闭条目的证据必须复制到本目录 `evidence/` 并脱敏。提交 Git 不是唯一持久方式；本地文件已可接续，但换机器须迁移相同工作区及未提交差异。

检测到额度/上下文不足时，先停止接纳新的长操作，保存上述检查点和日志，再交接。若额度突然耗尽，`in_progress` 或 `implemented` 保持未验收；接替者从最近落盘记录恢复，不能推断“没写失败就是成功”。

| 中断位置 | 接替动作 | 何时可以继续 |
|---|---|---|
| 写代码中 | 对照当前文件与最后检查点，识别半成品及其他人的变更 | 理解差异并确认修改归属后 |
| 编译/测试中 | 查记录的 PID、进程开始时间、工作目录和日志；仍运行则接读输出 | 获取真实结束码；进程已失踪且无结果则记未知，定向重跑无副作用检查 |
| 工具可能已产生效果 | 查询原逻辑调用、宿主记录、资源状态；不要换 ID 重跑 | 能证明未执行/幂等可恢复，或有明确下一步处置 |
| 证据已写但状态未更新 | 核对证据哈希、对应输入及合同 | 证据可信且适用后补登状态，不重复执行 |
| 状态文件损坏 | 使用上次可读版本，结合已有证据恢复 | 所有新增“通过”有来源；损坏记录不猜测 |

只操作本任务已确认的进程，不能全局结束所有 cargo/python/浏览器。对可能影响外部系统的未知效果，现有授权不等于可以盲目重放。
