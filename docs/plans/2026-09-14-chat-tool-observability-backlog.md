## TODO-CHAT-OBS-002：工具调用默认折叠显示

状态：待办，P8.3 后执行。

目标：工具调用不再作为普通助手消息占据聊天室正文。运行中在对应 turn 内显示一条默认折叠的执行状态；用户可展开查看必要信息。成功后保持折叠且不额外生成独立聊天消息，行为与思考摘要卡一致。

交互约束：

- 单个工具调用按稳定 `call_id` 原位更新：排队/运行/成功/失败/取消，不通过追加多条消息模拟状态变化。
- 默认折叠；运行、失败或需要用户操作时显示清晰状态，失败保留可展开错误摘要。
- 工具输出、参数和日志继续遵循脱敏、截断与权限规则；不能因折叠而删除可审计事件。
- 刷新、断线重连和历史会话回放后仍保持正确终态；工具卡不混入模型正文复制内容。
- 不显示无效 debug 文案，不把原始 reasoning 混入工具卡。

最小验收：成功、失败、取消、并行两调用、刷新回放；聊天室正文只出现最终助手回复，工具执行在所属 turn 内默认折叠可查。

## TODO-CHAT-OBS-003：思考与回复耗时、Token 花费

状态：待办，P8.3 后执行。

目标：每个 turn 分别展示思考阶段和最终回复阶段的耗时与 Token 花费，采用紧凑的 Codex 风格元信息，不干扰正文阅读。

数据与显示边界：

- 服务端记录单调时钟时间点：请求接受、首个 reasoning/summary token、首个 answer token、流结束、取消/失败；前端不以本机动画计时冒充服务端耗时。
- Token 优先使用 provider 返回的 input/output/reasoning/cached usage；provider 不提供的字段显示“不可用”或明确的估算标记，禁止伪造精确值。
- 每轮至少能区分：思考用时、回复用时、总用时；输入 Token、思考 Token、回复 Token、缓存 Token按能力显示。
- 流式过程中可显示运行时长，完成后冻结最终值；重连/回放使用持久化 usage 与时间戳，不重新计时。
- 与 provider/model/reasoning 能力表兼容，覆盖已配置的 Agnes 与 GLM-5.2；字段缺失采用能力降级，不用虚构统一协议。

最小验收：有 reasoning usage、只有总 usage、无 usage、流式取消、失败、刷新回放六类；数值归属到正确 turn，不重复累计工具耗时或重试 Token。
