# 卷轴边线、运行详情与聊天室权限入口补正

日期：2026-09-27。用户在 0.2.22 安装实图上补充三项问题：底部诊断栏遮住金框；顶部圆玉石被拉扁、Logo 两侧金饰被裁；当前聊天室的目录权限/完全访问选择不可见。本补正优先于此前“原稿视觉已通过”的范围，不删除此前真实操作证据，但不得再用它证明这三项体验已解决。

## 已确认的原因

- `index.html` 的常驻 `global-system-bar` 混合工作区、连接、会话计数、输入安全归属/恢复摘要和人工复核入口。它包含需要保留的操作，不能只把整段设为不可见。
- `scroll_theme.css` 对整幅框图采用 `border-image-repeat:stretch`，中间圆形玉石与长金线一起变形。圆形装饰须独立等比绘制，只有线段可延展。
- 品牌容器常规宽度为 230–290px，而背景宽度是 370px；窄屏 190px 容器配 255px 背景。原图含完整左右金饰，超出容器的裁切造成缺口。
- 原有 `chat-permission-select` 和保存按钮位于不再展示的旧聊天侧栏高级配置中。其渲染和保存仍是单节点查询，新增第二套同名控件会导致状态分叉。

## 设计决定

1. 移除主窗口底部常驻诊断栏及布局占位，将现有详情和输入安全操作移入可达的轨迹/运行详情。保留原事件、人工复核和安全事实；必要异常提示应能引导到详情，不能隐藏真实阻断或自动放行。
2. 顶部圆玉石和装饰用现有素材分区等比展示，线段负责适配宽度。保留左右玉轴、竹林和金玉色。装饰不接管指针、焦点，也不改变原生网页祖先的变换或裁切。
3. 中央品牌显示完整素材，宽度随品牌容器收缩且保持比例，不用溢出覆盖两侧环境按钮。普通和低高度窗口都检查金饰完整、字标可读。
4. **用户 2026-09-28 明确选择：权限入口放在顶部“当前聊天室”旁边，覆盖此前输入区位置提案。** 用户可选择“目录权限”或“完全访问”；同一套原控件和保存链路通过紧凑入口展开，不在输入区保留副本。普通和 903×551 下均可见，优先压缩房间名称及辅助状态图标，不遮中央 Logo。保留既有确认与审批；无聊天室时禁用，读取失败显示状态未知。工程级调试完全访问存在时明确展示有效权限及覆盖原因，不能在实际上仍完全访问时显示“已限制到目录”。模型工具开关及 Computer Use 输入安全归属仍独立生效。

Pro 审查会话本轮复查仍 `Pro disabled`，未发送新审查、未以其他型号替代。当前主会话负责上述已由用户明确要求的最小设计，Sol Max 负责代码及测试。

**2026-09-28 文案补充决定**：用户审阅小窗口实图后要求权限文本只写“完全访问”，不要“调试完全访问”。顶部及同类简短状态统一显示实际权限“完全访问”；工程级覆盖来源保留在展开详情的说明中。仅改展示名称，不改变调试开放配置、房间权限保存或输入安全规则。此前含旧文案的图保留历史身份，最终安装候选须重新编译并以新图核对。

### 2026-09-28 权限写入归属补审

进一步核实每个工程分别使用自己的会话库，但都可存在固定 ID `main-room`。权限 PATCH 现有的工程 pin 只阻止处理期间切换，无法确认请求发起时的工程；A 发出的旧请求若在切 B 后才取得 pin，可写入 B 的同名 ID 房间。单纯前端迟到守卫不能阻止这一副作用。

因此补充最小后端约束：权限更新请求携带发起时的 `expected_workspace`，取得工程 pin 后、查房和写库之前复用现有工程身份核对；缺失或不匹配返回 409。声明只用于核对，数据库仍由服务端当前工程决定。四个前端权限 PATCH 调用共用此约束；诊断弹窗保留打开时的房间/工程，不能在提交回调中临时采用另一个工程。权限内容、双确认和输入安全规则不变。由模型路由 Sol 负责后端及权限交互，视觉 Sol 负责顶栏与卷框样式，冻结后统一编译；受控双工程同 ID 的旧请求/缺字段拒绝零写与当前工程正常保存作为直接验证。

## 针对性验证与版本边界

- 新二进制：正常、最大化和 903×551 下底框完整；中央玉石长宽比不随窗口宽度变化；左右金饰不裁切；输入、发送和权限入口可达。
- 从正常入口打开运行详情，连接状态、归属摘要、CU 记录及原人工复核流程仍可找到；不得实际放行历史未知输入任务。
- 在隔离测试房验证权限读取、变更保存、取消确认保持原值、切房后状态正确；分别检查工程调试覆盖与普通模式。真实用户房间不为截图改权限。
- 活动原生网页在右栏打开时缩小/放大/关闭，检查新装饰和弹层不遮盖页面或输入。
- 产品前端是编译期内联，本次改动须重新离线构建、完整出包、正常安装并取得新版本原生证据。0.2.22 的十图和身份不追认为后续版本通过。

同时发现 0.2.22 最终提交的两条 CI 一过一败：PR 检查失败在 Goal shell 探针的成功断言，错误细节被丢弃；负载耗尽 30 秒预算只是时序推断。后续只为测试探针增加诊断和宽裕预算，产品执行时限不变，并修正原 `contains("exit 1")` 可能匹配命令自身的假阳性。准确结论由新记录给出，不能把重跑通过当作已证实旧失败原因。
